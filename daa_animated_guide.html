What is Algorithm Design?

Algorithm design is about finding the smartest strategy to solve a computational problem — not just any solution, but the fastest and most efficient one. This unit covers 4 major paradigms.

🎯
4 Design Paradigms
Divide & Conquer Split → Solve → Combine
Greedy Local best → Hope global best
Dynamic Prog. Memo → Never recompute
Backtracking Try → Fail → Backtrack

Divide & Conquer

Lecture 16–18 · Binary Search, Max-Min, Strassen's

THEORY

Core Idea: Bada problem lo → chhote independent subproblems mein todo → solve karo → combine karo.

Dictionary analogy: "Janissary" word dhundna hai? Beech se kholo — agar "Kiwi" dikhe to peeche jao, agar "Hypotenuse" dikhe to aage jao. Har step mein half possibilities eliminate ho jaati hain.

1
Divide: Problem ko same-type ke smaller subproblems mein split karo
2
Conquer: Subproblems ko recursively solve karo. Base case pe directly solve karo
3
Combine: Subproblems ke solutions ko merge karke final solution banao
BINARY SEARCHO(log n)

Problem: Sorted array mein element x dhundho. Return karo uska index.

Condition: Array must be sorted — otherwise binary search WILL NOT work!

1
Check base case: Agar l = r, element wahan hai ya nahi — return l
2
Find mid: m = floor((l + r) / 2)
3
Compare: x ≤ arr[m] → search left half (l to m), else search right half (m+1 to r)
4
Repeat recursively until found
ALGORITHM · Binary Search O(log n)
def binary_search(arr, x, l, r): # Base case: only one element left if l == r: return l # Return index m = (l + r) // 2 # Find midpoint if x <= arr[m]: return binary_search(arr, x, l, m) # Search left else: return binary_search(arr, x, m+1, r) # Search right # Recurrence: T(n) = T(n/2) + 1 → O(log n) # n=100: only 7 comparisons vs Linear's 100!

MAX-MIN PROBLEM

Problem: Array mein maximum AND minimum dono simultaneously dhundho.

❌ Naive Method
1
Max dhundho: n-1 comparisons
2
Min dhundho: n-1 comparisons
Total: 2n - 2 comparisons — wasteful!
✅ D&C Method
1
Array ko 2 halves mein divide karo
2
Har half mein max & min nikalo
3
max(max1, max2) aur min(min1, min2)
Total: ~1.5n - 2 comparisons — 25% better!
D&C Max-Min Code
def max_min_dc(arr, low, high): # Base: single element if low == high: return arr[low], arr[low] # Base: two elements — 1 comparison if high == low + 1: if arr[low] < arr[high]: return arr[high], arr[low] # max, min return arr[low], arr[high] mid = (low + high) // 2 max1, min1 = max_min_dc(arr, low, mid) max2, min2 = max_min_dc(arr, mid+1, high) return max(max1, max2), min(min1, min2) # Time: O(n) | Space: O(log n) call stack
STRASSEN'S MATRIX MULTIPLICATION

Problem: Two n×n matrices A and B ko multiply karo, but faster than O(N³).

Key Insight: Standard D&C uses 8 recursive multiplications → O(N³). Strassen uses only 7 multiplications using clever algebra → O(N^2.807).

8
Multiplications
Naive / Simple D&C
O(N³)
7
Multiplications
Strassen's Method
O(N^2.807)
Strassen's 7 Magic Formulae (2×2 case)
# A = [[a,b],[c,d]] B = [[e,f],[g,h]] # Standard needs 8 multiplications. Strassen uses 7: M1 = a * (f - h) # M1 = a(f-h) M2 = (a + b) * h # M2 = (a+b)h M3 = (c + d) * e # M3 = (c+d)e M4 = d * (g - e) # M4 = d(g-e) M5 = (a + d) * (e + h) # M5 = (a+d)(e+h) M6 = (b - d) * (g + h) # M6 = (b-d)(g+h) M7 = (a - c) * (e + f) # M7 = (a-c)(e+f) # Result C = A×B: C[0][0] = M5 + M4 - M2 + M6 # ae+bg C[0][1] = M1 + M2 # af+bh C[1][0] = M3 + M4 # ce+dg C[1][1] = M5 + M1 - M3 - M7 # cf+dh # Recurrence: T(N) = 7T(N/2) + O(N²) → O(N^log₂7) ≈ O(N^2.807)
Practical Note: Strassen is mostly THEORETICAL. In practice, Naive method is faster for small N due to high constant factors and numerical precision issues. Not used on sparse matrices.

MERGE SORTStable · Θ(n log n) always

Core Idea: Array ko aadha-aadha karte jao jab tak 1-element arrays na ban jayein. Phir in sorted pieces ko merge karo.

Real Life: Jab do taraf se sorted playing cards ko merge karo — pehle dono ke top cards compare karo, chhota uthao. Repeat!

1
Divide: mid = (low + high) / 2. Array ko [low..mid] aur [mid+1..high] mein split karo
2
Conquer: mergeSort(arr, low, mid) aur mergeSort(arr, mid+1, high) — recursive calls
3
Combine: merge(arr, low, mid, high) — do sorted halves ko ek sorted array mein milao
4
Base Case: low < high check karo. Agar only 1 element, already sorted!
MERGE SORT · Complete Code
def merge_sort(arr, low, high): if low < high: # More than 1 element? mid = (low + high) // 2 merge_sort(arr, low, mid) # Sort left half merge_sort(arr, mid+1, high) # Sort right half merge(arr, low, mid, high) # Merge both halves def merge(arr, low, mid, high): left = arr[low:mid+1] # Copy left half right = arr[mid+1:high+1]# Copy right half i = j = 0; k = low while i < len(left) and j < len(right): if left[i] <= right[j]: # Compare top of both arr[k] = left[i]; i += 1 else: arr[k] = right[j]; j += 1 k += 1 while i < len(left): # Remaining left elements arr[k] = left[i]; i += 1; k += 1 while j < len(right): # Remaining right elements arr[k] = right[j]; j += 1; k += 1 # Time: Θ(n log n) ALL cases — Best advantage of Merge Sort! # Space: O(n) extra — needs temp arrays # Stable: YES — equal elements keep original order

🌍 Real World Uses
Merge sort organizes large datasets — social media user records, e-commerce product lists by price, library catalogs. It's preferred when stability matters (equal elements keep their order).
QUICK SORTIn-place · O(n log n) avg · O(n²) worst

Core Idea: Ek pivot element choose karo → usse apni sahi jagah pe place karo → left side mein chhote, right side mein bade rakh do → recursively repeat.

Real Life: Jaise teacher ek student ko bolta hai "Aap left mein, baaki aap ke age ke neeche left mein aur upar right mein." — Partition karna!

1
Choose Pivot: Usually last element (ya random, ya median-of-3)
2
Partition: Pivot ko uski correct position pe place karo. Left mein pivot se chhhote, right mein bade elements
3
Recurse: quickSort(arr, low, pivot-1) aur quickSort(arr, pivot+1, high)
4
Base Case: low < high — agar sirf 1 element, already sorted!
QUICK SORT · Complete Code
def quick_sort(arr, low, high): if low < high: pi = partition(arr, low, high) # Find pivot position quick_sort(arr, low, pi - 1) # Sort left of pivot quick_sort(arr, pi + 1, high) # Sort right of pivot def partition(arr, low, high): pivot = arr[high] # Choose last as pivot i = low - 1 # Index of smaller element for j in range(low, high): if arr[j] <= pivot: # If current <= pivot i += 1 arr[i], arr[j] = arr[j], arr[i] # Swap # Place pivot at correct position arr[i+1], arr[high] = arr[high], arr[i+1] return i + 1 # Pivot's final index # Worst Case: Already sorted + last pivot → O(n²) # Fix: Random pivot or median-of-3 pivot # Space: O(log n) — only recursion stack, in-place!
Worst Case trick: [1,2,3,4,5] with last element as pivot → pivot=5 each time, only 1 partition. O(n²). Solution: Use random pivot or shuffle first!
🌍 Real World Uses
C++ std::sort(), Java's Arrays.sort() for primitives — both use Quicksort-based algorithms. Database query sorting, bank transaction logs, game leaderboards.
SELECTION SORTSimple · O(n²) always · In-place

Core Idea: Unsorted portion mein se minimum dhundho aur usse sorted portion ke end mein place karo.

Simple Rule: Pass 1 mein global min dhundho, Pass 2 mein baaki ka min, etc.

1
Set MIN to position 0 (first unsorted position)
2
Scan remaining unsorted array, find actual minimum element's index
3
Swap minimum element with element at position MIN
4
Increment MIN by 1 (sorted portion grows), repeat until sorted
SELECTION SORT
def selection_sort(arr): n = len(arr) for i in range(n): min_idx = i # Assume first unsorted is minimum # Find actual minimum in unsorted portion for j in range(i+1, n): if arr[j] < arr[min_idx]: min_idx = j # Swap minimum to front of unsorted portion arr[i], arr[min_idx] = arr[min_idx], arr[i] return arr # Example: [64, 25, 12, 22, 11] # Pass1: min=11 → [11, 25, 12, 22, 64] # Pass2: min=12 → [11, 12, 25, 22, 64] # Pass3: min=22 → [11, 12, 22, 25, 64] # Pass4: done → [11, 12, 22, 25, 64] ✓ # Always O(n²) — NOT suitable for large data

Greedy Algorithms

Lecture 19–21 · Knapsack · MST · Huffman

THEORY

Core Idea: "Jo abhi best lagta hai, wahi karo." Har step mein local optimal choice karo. Past decisions ko dobara nahi sochna.

Works perfectly for: Fractional Knapsack, MST (Prim/Kruskal), Huffman, Activity Selection, Dijkstra's

Fails for: 0/1 Knapsack, TSP, Coin Change (arbitrary denominations)

Generic Greedy Structure
def greedy_template(candidates): result = [] while candidates: item = select_best(candidates) # Greedy choice if is_feasible(item, result): # Can we add it? result.append(item) return result # 5 Components: # 1. Candidate Set — items to choose from # 2. Selection Fn — pick the best candidate # 3. Feasibility Fn — can it be added? # 4. Objective Fn — value of current solution # 5. Solution Fn — is solution complete?
FRACTIONAL KNAPSACK

Problem: Thief ke paas W kg capacity ka bag. N items hain, har item ka weight w[i] aur value v[i] hai. Items ka FRACTION le sakta hai. Maximum value chahiye.

Greedy Strategy: Value-per-kg ratio sabse zyada wala item pehle lo. Agar poora nahi aata to fraction lo.

1
Calculate ratio = value[i] / weight[i] for every item
2
Sort items by ratio in DESCENDING order
3
Greedily pick items: agar poora item fit hota hai to pura lo; warna remaining capacity ke liye fraction lo
4
Stop when knapsack is full (capacity = 0)
FRACTIONAL KNAPSACK · O(n log n)
def fractional_knapsack(values, weights, W): n = len(values) # Step 1: Calculate value/weight ratios items = [(values[i], weights[i], values[i]/weights[i]) for i in range(n)] # Step 2: Sort by ratio DESCENDING (greedy choice) items.sort(key=lambda x: x[2], reverse=True) total_profit = 0 remaining = W # Step 3: Greedily fill knapsack for v, w, ratio in items: if remaining == 0: break if w <= remaining: # Take full item total_profit += v remaining -= w else: # Take fraction! total_profit += ratio * remaining remaining = 0 return total_profit

MINIMUM SPANNING TREE

Problem: Connected, undirected, weighted graph G(V,E). Find a tree connecting ALL vertices with MINIMUM total edge weight, no cycles.

Real Life: Cities ko minimum cable length mein connect karo — electricity grids, internet backbone, water pipelines!

🔵 Kruskal's Algorithm
1
Saari edges ko weight ke basis pe sort karo (low→high)
2
Ek-ek edge lo. Agar cycle nahi banta to MST mein add karo
3
Cycle detect karne ke liye Union-Find use karo
4
Jab V-1 edges ho jayein, MST complete!
Best for sparse graphs (few edges). Uses edge sorting.
🟠 Prim's Algorithm
1
Kisi bhi ek vertex se shuru karo (source)
2
Current tree se nearest/cheapest vertex dhundho
3
Us vertex ko MST tree mein add karo
4
Sab vertices tree mein aajayein tab tak repeat
Best for dense graphs. Grows from one source vertex.
KRUSKAL'S ALGORITHM · O(E log E)
def kruskal(n, edges): # Sort all edges by weight edges.sort(key=lambda x: x[2]) parent = list(range(n)) # Union-Find rank = [0] * n def find(x): # Which component? if parent[x] != x: parent[x] = find(parent[x]) # Path compress return parent[x] def union(x, y): # Merge components px, py = find(x), find(y) if rank[px] < rank[py]: px, py = py, px parent[py] = px if rank[px] == rank[py]: rank[px] += 1 mst = []; total = 0 for u, v, w in edges: if find(u) != find(v): # No cycle! union(u, v) mst.append((u, v, w)) total += w return mst, total

HUFFMAN CODINGData Compression · O(n log n)

Problem: Characters ko binary codes assign karo jisse total encoded message length minimum ho.

Key Rule (Prefix Code): Kisi character ka code kisi doosre character ke code ka prefix nahi hona chahiye. Isse decoding ambiguous nahi hoti.

Greedy Strategy: Least frequent characters ko longest codes do (deep in tree). Most frequent = shortest codes (near root).

1
Leaf nodes banao: Har character ke liye ek node banao jisme frequency stored ho
2
Min-Heap banao: Sab nodes ko priority queue (min-heap) mein daalo — lowest frequency = highest priority
3
Merge: Heap se 2 minimum frequency nodes nikalo → unka sum banao → new internal node banao → wapas heap mein daalo
4
Repeat until only 1 node remains — that's the root!
5
Assign codes: Left edge = 0, Right edge = 1. Root se leaf tak ka path = character's code
📊 Huffman Tree — A:45, B:13, C:12, D:16, E:9, F:5
HUFFMAN CODING · Python
import heapq def huffman(chars, freqs): # Build min-heap of [frequency, char/node] heap = [[f, [c, ""]] for c, f in zip(chars, freqs)] heapq.heapify(heap) while len(heap) > 1: lo = heapq.heappop(heap) # Smallest freq hi = heapq.heappop(heap) # 2nd smallest for pair in lo[1:]: pair[1] = '0' + pair[1] # Left=0 for pair in hi[1:]: pair[1] = '1' + pair[1] # Right=1 # Merge and push back heapq.heappush(heap, [lo[0]+hi[0]] + lo[1:] + hi[1:]) codes = dict(heapq.heappop(heap)[1:]) # Calculate average code length total_freq = sum(freqs) avg_len = sum(f * len(codes[c]) for c, f in zip(chars, freqs)) / total_freq return codes, avg_len # Example: A:45,B:13,C:12,D:16,E:9,F:5 # Quiz: First pair merged = E(9) + F(5) = 14! # Avg code length = 2.24 bits per character
🌍 Real World Uses
ZIP/GZIP files, JPEG image encoding, MP3 audio compression, HTTP data compression — all use Huffman coding!

Dynamic Programming

Lecture 22–26 · Knapsack · LCS · Matrix Chain · TSP

THEORY

Core Idea: "Subproblems ek baar solve karo, table mein store karo, dobara kabhhi mat solve karna!"

Fibonacci without DP: fib(5) calls fib(3) twice, fib(2) thrice — exponential time. With DP: Each value computed once → O(n)!

2 Required Properties
1. Overlapping Subproblems
Same subproblems baar baar aate hain. Memoization se O(exponential)→O(polynomial)
2. Optimal Substructure
Global optimal solution, subproblems ke optimal solutions se bana hoga
4 Steps of DP
1
Characterize optimal solution ka structure
2
Recurrence define karo recursively
3
Compute bottom-up (table fill)
4
Construct actual solution from table
0/1 KNAPSACKO(nW) time & space

Difference from Fractional: Item ka fraction nahi le sakte. Ya poora lo (1) ya chhodo (0). Greedy FAIL karta hai yahan!

Why Greedy Fails: items=[(3kg,4$),(4kg,5$),(5kg,6$)], W=8. Greedy picks by ratio: picks 4$ item, then 5$ item (over capacity). Misses optimal: pick 5$+6$=11$ with 9kg... DP finds the true optimum.

1
Create table dp[n+1][W+1] where dp[i][w] = max value using items 1..i with capacity w
2
Base case: dp[0][w] = 0 (no items) and dp[i][0] = 0 (no capacity)
3
Fill table: For each item i and capacity w: if item fits → max(exclude, include); else → exclude
4
Answer is dp[n][W]. Trace back to find which items were selected
RECURRENCE FORMULA
# dp[i][w] = max value using items 1..i, capacity w # # Case 1: Item i is too heavy (w_i > w) # dp[i][w] = dp[i-1][w] — can't include # # Case 2: Item i can fit (w_i ≤ w) # dp[i][w] = max( # dp[i-1][w], — EXCLUDE item i # v_i + dp[i-1][w - w_i] — INCLUDE item i # )
0/1 KNAPSACK · Python Code
def knapsack_01(values, weights, W): n = len(values) # Create (n+1) × (W+1) table, init to 0 dp = [[0] * (W+1) for _ in range(n+1)] for i in range(1, n+1): for w in range(W+1): # Option 1: Don't include item i dp[i][w] = dp[i-1][w] # Option 2: Include item i (if it fits) if weights[i-1] <= w: include = values[i-1] + dp[i-1][w - weights[i-1]] dp[i][w] = max(dp[i][w], include) return dp[n][W] # ← The answer! # Time: O(n×W) | Space: O(n×W)

LCS — LONGEST COMMON SUBSEQUENCE

Problem: Two strings X and Y given. Find length of their longest common subsequence. Subsequence = elements in same ORDER but not necessarily CONTIGUOUS.

Example: X="ABCBDAB", Y="BDCABA" → LCS = "BCBA" (length 4)

1
Create dp[m+1][n+1] where dp[i][j] = LCS length of X[0..i-1] and Y[0..j-1]
2
Base case: dp[0][j] = dp[i][0] = 0 (empty string ka LCS = 0)
3
If X[i] == Y[j]: dp[i][j] = dp[i-1][j-1] + 1 (match! extend LCS)
4
If X[i] ≠ Y[j]: dp[i][j] = max(dp[i-1][j], dp[i][j-1]) (best without current char)
5
Answer: dp[m][n]. Traceback through table to find actual LCS string
LCS · Python Code · O(mn)
def lcs(X, Y): m, n = len(X), len(Y) dp = [[0]*(n+1) for _ in range(m+1)] for i in range(1, m+1): for j in range(1, n+1): if X[i-1] == Y[j-1]: # Characters match! dp[i][j] = dp[i-1][j-1] + 1 else: dp[i][j] = max(dp[i-1][j], dp[i][j-1]) return dp[m][n] # Length of LCS # "AGGTAB" vs "GXTXAYB" → LCS = 4 (GTAB) # "ABCBDAB" vs "BDCABA" → LCS = 4 (BCBA)

MATRIX CHAIN MULTIPLICATION

Problem: N matrices ki chain hai — unhe multiply karne ka OPTIMAL ORDER kya hai (minimum scalar multiplications)?

Key Insight: Matrix multiplication associative hai (A×B)×C = A×(B×C) but cost different ho sakti hai!

WHY ORDER MATTERS — Example
# A1(10×100), A2(100×5), A3(5×50) # Option A: (A1×A2)×A3 cost_A1_A2 = 10×100×5 = 5000 # result: 10×5 cost_res_A3 = 10×5×50 = 2500 # result: 10×50 total_A = 7500 # ✅ OPTIMAL! # Option B: A1×(A2×A3) cost_A2_A3 = 100×5×50 = 25000 # result: 100×50 cost_A1_res = 10×100×50 = 50000 # result: 10×50 total_B = 75000 # ❌ 10x worse! # Same result, 10x different cost!
MATRIX CHAIN DP · O(n³)
def matrix_chain(dims): n = len(dims) - 1 # number of matrices # m[i][j] = min cost to multiply A_i ... A_j m = [[0]*n for _ in range(n)] # l = chain length (2 to n) for l in range(2, n+1): for i in range(n - l + 1): j = i + l - 1 m[i][j] = float('inf') for k in range(i, j): # Try all split points cost = (m[i][k] + m[k+1][j] + dims[i] * dims[k+1] * dims[j+1]) m[i][j] = min(m[i][j], cost) return m[0][n-1] # Minimum cost # dims=[10,100,5,50] → 7500 ✓
TRAVELLING SALESMAN PROBLEM (TSP)

Problem: N cities hain. Salesperson ko EVERY city exactly ONCE visit karna hai aur starting city wapas aana hai. Find the MINIMUM cost tour.

O(n!)
Naive — Try all (n-1)! permutations
n=10: 362,880 tours
n=20: 2.4 × 10¹⁸ tours 🤯
O(n²·2ⁿ)
Held-Karp DP Algorithm
n=10: ~100,000
n=20: ~4 × 10⁸ (feasible!)
TSP DP (Bitmask / Held-Karp) · O(n²·2ⁿ)
# State: dp[S][i] = min cost to visit cities in set S, # ending at city i, starting from city 0 # S is encoded as a bitmask (e.g., S=0b0101 = cities {0,2}) def tsp_dp(dist): n = len(dist) INF = float('inf') dp = [[INF] * n for _ in range(1 << n)] dp[1][0] = 0 # Start at city 0 (bit 0 set) for S in range(1 << n): # All subsets for u in range(n): if dp[S][u] == INF: continue if not (S >> u & 1): continue # u not in S for v in range(n): # Try going to v if S >> v & 1: continue # v already visited newS = S | (1 << v) new_cost = dp[S][u] + dist[u][v] dp[newS][v] = min(dp[newS][v], new_cost) full = (1 << n) - 1 # All cities visited return min(dp[full][i] + dist[i][0] for i in range(1, n)) # Recurrence: C(S,i) = min{ C(S-{i},j) + dist(j,i) } # Base: C({0,i}, i) = dist(0, i)

Backtracking

Lecture 27–28 · N-Queens · Subset Sum · Hamiltonian

THEORY

Core Idea: "Systematically try all possibilities, but PRUNE branches that cannot lead to a solution."

Real Life: Maze mein rasta dhundhna — ek rasta lo, agar band gali mili to wapas aao (backtrack) aur doosra rasta try karo!

1
Start with an empty/partial solution
2
Check: Kya ye partial solution valid hai? Kya isse solution mil sakta hai?
3
If valid: Extend karo (next choice try karo)
4
If invalid: Backtrack — last choice UNDO karo, try different choice
5
Stop when solution found OR all possibilities exhausted
Backtracking explores a state space tree. "Dead ends" are pruned early — we never generate ALL combinations!
N-QUEENS PROBLEM

Problem: N queens ko N×N chess board pe place karo jaise koi queen kisi doosri queen ko attack na kare (same row, column, diagonal — all forbidden).

1
Row by row solve karo — ek row mein sirf ek queen
2
Each column try karo current row mein
3
is_safe() check: Same column? Same diagonal? Agar haan → skip
4
If safe: Queen place karo, move to next row
5
If no column works: Backtrack to previous row, try next column there
N-QUEENS BACKTRACKING · Python
def solve_n_queens(n): board = [-1] * n # board[row] = column of queen solutions = [] def is_safe(row, col): for r in range(row): c = board[r] if c == col: return False # Same column if abs(c-col) == abs(r-row): # Same diagonal return False return True def backtrack(row): if row == n: # All queens placed! solutions.append(board[:]) return for col in range(n): # Try each column if is_safe(row, col): # Safe to place? board[row] = col backtrack(row + 1) # Next row board[row] = -1 # ← BACKTRACK! backtrack(0) return solutions # 4-Queens: 2 solutions # 8-Queens: 92 solutions

SUM OF SUBSETS

Problem: Set S = {S1, S2, ..., Sn} given. Find all subsets whose sum = target X.

Approach: Binary tree — left child = include element, right child = exclude element.

SUM OF SUBSETS · Backtracking with Pruning
def sum_of_subsets(arr, target): arr.sort() # Sort helps with pruning! solutions = [] def backtrack(start, curr_sum, subset): if curr_sum == target: solutions.append(subset[:]) # Found! return for i in range(start, len(arr)): # PRUNING: sorted, so if too large — stop! if curr_sum + arr[i] > target: break # All future elements also too large subset.append(arr[i]) backtrack(i+1, curr_sum + arr[i], subset) subset.pop() # ← BACKTRACK! backtrack(0, 0, []) return solutions # Example: arr=[3,2,7,1], target=6 # Solutions: [1,2,3], [6 if present], etc. # arr=[1,2,3,4], target=5 → [1,4], [2,3]
Pruning Trick: Array sort karo. Agar current_sum + arr[i] > target → BREAK. Baaki sab elements bhi zyada honge (sorted array). Ye prunes many branches!
HAMILTONIAN CIRCUIT

Problem: Graph G=(V,E) mein ek cycle dhundho jo EVERY vertex exactly ONCE visit kare aur starting vertex pe return kare.

Note: TSP = Hamiltonian Circuit + Minimum Cost. Hamiltonian just says "visit all" — TSP additionally minimizes cost.

HAMILTONIAN CIRCUIT · Backtracking
def hamiltonian(adj, n): path = [0] # Start from vertex 0 def is_safe(v, pos): if adj[path[pos-1]][v] == 0: # No edge return False if v in path: # Already visited return False return True def backtrack(pos): if pos == n: # All vertices included! # Check if last connects back to start return adj[path[pos-1]][path[0]] == 1 for v in range(1, n): if is_safe(v, pos): path.append(v) if backtrack(pos+1): return True path.pop() # ← BACKTRACK! return False # No circuit found if backtrack(1): return path + [path[0]] # Complete circuit return "No Hamiltonian Circuit exists"

Branch & Bound

Lecture 29–30 · 0/1 Knapsack · TSP

THEORY

Core Idea: Backtracking + Bounds. Optimization problems ke liye. Tree explore karo, but agar ek branch se current best beat nahi ho sakta (based on upper/lower bound) → PRUNE!

Proposed by: A.H. Land and A.G. Doig (1960) for linear programming.

🌿 BRANCHING

Problem ko subproblems mein split karo. Each split = a decision (include/exclude item, go to city X/Y).

🔢 BOUNDING

Har node ke liye best possible solution calculate karo. Agar bound ≤ current best → prune entire subtree!

KEY DIFFERENCE from Backtracking: B&B uses objective function bounds to prune. Backtracking only uses feasibility (constraint violated?). B&B is smarter!
0/1 KNAPSACK — BRANCH & BOUND

Key Idea: Fractional Knapsack greedy se upper bound calculate karo. Agar ye bound bhi current best profit se zyada nahi → prune!

1
Sort items by value/weight ratio (descending) — for efficient bounding
2
Upper bound: Current profit + greedy fractional fill of remaining capacity
3
If bound ≤ max_profit_so_far: Prune this node (can't improve)
4
Else: Branch — try both include item and exclude item
5
Use Best-First search (priority queue by bound) for better pruning
B&B KNAPSACK · Upper Bound Calculation
def upper_bound(profit, weight, idx, items, W): # Greedy fractional estimate from current state bound = profit w = weight for i in range(idx, len(items)): v, wt = items[i] if w + wt <= W: bound += v # Take full item w += wt else: bound += (W-w) * v/wt # Take fraction break return bound # If upper_bound(node) <= current_best → PRUNE! # This is the key pruning condition. # Example: items sorted by ratio # Current: profit=60, weight=10, idx=1 (item A taken) # Remaining capacity: W-10 # Fractionally fill remaining → upper bound # If bound <= best found → skip this branch!
TSP — BRANCH & BOUND

Key Technique: Cost matrix reduction. Subtract minimum from each row and column. Total subtracted = lower bound for any tour through this state!

TSP B&B — Matrix Reduction Steps
Step 1: Create cost matrix C[n×n] cij = edge cost from i to j cij = INF if no edge exists Step 2: Row Reduction For each row, subtract its minimum value row_reduction = sum of all minimums subtracted Step 3: Column Reduction For each column, subtract its minimum value col_reduction = sum of all minimums subtracted Step 4: Lower bound of root lb(root) = row_reduction + col_reduction Step 5: For edge (i→j) selected: a) Set entire row i = INF b) Set entire col j = INF c) Set C[j][start] = INF (prevent early return) d) Reduce resulting matrix again lb(child) = lb(parent) + C[i][j] + new_reduction Step 6: Prune if lb(node) >= current_best_tour_cost
