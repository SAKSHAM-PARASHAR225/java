Topic 1.0
What is a Package?
🗣 Hinglish Explanation

Package ek folder ki tarah hota hai Java mein. Jaise computer mein hum related files ek folder mein rakhte hain — waise hi Java mein related classes aur interfaces ko ek package mein organize karte hain. Socho agar tumhare paas 500 Java classes hain — sab ek jagah rakhoge to bahut confusion hoga. Package se sab sorted rehta hai!

Definition
A Package in Java is a namespace mechanism used to group related classes, interfaces, enumerations, and annotations together. It provides access protection and avoids naming conflicts.
Why Packages?
Organization

Related classes grouped logically — easy to find and manage.

Name Collision

Two classes with the same name can coexist in different packages.

Access Control

Package-level access protects classes from outside use.

Reusability

Packages can be imported and reused across projects.

Types of Packages
1. Built-in Packages (java.lang, java.util, etc.) 2. User Defined Packages (created by programmers)
✅ Advantages
Avoids class name conflicts
Better code organization
Reusability of classes
Access control/protection
Easy maintenance of large projects
❌ Disadvantages
Complex directory structure needed
Long import statements required
Circular dependency possible
Slight overhead for beginners

Topic 1.2 - 1.4
Creating, Accessing & Using User Defined Packages
🗣 Hinglish Explanation

User Defined Package matlab tumhara khud ka package. Jaise ek school mein alag-alag departments hote hain (Science, Arts, Commerce), waise hi tum apne project mein alag-alag packages bana sakte ho. Jaise com.school.science ya myapp.database. Pehle file ke upar package keyword likhte hain, phir alag folder mein rakhte hain. Doosri classes mein use karne ke liye import karte hain.

Step 1 — Creating a Package
Use the package keyword as the first statement in a Java file. The package name must match the folder/directory structure.
Syntax
package packageName; // simple package package com.company.module; // nested/subpackage (recommended)
Creating Package — Code
Java — mypackage/Calculator.java
// File path: mypackage/Calculator.java
package mypackage;  // First line - declares the package

public class Calculator {

    public int add(int a, int b) {
        return a + b;
    }

    public int subtract(int a, int b) {
        return a - b;
    }

    public double divide(double a, double b) {
        if(b == 0) throw new ArithmeticException("Cannot divide by zero!");
        return a / b;
    }
}
Step 2 — Accessing (Importing) the Package

Three ways to access a package:

1. Fully Qualified Name

Use complete class path each time. No import needed.

2. Import Specific Class

Import only the class you need — recommended practice.

3. Import All (*)

Import all classes from a package. Convenient but can slow compilation.

Java — Using the Package (Main.java)
// Method 1: Fully Qualified Name (no import)
mypackage.Calculator calc1 = new mypackage.Calculator();

// Method 2: Import specific class (BEST PRACTICE)
import mypackage.Calculator;

public class Main {
    public static void main(String[] args) {

        Calculator calc = new Calculator();
        System.out.println("Add: " + calc.add(10, 5));        // Output: 15
        System.out.println("Sub: " + calc.subtract(10, 5));   // Output: 5
        System.out.println("Div: " + calc.divide(10, 2));     // Output: 5.0
    }
}

// Method 3: Import all classes from package
import mypackage.*;   // Imports ALL classes from mypackage
Directory Structure
Package Folder Structure
Compile & Run Commands
// COMPILE javac mypackage/Calculator.java javac Main.java // RUN java Main // Compile with -d flag (auto-creates package directories) javac -d . Calculator.java // Creates mypackage/Calculator.class automatically
✅ Advantages
Full control over structure
Better modularization
Can set access levels
Reusable across projects
❌ Disadvantages
Must match folder structure exactly
CLASSPATH setup needed
Tedious for small programs

Writing to a File — Code
Java — FileWriter + BufferedWriter
import java.io.FileWriter;
import java.io.BufferedWriter;
import java.io.IOException;

public class WriteFile {
    public static void main(String[] args) {

        // try-with-resources (auto-closes stream)
        try (BufferedWriter bw = new BufferedWriter(new FileWriter("output.txt"))) {

            bw.write("Hello, Java File I/O!");
            bw.newLine();                   // new line
            bw.write("Second line here.");
            bw.newLine();
            bw.write("Third line done!");

            System.out.println("File written successfully!");

        } catch (IOException e) {
            System.out.println("Error: " + e.getMessage());
        }

        // Append mode - FileWriter(filename, true)
        try (FileWriter fw = new FileWriter("output.txt", true)) {
            fw.write("\nAppended line!");
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
Reading from a File — Code
Java — FileReader + BufferedReader
import java.io.FileReader;
import java.io.BufferedReader;
import java.io.IOException;

public class ReadFile {
    public static void main(String[] args) {

        try (BufferedReader br = new BufferedReader(new FileReader("output.txt"))) {

            String line;
            System.out.println("=== File Contents ===");

            // readLine() returns null at end of file
            while ((line = br.readLine()) != null) {
                System.out.println(line);
            }

        } catch (IOException e) {
            System.out.println("File not found: " + e.getMessage());
        }
    }
}

/* Output:
=== File Contents ===
Hello, Java File I/O!
Second line here.
Third line done!
Appended line!
*/
Byte Stream File I/O — Binary Files
Java — FileInputStream / FileOutputStream
import java.io.*;

public class ByteStreamDemo {
    public static void main(String[] args) throws IOException {

        // Writing bytes to file
        FileOutputStream fos = new FileOutputStream("data.bin");
        String data = "Binary Data Here";
        fos.write(data.getBytes()); // Convert string to bytes
        fos.close();

        // Reading bytes from file
        FileInputStream fis = new FileInputStream("data.bin");
        int byteData;
        System.out.print("Read: ");
        while ((byteData = fis.read()) != -1) {  // -1 = end of file
            System.out.print((char) byteData);   // Cast byte to char
        }
        fis.close();
    }
}

Topic 2.0
Exception Handling — Introduction
🗣 Hinglish Explanation

Exception matlab kuch unexpected/galat ho gaya program mein. Jaise agar tum kisi number ko zero se divide karo, ya kisi aisi file ko open karo jo exist hi na kare — ye sab exceptions hain. Java mein agar exception handle na karo, to program crash ho jata hai. Exception Handling se hum ek safety net bana dete hain — program gracefully handle karta hai aur crash nahi hota. try mein risky code, catch mein problem solve, finally mein cleanup!

Definition
An Exception is an event that disrupts the normal flow of program execution. It is an object that wraps an error event that occurred within a method. Java's exception handling mechanism uses try, catch, finally, throw, and throws keywords.
Exception vs Error
ExceptionError
Can be caught and handledUsually cannot be caught/recovered
Caused by application codeCaused by JVM/system problems
E.g., NullPointerException, IOExceptionE.g., StackOverflowError, OutOfMemoryError
java.lang.Exception is superclassjava.lang.Error is superclass
Exception Hierarchy
java.lang.Throwable
├── java.lang.Error Unrecoverable
│ ├── StackOverflowError
│ ├── OutOfMemoryError
│ └── VirtualMachineError
└── java.lang.Exception Recoverable
├── RuntimeException Unchecked
│ ├── NullPointerException
│ ├── ArrayIndexOutOfBoundsException
│ ├── ArithmeticException
│ └── ClassCastException
├── IOException Checked
│ ├── FileNotFoundException
│ └── EOFException
└── SQLException Checked
Checked vs Unchecked
Checked Exception

Compiler forces you to handle them. Must use try-catch or throws. E.g.: IOException, SQLException, ClassNotFoundException

Unchecked Exception

Runtime exceptions — compiler does NOT force handling. E.g.: NullPointerException, ArrayIndexOutOfBoundsException

Basic try-catch Syntax
try { // Risky/exception-prone code } catch (ExceptionType e) { // Handle the exception } finally { // Always executes (optional) }
Basic try-catch Example
Java — Basic Exception Handling
public class BasicException {
    public static void main(String[] args) {

        try {
            int result = 10 / 0;  // This throws ArithmeticException
            System.out.println("Result: " + result);  // Never executed
        } catch (ArithmeticException e) {
            System.out.println("Caught! Cannot divide by zero: " + e.getMessage());
        }

        System.out.println("Program continues normally...");
    }
}
/* Output:
   Caught! Cannot divide by zero: / by zero
   Program continues normally...
*/

Code — Common Built-in Exceptions Demo
Java — Built-in Exceptions Examples
public class BuiltInExceptions {
    public static void main(String[] args) {

        // 1. ArithmeticException
        try {
            int x = 5 / 0;
        } catch (ArithmeticException e) {
            System.out.println("1. Arithmetic: " + e.getMessage());
        }

        // 2. NullPointerException
        try {
            String s = null;
            System.out.println(s.length()); // NPE here
        } catch (NullPointerException e) {
            System.out.println("2. NullPointer: object is null");
        }

        // 3. ArrayIndexOutOfBoundsException
        try {
            int[] arr = {1, 2, 3};
            System.out.println(arr[5]); // index 5 doesn't exist
        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.println("3. Array out of bounds: " + e.getMessage());
        }

        // 4. NumberFormatException
        try {
            int num = Integer.parseInt("abc"); // "abc" is not a number
        } catch (NumberFormatException e) {
            System.out.println("4. NumberFormat: " + e.getMessage());
        }

        // 5. ClassCastException
        try {
            Object obj = "Hello";
            Integer num = (Integer) obj; // String cannot be cast to Integer
        } catch (ClassCastException e) {
            System.out.println("5. ClassCast: " + e.getMessage());
        }
    }
}
/* Output:
   1. Arithmetic: / by zero
   2. NullPointer: object is null
   3. Array out of bounds: Index 5 out of bounds for length 3
   4. NumberFormat: For input string: "abc"
   5. ClassCast: class java.lang.String cannot be cast to class java.lang.Integer
*/

Topic 2.2
User Defined (Custom) Exceptions
🗣 Hinglish Explanation

Kabhi-kabhi Java ke built-in exceptions hmare kaam nahi aate — kyunki problem business-specific hoti hai. Jaise ek bank app mein agar balance se zyada paise withdraw karne ki koshish karo — ye Java built-in mein nahi hai! Tab hum khud apna exception banate hain — Exception class ko extend karke. Phir jab galat condition aaye, throw se usse throw karte hain.

Definition
A User Defined (Custom) Exception is an exception created by the programmer by extending the Exception class (or RuntimeException). It provides meaningful, domain-specific error messages for business logic violations.
Syntax — Creating Custom Exception
class CustomException extends Exception { // Checked CustomException(String message) { super(message); // Pass message to parent } } class CustomRuntimeException extends RuntimeException { // Unchecked CustomRuntimeException(String message) { super(message); } }
Code — Bank Balance Custom Exception
Java — User Defined Exception
// Step 1: Create custom exception class
class InsufficientFundsException extends Exception {
    private double amount;

    InsufficientFundsException(double amount) {
        super("Insufficient funds! Tried to withdraw: ₹" + amount);
        this.amount = amount;
    }

    double getAmount() { return amount; }
}

// Step 2: Use custom exception in a class
class BankAccount {
    private double balance;

    BankAccount(double initialBalance) {
        this.balance = initialBalance;
    }

    void withdraw(double amount) throws InsufficientFundsException {
        if (amount > balance) {
            throw new InsufficientFundsException(amount);  // throw!
        }
        balance -= amount;
        System.out.println("Withdrawn: ₹" + amount + ", Remaining: ₹" + balance);
    }
}

// Step 3: Handle the custom exception
public class BankDemo {
    public static void main(String[] args) {
        BankAccount acc = new BankAccount(5000);

        try {
            acc.withdraw(2000);   // OK
            acc.withdraw(4000);   // Throws InsufficientFundsException
        } catch (InsufficientFundsException e) {
            System.out.println("Error: " + e.getMessage());
            System.out.println("Amount attempted: ₹" + e.getAmount());
        }
    }
}
/* Output:
   Withdrawn: ₹2000.0, Remaining: ₹3000.0
   Error: Insufficient funds! Tried to withdraw: ₹4000.0
   Amount attempted: ₹4000.0
*/
Another Example — Age Validation
Java — InvalidAgeException
class InvalidAgeException extends Exception {
    InvalidAgeException(String msg) { super(msg); }
}

public class AgeCheck {
    static void validateAge(int age) throws InvalidAgeException {
        if (age < 18)
            throw new InvalidAgeException("Age must be 18+! Your age: " + age);
        System.out.println("Welcome! Age verified: " + age);
    }

    public static void main(String[] args) {
        try {
            validateAge(25);  // OK
            validateAge(15);  // Throws InvalidAgeException
        } catch (InvalidAgeException e) {
            System.out.println("Caught: " + e.getMessage());
        }
    }
}

Topic 2.3
Handling Multiple Exceptions
🗣 Hinglish Explanation

Ek try block mein alag-alag types ki exceptions aa sakti hain. Jaise tum array access karo aur number format bhi parse karo — dono alag exceptions. Tab hum multiple catch blocks likhte hain — jaise multiple security guards at different gates. Har catch ek alag type ki exception ko pakadta hai. Java 7 se ek catch mein multiple exceptions bhi pakad sakte ho pipe (|) se.

Syntax — Multiple Catch Blocks
try { // risky code with multiple possible exceptions } catch (ExceptionType1 e) { // handle exception 1 } catch (ExceptionType2 e) { // handle exception 2 } catch (ExceptionType3 e) { // handle exception 3 } catch (Exception e) { // catch-all (most general — must be LAST) }
Syntax — Multi-catch (Java 7+)
// Java 7+ multi-catch: pipe (|) operator try { // code } catch (ArithmeticException | NullPointerException e) { // Handle both in one block }
Code — Multiple Catch Blocks
Java — Multiple Exception Handling
public class MultipleExceptions {

    static void process(int choice) {
        int[] arr = {10, 20, 30};
        String[] data = {"100", "abc", "300"};

        try {
            if (choice == 1) {
                int result = arr[5];    // ArrayIndexOutOfBoundsException
            } else if (choice == 2) {
                int num = Integer.parseInt(data[1]);  // NumberFormatException
            } else if (choice == 3) {
                String s = null;
                s.length();              // NullPointerException
            } else {
                int x = 10 / 0;          // ArithmeticException
            }

        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.println("Array error: " + e.getMessage());

        } catch (NumberFormatException e) {
            System.out.println("Number parse error: " + e.getMessage());

        } catch (NullPointerException e) {
            System.out.println("Null reference error!");

        } catch (Exception e) {    // Generic - catches anything else
            System.out.println("General error: " + e.getMessage());
        }
    }

    public static void main(String[] args) {
        process(1);   // Array error
        process(2);   // Number format error
        process(3);   // Null pointer error
        process(4);   // Arithmetic error (caught by general catch)
    }
}
/* Output:
   Array error: Index 5 out of bounds for length 3
   Number parse error: For input string: "abc"
   Null reference error!
   General error: / by zero
*/
Code — Java 7 Multi-catch (|) Operator
Java 7+ — Multi-catch with pipe
import java.io.*;

public class MultiCatch {
    public static void main(String[] args) {

        try {
            int[] arr = new int[3];
            arr[5] = 10;  // Might throw ArrayIndexOutOfBoundsException
            int x = 10 / 0;  // Might throw ArithmeticException

        } catch (ArrayIndexOutOfBoundsException | ArithmeticException e) {
            // Same handling for both exceptions
            System.out.println("Caught: " + e.getClass().getSimpleName()
                               + " — " + e.getMessage());
        }
    }
}
// Note: In multi-catch, 'e' is effectively final — cannot reassign
⚠️ Important Rule

Catch blocks must be ordered from most specific to most general. If you put Exception (parent) before NullPointerException (child), it causes a compile error — "exception already caught".

Topic 2.4
The finally Clause
🗣 Hinglish Explanation

finally block hamesha execute hota hai — chahe exception aaye ya na aaye! Ye jaise ek promise hai Java ka — "main zaroor chalunga." Iska use mainly cleanup kaam ke liye hota hai — jaise file close karna, database connection close karna, ya resources free karna. Yani chahe try mein kuch bhi ho, chahe catch execute ho ya na ho, finally hamesha run karta hai (except: System.exit() call ho to nahi chalta).

Definition
The finally block is an optional block that always executes regardless of whether an exception was thrown or caught. It is used for cleanup activities like closing files, releasing connections, or freeing resources.
Syntax
try { // risky code } catch (Exception e) { // handle exception } finally { // ALWAYS executes — cleanup code here // Close files, connections, release resources }
When does finally NOT execute?
System.exit() is called JVM crashes (OutOfMemoryError) Power failure / machine shutdown
Code — finally Clause Demo
Java — finally Block
import java.io.*;

public class FinallyDemo {

    // Case 1: No exception — finally still runs
    static void case1() {
        System.out.println("\n--- Case 1: No Exception ---");
        try {
            System.out.println("In try block");
            int x = 10 / 2;  // No exception
            System.out.println("Result: " + x);
        } catch (ArithmeticException e) {
            System.out.println("In catch block");  // Skipped
        } finally {
            System.out.println("In finally — ALWAYS runs!");
        }
    }

    // Case 2: Exception occurs — catch + finally both run
    static void case2() {
        System.out.println("\n--- Case 2: Exception Caught ---");
        try {
            System.out.println("In try block");
            int x = 10 / 0;  // Exception!
        } catch (ArithmeticException e) {
            System.out.println("In catch: " + e.getMessage());
        } finally {
            System.out.println("In finally — still runs!");
        }
    }

    // Real-world: File closing in finally
    static void readFile() {
        BufferedReader br = null;
        System.out.println("\n--- File Read with Finally ---");
        try {
            br = new BufferedReader(new FileReader("test.txt"));
            System.out.println(br.readLine());
        } catch (IOException e) {
            System.out.println("File error: " + e.getMessage());
        } finally {
            try {
                if (br != null) br.close();  // Always close!
                System.out.println("Reader closed in finally.");
            } catch (IOException e) { }
        }
    }

    public static void main(String[] args) {
        case1();
        case2();
        readFile();
    }
}
/* Output:
--- Case 1: No Exception ---
In try block
Result: 5
In finally — ALWAYS runs!

--- Case 2: Exception Caught ---
In try block
In catch: / by zero
In finally — still runs!

--- File Read with Finally ---
File error: test.txt (No such file or directory)
Reader closed in finally.
*/

Guarantees resource cleanup

Topic 2.5
The throws Clause (throw vs throws)
🗣 Hinglish Explanation

Socho tum ek method bana rahe ho jo koi risky kaam karta hai — tum us method mein exception handle nahi karna chahte, balki caller ko bhejna chahte ho ki "yaar, ye method exception throw kar sakta hai, tum handle karo!" — iske liye throws keyword use hota hai method signature mein. Aur jab actually exception throw karni ho manually, tab throw keyword use hota hai (bina 's' ke). Ye dono alag hain!

throw vs throws — Comparison
throwthrows
Used to explicitly throw an exceptionUsed in method signature to declare exceptions

Java — throw and throws Keywords
import java.io.*;

public class ThrowDemo {

    // Method declares it MIGHT throw IOException
    // 'throws' = declaration / warning to caller
    static void readData(String filename) throws IOException {
        if (filename == null) {
            // 'throw' = actually throwing the exception
            throw new IOException("Filename cannot be null!");
        }
        BufferedReader br = new BufferedReader(new FileReader(filename));
        System.out.println(br.readLine());
        br.close();
    }

    // Method throws multiple exceptions
    static void processData(int x) throws ArithmeticException, NullPointerException {
        if (x == 0)
            throw new ArithmeticException("x cannot be zero!");
        if (x < 0)
            throw new NullPointerException("x cannot be negative!");
        System.out.println("Processing: " + (100 / x));
    }

    public static void main(String[] args) {

        // Must handle because readData() uses 'throws'
        try {
            readData(null);
        } catch (IOException e) {
            System.out.println("Caught: " + e.getMessage());
        }

        // processData can throw two types
        try {
            processData(5);   // OK
            processData(0);   // ArithmeticException
        } catch (ArithmeticException | NullPointerException e) {
            System.out.println("Process error: " + e.getMessage());
        }
    }
}
/* Output:
   Caught: Filename cannot be null!
   Processing: 20
   Process error: x cannot be zero!
*/

Java — Full Exception Demo (All Concepts)
import java.io.*;

// Custom Exception
class AgeException extends Exception {
    AgeException(String msg) { super(msg); }
}

public class CompleteExceptionDemo {

    // Method with throws
    static void validateAge(int age) throws AgeException {
        if (age < 0 || age > 150)
            throw new AgeException("Invalid age: " + age);
        System.out.println("Valid age: " + age);
    }

    public static void main(String[] args) {
        int[] ages = {25, -5, 200};

        for (int age : ages) {
            try {
                System.out.print("Testing age " + age + ": ");
                validateAge(age);          // might throw

            } catch (AgeException e) {   // custom exception
                System.out.println("AgeError: " + e.getMessage());

            } catch (Exception e) {      // general catch
                System.out.println("Error: " + e.getMessage());

            } finally {                  // always runs
                System.out.println("  [finally] loop iteration done.");
            }
        }
        System.out.println("\nProgram completed successfully!");
    }
}
/* Output:
Testing age 25: Valid age: 25
  [finally] loop iteration done.
Testing age -5: AgeError: Invalid age: -5
  [finally] loop iteration done.
Testing age 200: AgeError: Invalid age: 200
  [finally] loop iteration done.

Program completed successfully!
*/
✅ Advantages of throws
Propagates exception to caller
Clean separation of concerns
Forces caller awareness
Method stays clean (no try-catch clutter)
❌ Disadvantages
Caller must always handle
Long chain of throws possible
Can lead to exception swallowing
