RAID – Redundant Array of Independent Disks

Lecture 31 · PPT: Lecture-31_Raid.pptx
Slide 3–5What is RAID? Why RAID?

Definition: RAID combines multiple small, inexpensive disk drives into an array of disk drives whose performance exceeds that of a Single Large Expensive Drive (SLED). The array appears to the OS as one single logical storage unit — this is an example of storage virtualization.

RAID stores the same data in different places (redundantly) on multiple hard disks. Because multiple disks overlap their I/O operations in a balanced way, both performance and fault tolerance improve. Storing data redundantly increases the Mean Time Between Failures (MTBF).

🇮🇳 Hinglish Explanation

RAID ek aisa system hai jisme bahut saare chhote-chhote disk drives ko milake ek bada aur fast storage banate hain. Jaise 10 chote coolie milke ek heavy luggage uthate hain, waisi tarah kai disks milke kaam karte hain. Computer ko lagta hai yeh ek hi disk hai. Agar ek disk fail bhi ho jaaye, toh data doosri disk mein safe rehta hai — yahi RAID ki khasiyat hai.

🇬🇧 Plain English

RAID is a technology that groups multiple physical hard drives together so they work as one unit. The operating system sees them as a single disk. By spreading data across drives, RAID improves both speed (parallelism) and safety (if one drive dies, data isn't lost). The concept is called "storage virtualization."

⚠️ Exam Point

RAID full form is Redundant Array of Independent Disks (older: Inexpensive Disks). The two key goals are: (1) increase data reliability/capacity and (2) increase I/O performance. RAID is named RAID-0, RAID-1 ... RAID-6. Always remember SLED = Single Large Expensive Drive.

Slide 7–8Striping – Fundamental Concept

Striping is a method of concatenating multiple drives into one logical unit by partitioning each drive's storage into stripes — which can be as small as one sector (512 bytes) or as large as several megabytes. The processor doesn't idle waiting for data because multiple stripes are read/written in parallel.

How Striping Works (RAID 0)
  File Data:  [Block A] [Block B] [Block C] [Block D] [Block E] [Block F]

  Disk 1:  ┌─────────┬─────────┬─────────┐
           │ Block A │ Block C │ Block E │   ← Every alternate block
           └─────────┴─────────┴─────────┘
  Disk 2:  ┌─────────┬─────────┬─────────┐
           │ Block B │ Block D │ Block F │   ← Every other block
           └─────────┴─────────┴─────────┘
              ↑ Both read simultaneously = DOUBLE SPEED ↑
🇮🇳 Hinglish

Striping matlab hai data ko chhote-chhote tukdon mein kaat ke alag-alag disks mein store karna. Jaise pizza ke 6 slice ek baar mein 6 logon ko mile — sab ek saath khaate hain, jaldi khatam hoti hai. Aise hi data parallel mein read/write hota hai, speed badh jaati hai. Lekin agar ek disk kharaab ho gayi toh poora data kho jaata hai — koi backup nahi!

⚠️ Key Point

Striping = No fault tolerance. Any disk failure = total data loss. Used in RAID 0 only for maximum speed.

Slides 7–17All RAID Levels – Detailed
🔴 RAID 0 – Striping (No Redundancy)

Data is split (striped) across drives giving maximum read/write throughput. No redundant information is stored. Failure of ANY single disk = complete data loss. Minimum 2 disks required.

  Disk1: [A1][A3][A5]
  Disk2: [A2][A4][A6]   ← Data split, no copy
  Performance: ★★★★★   Reliability: ✗ (zero)

No Fault ToleranceMax SpeedMin 2 Disks

Real-life: Used in gaming rigs, video editing stations where speed matters more than safety. Not for banking data!

🟢 RAID 1 – Mirroring (100% Duplication)

All data is written to two or more drives simultaneously. If one drive fails, the other has a complete copy. Reads can be faster (read from either), writes are same speed. High cost: 50% of storage is overhead. Minimum 2 disks.

  Disk1: [A1][A2][A3]  (Primary)
  Disk2: [A1][A2][A3]  (Exact Mirror Copy)
          ↑ identical data on both disks ↑
  If Disk1 fails → Disk2 serves all data!

100% Fault ToleranceGood Read Speed50% Space Waste

Real-life: Used in ATMs, hospitals, and financial servers where data must never be lost.

🟡 RAID 2 – Hamming Error Correction (Rarely Used)

Uses Hamming error correction codes. Intended for drives without built-in error detection. All SCSI drives already have built-in error detection, making RAID 2 practically obsolete. Requires 39 disks — very expensive and rarely used.

ObsoleteHamming Code39 Disks Needed

🔵 RAID 3 – Byte-Level Striping with Dedicated Parity

All disk spindles are synchronized. Data is striped byte-by-byte across disks. A dedicated parity disk stores parity information calculated from corresponding bytes on all data disks. If one disk fails, data can be reconstructed from remaining disks + parity.

  Disk1: [B1][B4][B7]  ← byte 1, 4, 7...
  Disk2: [B2][B5][B8]  ← byte 2, 5, 8...
  Disk3: [B3][B6][B9]  ← byte 3, 6, 9...
  ParityDisk: [P1][P2][P3]  ← P = XOR of all bytes in stripe
  
  If Disk2 fails: B2 = P XOR B1 XOR B3 (reconstructed!)

1-Disk Fault ToleranceDedicated Parity

🟣 RAID 4 – Block-Level Striping with Dedicated Parity

Like RAID 3 but striping is at block level (not byte). One dedicated parity drive. Read performance is excellent (same as RAID 0). Writes are slow because parity must be recalculated and updated each time. Cost is low since only one parity disk used.

Good Read SpeedSlow WritesDedicated Parity Block

🟦 RAID 5 – Block Striping with Distributed Parity ⭐ Most Popular

Most widely used RAID level. Parity is distributed across all drives (no dedicated parity disk). All drives but one must be present to operate. A single drive failure doesn't destroy the array — reads continue by recalculating from distributed parity. Minimum 3 disks.

  Disk1: [A1][B1][C1][P4]  ← parity rotates!
  Disk2: [A2][B2][P3][C2]
  Disk3: [A3][P2][B3][C3]
  Disk4: [P1][A4][B4][C4]
  
  P = Parity (XOR of all data in stripe row)
  Parity is spread = no bottleneck on one disk!
  
  Any ONE disk failure → data reconstructed from others

Best BalanceDistributed ParityMin 3 Disks1-Disk Fault Tolerance

Real-life: Used in NAS drives, enterprise servers, cloud storage backends. Best choice for most use cases.

⚠️ Most Expected

RAID 5 is the most commonly asked RAID level in exams. Remember: distributed parity, not dedicated parity. Tolerates exactly 1 disk failure. Performance degrades after failure until rebuilt.

🟠 RAID 6 – Block Striping with Double Distributed Parity

Like RAID 5 but uses two sets of distributed parity, tolerating 2 simultaneous disk failures. Essential for large arrays where rebuild time is long — during RAID 5 rebuild, a second failure would cause total data loss. RAID 6 gives extra protection window. Minimum 4 disks.

  Disk1: [A1][P+Q area][C1]
  Disk2: [A2][B2][P+Q ]
  Disk3: [P][A3][B3 ]
  Disk4: [Q][P ][A4 ]
  
  TWO parity blocks (P and Q) per stripe row
  → Can survive 2 disk failures simultaneously!

2-Disk Fault ToleranceDouble ParityMore OverheadMin 4 Disks

Real-life: Used in large data centers, cloud providers like AWS, where arrays have 20+ disks and single-parity isn't enough.

AnalysisProblems with RAID

Although RAID improves performance and reliability, it has several important limitations that are often tested in exams.

ProblemExplanation
No protection against data corruptionIf data is corrupted (logical error), corruption gets mirrored/striped too. RAID protects against hardware failure, not data errors.
Slow rebuild timeAfter a disk fails, rebuilding the array from parity can take hours–days for large drives. During rebuild, another failure = data loss.
RAID 0 – no redundancyAny single disk failure = 100% data loss. Most dangerous RAID level.
High costRAID 1 wastes 50% storage. RAID 5/6 need extra parity disks.
Controller failureIf RAID controller fails, the entire array may become inaccessible.
Write penaltyRAID 5/6 have write penalty because parity must be calculated and written on every write operation.
Not a backupRAID is NOT a substitute for backups. Accidental deletion, viruses, and ransomware affect all mirrors equally.
⚠️ Common Exam Mistake

Students often write "RAID = Backup." WRONG! RAID protects against hardware failure only. It does NOT protect against software corruption, deletion, or ransomware. Always state: "RAID is fault tolerance, not backup."

🇮🇳 Hinglish

RAID ke problems: Sabse badi galti — RAID ko backup samajhna. RAID sirf disk failure se bachata hai. Agar virus ne poora data delete kar diya, RAID mein bhi delete ho jaayega. Rebuild time bhi problem hai — badi disk rebuild hone mein 10+ ghante lagte hain aur us time ek aur disk fail ho gayi toh sab khatam. RAID 5 mein write karte time parity calculate karni padti hai — iska matlab write operations thode slow hote hain.

System Protection & Security

PPTs: L-3_1_1 to L-3_1_4
Slide 3 – L-3_1_1Goals of Protection

In a protection model, a computer consists of a collection of objects (hardware or software). Each object has a unique name and can be accessed only through a well-defined set of operations. The protection problem is to ensure that each object is accessed correctly and only by those processes that are allowed to do so.

🇮🇳 Hinglish

Computer mein jo bhi cheez hoti hai — file, printer, memory, CPU — yeh sab "objects" hain. Protection ka goal hai ki har object sirf usko access kare jise permission di gayi hai. Jaise bank locker — sirf account holder hi khol sakta hai, koi stranger nahi. OS ka kaam hai yeh ensure karna ki koi galat banda galat cheez access na kare.

🇬🇧 English

Protection in OS means controlling who can access which resources. Every hardware or software resource is an "object." The OS ensures that processes access objects only in authorized ways — for example, a print operation on a printer, or a read operation on a file.

Keywords
ObjectProtection ProblemAccess RightsAuthorized Access
Slide 4Principles of Protection

The guiding principle is the Principle of Least Privilege — programs, users, and systems should be given just enough privileges to perform their tasks, and nothing more.

ConceptExplanation
Principle of Least PrivilegeGive minimum permissions needed. If a process only needs read access, don't give write or execute.
Static PrivilegesFixed for life of system/process. Never change during execution.
Dynamic PrivilegesChange as needed — domain switching, privilege escalation (e.g., sudo in Linux).
Coarse-grained (Rough-grained)Simple to implement, easier to manage. Less secure but less overhead.
Fine-grainedComplex, more overhead, but much more protective. More secure.
DomainCan be a user, a process, or a procedure.
🇮🇳 Hinglish

Principle of Least Privilege matlab: jitni zaroorat utni hi power do. Agar ek program ko sirf read karna hai, toh use write power mat do. Yeh ek safeguard hai — agar program mein bug aya, toh woh sirf utna hi damage kar sakta hai jitni use permission thi. Jaise peon ko office ki master key mat do — sirf apne room ki key do!

⚠️ Exam Point

Principle of Least Privilege is THE most important principle in OS protection. Always explain: "if an entity (process/user) has a bug or is compromised, damage is limited to only the privileges it was granted."

Slide 5Domain Structure

An access-right is defined as <object-name, rights-set> where rights-set is a subset of all valid operations on that object. A Domain is a set of access-rights. A process executes in exactly one domain at a time, and that domain determines what objects it can access and how.

Domain Structure Diagram
  Domain D1:                 Domain D2:              Domain D3:
  ┌──────────────────┐       ┌──────────────────┐    ┌──────────────────┐
  │ File F1: {Read}  │       │ File F1: {Read}  │    │ File F2: {Read}  │
  │ File F2: {Read,  │       │ Printer: {Print} │    │ File F3: {Read,  │
  │          Write}  │       │                  │    │          Write,  │
  │ Printer: {Print} │       │                  │    │          Execute}│
  └──────────────────┘       └──────────────────┘    └──────────────────┘
  
  A process in Domain D1 can Read F1, Read+Write F2, Print.
  A process in Domain D2 can only Read F1 and Print.
  Objects outside your domain are COMPLETELY inaccessible!
🇮🇳 Hinglish

Domain ek box ki tarah hai jisme sirf kuch hi permissions hain. Jaise school mein: student domain ke pass library access hai, canteen access hai — principal room nahi. Teacher domain ke pass staffroom bhi hai. Har process apne domain ke hisaab se hi objects access kar sakti hai.

The Access Matrix is a 2D matrix where:

  • Rows represent Domains (D1, D2, D3...)
  • Columns represent Objects (Files, Printers, Disks...)
  • Access(i,j) = set of operations that process in Domain-i can invoke on Object-j

🇮🇳 Hinglish

Access Matrix ek badi table hai — rows mein domains (jaise User1, User2, Admin) aur columns mein objects (jaise File1, Printer, Database). Har cell mein likha hota hai — is domain ko is object par kya karna allowed hai. Agar cell khali hai toh bilkul access nahi. Yeh ek permissions table ki tarah hai, jaise school ke register mein — kaun si class kaun si lab use kar sakti hai.

⚠️ Frequently Asked

Access Matrix separates mechanism (OS provides the matrix + rules) from policy (user dictates who can do what). This is a key design principle. Also remember the 4 special rights: owner, copy, control, transfer.

Slides 14–16Implementation of Access Matrix

The access matrix is generally a sparse matrix (most cells are empty). Four implementation strategies exist:

#MethodHow it WorksProblem
1 Global Table Store ordered triples <domain, object, rights-set> in a global table. To check: search for <Di, Oj, Rk> where operation M ∈ Rk. Table can be huge → won't fit in main memory. Difficult to group objects.
2 Access Lists (ACL) Each column (object) has a list of <domain, rights-set> pairs. Like: File F1 → {D1:Read, D3:Read,Write}. A default set can grant common access. Checking requires scanning entire list for each access.
3 Capability List Each row (domain) has a list of <object, rights> pairs. Like a key ring — possession of capability = permission. Protected by OS, never directly accessible by domain itself. Like a "secure pointer." Revoking access is complex — must find all capability lists that mention the object.
4 Lock-Key Compromise between ACL and Capability list. Each object has locks (unique bit patterns); each domain has keys. Access allowed only if domain has a key matching one of the object's locks. Managing locks and keys adds overhead.

🇮🇳 Hinglish

Global Table: Ek badi diary mein sab kuch likho — lekin itni badi hogi ki RAM mein fit nahi hogi.
Access List (ACL): Har file ke saath ek list — kaun-kaun use access kar sakta hai. Jaise building ke gate par register — kaun andar ja sakta hai.
Capability List: Har user ke paas ek keys ka bunch — jinke paas key hai woh enter kar sakte hain. Jaise college ID card.
Lock-Key: Dono ka combination — file mein lock, user ke paas key. Match karo, andar jao.

⚠️ Exam Point

Most important to remember: ACL = object-based (column), Capability List = domain-based (row). Capability lists are protected by OS — domain can't directly access them (hence "secure pointer"). Unix uses ACL. Ask: "Which implementation is best for revoking access?" → ACL (just remove the entry from the object's list).

The Security Problem & Threats

PPT: L-3_1_2
Slide 3–6Security Problem & Violation Categories

A system is secure if resources are used and accessed as intended under all circumstances — but this is unachievable in practice. An Intruder (cracker) attempts to breach security. A threat is a potential security violation; an attack is an actual attempt. Attacks can be accidental or malicious. Accidental misuse is easier to protect against than deliberate attacks.

Violation CategoryDefinitionExample
Breach of ConfidentialityUnauthorized reading of dataHacker reads your bank statements
Breach of IntegrityUnauthorized modification of dataAttacker changes exam scores in DB
Breach of AvailabilityUnauthorized destruction of dataRansomware encrypts all files
Theft of ServiceUnauthorized use of resourcesUsing someone's Netflix account
Denial of Service (DoS)Preventing legitimate useFlooding a web server so it can't respond to real users
🇮🇳 Hinglish

Security violations ke 5 types hain:
1. Confidentiality — kisi ne bina permission ke aapka data padh liya.
2. Integrity — data change kar diya (marks badle, bank balance modify kiya).
3. Availability — data hi destroy kar diya (ransomware).
4. Theft of Service — tumhari bandwidth use ki, crypto mine ki tumhare PC par.
5. DoS — server ko itne requests bhejo ki woh genuine users ke liye unavailable ho jaaye.

Cryptography as a Security Tool

PPT: L-3_1_3
Slides 3–5Why Cryptography?

Cryptography is the broadest security tool available. Within a computer, source and destination are known and OS can protect them. But over a network, we cannot trust source/destination without cryptography — IP addresses can be spoofed, unauthorized hosts can be added. Cryptography solves: confirmation of source, receipt only by certain destination, and trust relationships.

🇮🇳 Hinglish

Computer ke andar OS sab kuch control karta hai — koi problem nahi. Lekin jab internet par message jaata hai, kaise pata ki woh sahi jagah se aaya? Kaise pata ki beech mein kisi ne padha nahi? Authentication

PPT: L-3_1_4
Slides 3–8Authentication Types

Authentication constrains the set of potential senders of a message — it proves who sent a message. It can also prove the message was not modified. Three main types:

TypeHow It WorksExample
Hash Function (Message Digest)Creates a small, fixed-size hash from the message. MD5 = 128-bit hash; SHA-1 = 160-bit hash. Hash is collision-resistant: impossible to find m' ≠ m such that H(m)=H(m'). If hashes match, message is unchanged.Downloading a file and checking its MD5 checksum to verify it wasn't corrupted
MAC (Message Authentication Code)Uses symmetric encryption. MAC = f(k, H(m)). Both sender and receiver need same key k. Any computer with k can both generate and verify MACs.HMAC in API authentication (e.g., AWS uses HMAC-SHA256)
Digital SignatureUses asymmetric keys. Sender signs with private key; anyone verifies with sender's public key. Based on RSA (but key use is REVERSED from encryption). Provides non-repudiation.Signing software updates, PDF documents, emails (S/MIME)

🇮🇳 Hinglish

Hash Function: Message se ek chhota "fingerprint" banana — koi bhi change hua toh fingerprint change ho jaayega. MD5 = 128 bit, SHA-1 = 160 bit fingerprint.
MAC: Symmetric key use karke message ki "seal" banana — jaise letter par wax seal jo sirf secret key se banti aur verify hoti hai.
Digital Signature: Private key se sign karo, sab log public key se verify kar sakte hain. Agar signature valid hai, pakka sender ne hi bheja — yahi non-repudiation hai (sender mana nahi kar sakta ki usne message nahi bheja).

Slides 12–13User Authentication & Passwords

User identity is most often established through passwords. Password security practices:

  • Passwords stored encrypted (never in plaintext) — Unix uses /etc/shadow (superuser-only readable)
  • Add "salt" to password before hashing — prevents same password mapping to same encrypted value
  • One-time passwords — hardware token (key fob) generates password that changes very frequently
  • Biometrics — fingerprint, hand scan, retina scan
  • Multi-factor authentication (MFA) — requires 2+ factors (e.g., password + USB dongle + biometric)
Why "salt"? Without salt, if two users have the same password "hello123," they'd have the same hash. An attacker could use a rainbow table (precomputed hash list) to crack many accounts at once. Salt adds a random value to each password before hashing, making rainbow table attacks ineffective.
⚠️ Exam Point

Authentication vs Encryption: Authentication proves who sent a message + that it wasn't modified. Encryption provides confidentiality. Digital signatures provide non-repudiation (sender cannot deny sending). MFA requires 2+ independent factors from: something you know (password), something you have (key fob), something you are (biometric).

Combined Revision Notes

🔴 RAID – Quick Revision

RAID = Redundant Array of Independent Disks. Replaces SLED (Single Large Expensive Drive). Two goals: reliability + performance.
RAID 0 = Striping only. No fault tolerance. Max speed. Any disk fail = data loss.
RAID 1 = Mirroring. 100% duplication. Min 2 disks. 50% storage waste. Best for critical data.
RAID 2 = Hamming ECC. Obsolete (needs 39 disks). SCSI drives don't need it.
RAID 3 = Byte-level stripe + dedicated parity disk. Synchronized spindles.
RAID 4 = Block-level stripe + dedicated parity. Good reads, slow writes.
RAID 5 = Block stripe + DISTRIBUTED parity. Most popular. Min 3 disks. 1-disk failure tolerance.
RAID 6 = Block stripe + DOUBLE distributed parity. 2-disk failure tolerance. Min 4 disks.
RAID is NOT a backup! Protects only against hardware failure.

🛡️ Protection – Quick Revision

Goal of Protection: Each object accessed correctly and only by authorized processes.
Principle of Least Privilege: Give minimum privileges needed — limits damage from bugs/compromises.
Domain: Set of access-rights. Access-right = <object-name, rights-set>.
Access Matrix: Rows = Domains, Columns = Objects, Cell = Allowed operations.
Special rights: owner, copy(*), control, transfer.
Implementation: Global Table (too large), ACL (column/object-based), Capability List (row/domain-based, secure pointer), Lock-Key (compromise).
Mechanism (OS enforces) vs Policy (user defines who gets what) — important design principle.

🔓 Security Threats – Quick Revision

5 Violation Categories: Confidentiality, Integrity, Availability, Theft of Service, DoS. Mnemonic: CIA+TS.
Attack methods: Masquerading, Replay, MITM, Session Hijacking.
Program Threats: Trojan Horse, Trap Door, Logic Bomb, Buffer Overflow, Virus.
Virus vs Worm: Virus needs host program. Worm is standalone (uses network spawn mechanism).
Network Threats: Worm, Port Scanning (nmap, nessus), DoS/DDoS, Keystroke Logger, Botnet.
Security Levels: Physical, Human, OS, Network (weakest link determines overall security).

🔐 Cryptography & Auth – Quick Revision

Symmetric: Same key encrypt+decrypt. DES, 3DES, AES, RC4. Fast. Key distribution is the problem.
Asymmetric: Public key (encrypt) + Private key (decrypt). RSA. Slow. Based on prime factoring.
Hash: MD5=128-bit, SHA-1=160-bit. Collision-resistant fingerprint of message.
MAC: Symmetric key + hash. Both parties need same key.
Digital Signature: Sign with private key, verify with public key. Provides non-repudiation. RSA reversed.
Passwords: Stored encrypted with salt. Unix: /etc/shadow. One-time passwords. Biometrics. MFA.
Firewall types: Network, Personal, Application Proxy, System-Call.
DoD Security Levels: D (minimal) → C1 → C2 → B1 → B2 → B3 → A (highest, formal verification).

🌐 Distributed OS – Quick Revision

Distributed system: Loosely coupled processors on communication network. Reasons: Resource sharing, Speed, Reliability, Communication.
Network OS: User aware of multiple machines, explicit access (telnet, FTP).
Distributed OS: Transparent, user unaware. Data/Computation/Process migration automatic.
LAN: 10–100 Mbps, small area. WAN: 1.544–45 Mbps, large area.
Topology criteria: Installation cost, Communication cost, Reliability.
Routing: Fixed (predefined), Virtual Circuit (session-fixed), Dynamic (real-time, may arrive out-of-order).
Switching: Circuit (telephone), Message (post), Packet (internet).
Contention: CSMA/CD (Ethernet), Token Passing (IBM Token Ring), Message Slots.
OSI 7 layers: Physical → Data Link → Network → Transport → Session → Presentation → Application. Mnemonic: "Please Do Not Throw Sausage Pizza Away."
Failure Detection: Handshaking Protocol (I-am-up / Are-you-up). Cannot determine type of failure.
Design Issues: 10 issues including Transparency (5 types: Location, Migration, Replication, Concurrency, Parallelism).

2-Mark Questions

Q1.Differentiate between striping and mirroring in RAID.
A: Striping (RAID 0) splits data across multiple disks for speed but has zero fault tolerance — any disk failure means data loss. Mirroring (RAID 1) duplicates all data on 2+ disks for 100% fault tolerance but wastes 50% of storage capacity.
Q2.What is an Access Matrix? How does it separate mechanism from policy?
A: Access Matrix is a 2D table where rows = domains, columns = objects, cells = allowed operations. Mechanism: OS provides the matrix infrastructure and strictly enforces rules. Policy: Users/administrators dictate who can access what. Thus OS doesn't decide policy — it only enforces it.
Q3.What are the 5 categories of security violations? Give one example each.
A: (1) Breach of Confidentiality — unauthorized reading (hacker reads your email); (2) Breach of Integrity — unauthorized modification (changing bank balance); (3) Breach of Availability — destruction of data (ransomware); (4) Theft of Service — unauthorized resource use (crypto mining on your computer); (5) Denial of Service — preventing legitimate use (DDoS attack on a website).
Q4.Differentiate between Symmetric and Asymmetric Encryption.
A: Symmetric: Same key encrypts and decrypts. Very fast but key distribution is a challenge. Examples: DES, AES. Asymmetric: Public key encrypts, private key decrypts (or vice versa for signatures). Slower but solves key distribution. Based on prime factoring. Example: RSA. Asymmetric is typically NOT used for bulk data encryption due to its computational cost.

5-Mark Questions

Q1.Explain RAID levels 0, 1, 5, and 6 with their advantages and disadvantages.
RAID 0 (Striping): Data split across all drives. No redundancy. Advantage: maximum speed (all drives read/write in parallel). Disadvantage: any single disk failure = complete data loss. Min 2 disks.

RAID 1 (Mirroring): Data written identically to 2+ drives. Advantage: 100% fault tolerance, fast reads. Disadvantage: 50% storage waste, high cost per MB. Min 2 disks.

RAID 5 (Distributed Parity): Block striping + parity distributed across all drives (no dedicated parity disk). Advantage: best balance of performance, capacity, and fault tolerance. Tolerates 1 disk failure. Disadvantage: write penalty (parity recalculation), performance degrades after failure until rebuild. Min 3 disks.

RAID 6 (Double Distributed Parity): Like RAID 5 but with 2 parity sets. Advantage: tolerates 2 simultaneous disk failures — critical for large arrays with long rebuild times. Disadvantage: higher write penalty, more overhead, min 4 disks.
Q2.Explain the four implementations of the Access Matrix.
1. Global Table: Stores ordered triples <domain, object, rights-set>. To check access, search for <Di, Oj, Rk> where operation M ∈ Rk. Problem: table is large, doesn't fit in main memory; grouping objects is difficult.

2. Access Lists (ACL): Each object has a list of <domain, rights-set> pairs (column-based). Easy to extend with default sets. Used in Unix/Linux file systems. Problem: must scan entire list for each access check.

3. Capability Lists: Each domain has a list of <object, rights> pairs (row-based). Possession = permission. Protected by OS — domains cannot directly access capability lists (secure pointer). Like a key ring. Problem: revoking access is complex — must find all capability lists mentioning the object.

4. Lock-Key: Compromise between ACL and capability lists. Each object has a list of locks (bit patterns); each domain has a list of keys. Access allowed if domain's key matches object's lock. Problem: key/lock management overhead.
Q3.Explain the OSI 7-layer model with each layer's function.
1. Physical Layer: Handles mechanical and electrical details of transmitting a raw bit stream over physical medium (cables, signals, hubs).
2. Data Link Layer: Handles frames (fixed-length parts of packets), error detection and recovery. Provides Point-to-Point delivery using MAC addresses.
3. Network Layer: Routes and addresses packets. Handles source-to-destination delivery across multiple networks using IP addresses.
4. Transport Layer: End-to-end communication. Partitions messages into packets, maintains packet order, controls flow, provides physical addresses. (TCP, UDP)
5. Session Layer: Implements sessions — process-to-process communication protocols and synchronization.
6. Presentation Layer: Resolves format differences: character conversions (ASCII ↔ EBCDIC), encryption, half/full duplex handling.
7. Application Layer: Direct user-facing services: file transfer (FTP), remote login (Telnet), email (SMTP), distributed databases. (HTTP, DNS)

10-Mark Questions

Q1.Write a detailed note on System and Network Threats including program threats, virus categories, worms, and DoS attacks.
Introduction: System security threats come from both within programs (program threats) and from networks. Understanding these threats is essential for designing effective countermeasures.

Program Threats:
• Trojan Horse: Code hidden in legitimate programs that exploits privileges. 80% of spam is delivered via spyware/Trojans.
• Trap Door: Secret password or code path bypassing normal security. Can be introduced at compilation stage. Hard to detect.
• Logic Bomb: Dormant code that activates when specific conditions are met (e.g., date, event, employee name removed).
• Buffer Overflow: Exploits programs that don't check input bounds. Data overflows into the return address on the call stack → attacker's code executes → unauthorized privilege escalation.
• Virus: Self-replicating code embedded in legitimate programs. CPU/OS specific. Spreads via email, macros.

Virus Categories: File/Parasitic, Boot/Memory, Macro, Source Code, Polymorphic, Encrypted, Stealth, Tunneling, Multipartite, Armored. Virus dropper is a program that installs a virus.

Network Threats:
• Worm: Standalone self-replicating program using network spawn mechanisms. No host needed. Morris Worm (1988): 99 lines of C exploiting Unix's rsh, finger, sendmail.
• Port Scanning: Automated tools (nmap, nessus) probe port ranges to find vulnerabilities. Launched from zombie systems.
• DoS (Denial of Service): Overloads target system. SYN flooding exploits TCP handshake — exhausts half-open connection queue. System appears unavailable to legitimate users.
• DDoS (Distributed DoS): DoS from multiple zombie/botnet machines simultaneously. Very difficult to block. Extortion tool, punishment mechanism.
• Keystroke Logger: Records keystrokes to steal passwords/credit cards. Installed by Trojans.
• Botnet: Network of compromised zombie computers used for spam, DDoS, crypto mining.

Why Windows is targeted most: Most widespread OS, users typically run as administrators, monoculture makes coordinated attacks effective.

Security Measure Levels: Security must be implemented at all four levels — Physical, Human, OS, Network — since it is only as strong as the weakest link.

Scenario-Based Questions

S1.A company has 5 critical servers and wants fault tolerance for up to 2 simultaneous disk failures. Which RAID level should they use and why?
A: RAID 6. RAID 6 uses block-level striping with double distributed parity (two sets of parity), which provides fault tolerance for 2 simultaneous disk failures. This is especially important for large-capacity drives that take hours/days to rebuild — during RAID 5 rebuild, a second failure would cause total data loss. RAID 6 gives a safety window for the rebuild period. Minimum 4 disks required.
S2.Alice wants to send a digitally signed message to Bob so Bob can verify Alice sent it and the message wasn't tampered with. Explain the complete process.
A: Alice computes H(m) = hash of the message using SHA-1 (160-bit). She then signs: Signature = H(m)^ks mod N, using her private key ks. She sends the message AND the signature to Bob. Bob computes H(m) of the received message independently. Bob also decrypts the signature: a^kv mod N = H(m)?, using Alice's public key kv. If both H(m) values match → message is authentic and unmodified → Alice cannot deny sending it (non-repudiation).
S3.A process in Domain D2 wants to access File F3 with Write permission. The access matrix shows D2-F3 cell contains only "Read". What happens?
A: The OS checks Access(D2, F3) = {Read}. Since "Write" ∉ {Read}, the access is denied. The OS raises a protection violation/exception. The process does not gain write access. This enforces the protection mechanism — only operations explicitly listed in Access(i,j) are permitted.

Twisted Conceptual Questions

T1.Can RAID 1 be used as a backup strategy? Justify your answer.
A: No, RAID 1 is NOT a backup strategy. RAID 1 protects only against hardware disk failure — it mirrors data in real time. If you accidentally delete a file, it's deleted on both mirrors simultaneously. If ransomware encrypts your data, both drives get encrypted. If a software corruption occurs, both mirrors are corrupted. A true backup is an offline, separate copy of data that is NOT modified when the primary data changes. RAID provides high availability; backup provides disaster recovery.
T2.In the OSI model, why does data travel DOWN the layers at the sender and UP at the receiver? What happens at each layer?
A: At the sender, each layer adds its own header (encapsulation) as data travels down: Application creates data → Transport adds port numbers → Network adds IP addresses → Data Link adds MAC frames → Physical converts to bits. At the receiver, each layer strips its corresponding header (decapsulation) as data travels up, passing the remaining payload to the upper layer. This layered approach means each layer communicates logically with its peer layer on the other side, creating a horizontal abstraction even though physical communication only occurs at the Physical layer (bottom).
T3.Why is asymmetric encryption NOT used for bulk data encryption even though it's more secure?
A: Asymmetric encryption is based on complex mathematical operations (modular exponentiation with large prime numbers) and is computationally intensive — much slower than symmetric encryption. For bulk data (large files, real-time streams), this overhead is unacceptable. In practice, a hybrid approach is used: asymmetric encryption is used only to securely exchange a symmetric session key (small data), and then that symmetric key is used for fast bulk data encryption. This is exactly how HTTPS/TLS works — RSA for key exchange, AES for data encryption.

Viva Questions

V1.What is the difference between a domain and an access right?
An access right is a pair <object-name, rights-set> that specifies what operations can be performed on a specific object. A domain is a set of access rights — it defines the complete set of objects a process can access and how. A process executing in a domain can access all objects listed in that domain's access rights.
V2.What is "salt" in password hashing and why is it used?
Salt is a random value appended to a password before it is hashed. Without salt, if two users have the same password "hello123," they produce identical hashes — an attacker with a precomputed rainbow table can crack many accounts at once. Salt makes each hash unique even for identical passwords, making rainbow table attacks infeasible because the attacker would need a separate table for every possible salt value.
V3.How does the Morris Worm differ from a virus?
The Morris Worm was a standalone program that used network mechanisms (rsh, sendmail, finger) to propagate — no host program needed. A virus is a code fragment embedded in a legitimate program that needs that host to replicate. The worm spread autonomously across the network, while viruses spread through file sharing. The Morris Worm had special logic: it would abort if a target system was already infected, except every 7th infection attempt — to ensure spread wasn't blocked by fake "already infected" defenses.
