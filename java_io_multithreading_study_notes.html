1. Java IO & Streams — Introduction

Definition: A stream in Java is an abstraction that either produces or consumes information. It is linked to a physical device by the Java I/O system. All streams behave in the same manner regardless of the actual physical device they are connected to.

Java performs all I/O through streams. The java.io package contains all stream classes. A stream is a group of objects providing methods that can be piped together to get the desired outcome.

Types of Streams

Byte Streams handle input/output of raw bytes — used for binary data (images, audio). Base classes: InputStream, OutputStream.

Character Streams handle input/output of characters using Unicode — suitable for text and internationalization. Base classes: Reader, Writer.

2. FileOutputStream

Definition: FileOutputStream is a byte output stream used for writing data to a file. It extends OutputStream and is used to write primitive values or byte-oriented data into a file.
public class FileOutputStream extends OutputStream

Key Methods

MethodDescription

Example — Write a Single Byte

import java.io.FileOutputStream;
public class FileOutputStreamExample {
    public static void main(String args[]) {
        try {
            FileOutputStream fout = new FileOutputStream("D:\\testout.txt");
            fout.write(65);   // writes ASCII 65 = 'A'
            fout.close();
            System.out.println("success...");
        } catch(Exception e) { System.out.println(e); }
    }
}
// Output: success...
// File testout.txt contains: A
ASCII value 65 corresponds to the character 'A'. FileOutputStream writes raw bytes, so calling fout.write(65) stores 'A' in the file.

import java.io.*;
class ByteArrayOutputStreamDemo {
    public static void main(String args[]) throws IOException {
        ByteArrayOutputStream f = new ByteArrayOutputStream();
        String s = "This should end up in the array";
        byte buf[] = s.getBytes();
        f.write(buf);
        System.out.println(f.toString());       // prints as string
        byte b[] = f.toByteArray();             // convert to byte array
        for(int i=0; i<b.length; i++)
            System.out.print((char)b[i]);
        f.reset();                              // reset buffer
        for(int i=0; i<3; i++) f.write('X');
        System.out.println(f.toString());       // prints: XXX
    }
}

9. Object Serialization & Deserialization

Serialization: The process of saving an object's state to a sequence of bytes (typically to disk). The Java Serialization API provides a standard mechanism. Only objects of classes implementing the Serializable interface can be serialized.
Deserialization: The process of reconstructing a serialized object from bytes back into a live object in memory. Serialization is JVM-independent — an object serialized on one platform can be deserialized on an entirely different platform.

Classes Used

ObjectOutputStream — for serialization  |  ObjectInputStream — for deserialization

Writing to ObjectOutputStream

FileOutputStream out = new FileOutputStream("theTime");
ObjectOutputStream s = new ObjectOutputStream(out);
s.writeObject("Today");
s.writeObject(new Date());
s.flush();

Reading from ObjectInputStream

FileInputStream in = new FileInputStream("theTime");
ObjectInputStream s = new ObjectInputStream(in);
String today = (String) s.readObject();
Date date = (Date) s.readObject();

Complete Serialization Example

import java.io.*;
public class MyClass implements Serializable {
    String s; int i; double d;
    public MyClass(String s, int i, double d) {
        this.s = s; this.i = i; this.d = d;
    }
    public String toString() { return "s=" + s + "; i=" + i + "; d=" + d; }
}

// Serialization
MyClass object1 = new MyClass("Hello", -7, 2.7e10);
FileOutputStream fos = new FileOutputStream("serial");
ObjectOutputStream oos = new ObjectOutputStream(fos);
oos.writeObject(object1);
oos.flush(); oos.close();

// Deserialization
FileInputStream fis = new FileInputStream("serial");
ObjectInputStream ois = new ObjectInputStream(fis);
MyClass object2 = (MyClass) ois.readObject();
ois.close();
System.out.println("object2: " + object2);

The transient Keyword

transient — marks a field to be excluded from serialization. When a transient field is deserialized, it gets the default value (null for objects, 0 for numbers, false for boolean). Static variables are also NOT serialized by default. Only used with variable declarations.
class Example implements Serializable {
    String name;           // will be serialized
    transient int password; // will NOT be serialized — value lost
    static int count;      // static — also not serialized
}

11. Java Piped I/O

Definition: Pipes are used as a communication channel between threads to transfer data in a producer-consumer scenario. They provide a unidirectional flow of data — one thread writes to the pipe, another thread reads from it.

Piped Classes

ClassTypePurpose
PipedInputStreamByte-basedReads from the pipe as bytes
PipedOutputStreamByte-basedWrites to the pipe as bytes
PipedReaderCharacter-basedReads from the pipe as characters
PipedWriterCharacter-basedWrites to the pipe as characters

PipedWriter

Used to write text into a pipe as a stream of characters. Must be connected to a PipedReader. Used by the Producer thread. PipedWriter is a subclass of Writer.

PipedReader

Used to read the contents of a pipe as a stream of characters. Must be connected to the same PipedWriter. Used by the Consumer thread.

Example — Producer-Consumer with Pipes

import java.io.PipedReader;
import java.io.PipedWriter;

public class PipeReaderExample {
    public static void main(String[] args) {
        try {
            final PipedReader read = new PipedReader();
            final PipedWriter write = new PipedWriter(read); // connected!

            Thread readerThread = new Thread(new Runnable() {
                public void run() {
                    try {
                        int data = read.read();
                        while(data != -1) {
                            System.out.print((char) data);
                            data = read.read();
                        }
                    } catch(Exception ex) {}
                }
            });

            Thread writerThread = new Thread(new Runnable() {
                public void run() {
                    try {
                        write.write("My name is BHAVNEET\n".toCharArray());
                    } catch(Exception ex) {}
                }
            });

            readerThread.start();
            writerThread.start();
        } catch(Exception ex) {
            System.out.println(ex.getMessage());
        }
    }
}
The write(int) method of PipedWriter throws an IOException if the pipe is broken or the connected PipedReader is closed.

12. Multithreading

Definition: Multithreading is a Java feature that enables two or more parts (threads) of the same process to run concurrently for optimal CPU utilization. Each thread is a lightweight process within a process.

Multitasking vs. Multithreading

FeatureMultitaskingMultithreading
UnitProcess (separate programs)Thread (part of same process)
MemoryEach process has its own memoryThreads share same memory/heap
CommunicationInter-process (costly)Intra-process (cheaper)
Context SwitchHeavyweight — slowerLightweight — faster
ExampleRunning Word + Chrome simultaneouslyTyping + spell-check in Word

Thread Life Cycle

New
→
Runnable
→
Running
→
Waiting / Timed Waiting
→
Terminated
  • New: Thread is created using new Thread(); not yet started
  • Runnable: After start() is called; thread is ready to execute
  • Running: Thread scheduler has assigned CPU to this thread
  • Waiting: Thread waits for another thread to signal it (e.g., wait(), join())
  • Timed Waiting: Thread waits for a specified time interval (e.g., sleep(ms))
  • Terminated (Dead): Thread completes its run() method or is stopped

Advantages of Multithreading

  • Improved performance and concurrency (multiple tasks simultaneously)
  • Simplified coding of remote procedure calls and conversations
  • Simultaneous access to multiple applications
  • Reduced number of required servers

Disadvantages of Multithreading

  • Difficulty of writing code — complex logic required
  • Difficulty of debugging — race conditions are hard to reproduce
  • Difficulty of managing concurrency — deadlocks, starvation
  • Difficulty of testing — non-deterministic behavior
  • Difficulty of porting existing single-threaded code

Method 1 — Extending Thread Class

class Multi extends Thread {
    public void run() {
        System.out.println("thread is running...");
    }
    public static void main(String args[]) {
        Multi t1 = new Multi();
        t1.start();   // DO NOT call run() directly
    }
}
// Output: thread is running...

Method 2 — Implementing Runnable Interface

class Multi3 implements Runnable {
    public void run() {
        System.out.println("thread is running...");
    }
    public static void main(String args[]) {
        Multi3 m1 = new Multi3();
        Thread t1 = new Thread(m1);  // wrap in Thread object
        t1.start();
    }
}
// Output: thread is running...
Runnable Interface: Contains only a single method — public void run(). When start() is called: (1) a new thread starts with a new call stack, (2) thread moves from New to Runnable state, (3) when scheduled, its run() method executes.
Key rule: Always call start(), never run() directly. Calling run() directly executes it in the current thread without creating a new thread.

14. Thread Synchronization

Definition: Synchronization is the process of controlling access to shared resources among multiple threads so that only one thread can access a shared resource at a given point in time. Key concept: the monitor (also called a semaphore).

Why Synchronization?

Without synchronization, multiple threads accessing/modifying the same data simultaneously can produce inconsistent results (race conditions). Every object in Java has a lock associated with it.

Types of Synchronization

TypeDescription
Synchronized MethodThe entire method is locked — only one thread can execute it at a time
Synchronized BlockOnly a specific block of code is locked — more granular control
Static SynchronizationLock is on the Class object, not on an instance
Inter-thread Communicationwait(), notify(), notifyAll() for cooperation between threads

1. Synchronized Method

When a thread invokes a synchronized method, it automatically acquires the lock for that object and releases it when the method completes.
class Table {
    synchronized void printTable(int n) {  // lock on 'this' object
        for(int i=1; i<=5; i++) {
            System.out.println(n * i);
            try { Thread.sleep(400); } catch(Exception e) {}
        }
    }
}
// Two threads sharing same Table object — output will be sequential, not interleaved

2. Synchronized Block

Used to synchronize only a portion of a method. Smaller scope than a synchronized method. Syntax: synchronized(object) { /* code */ }
class Table {
    void printTable(int n) {
        synchronized(this) {    // synchronized block — lock only this portion
            for(int i=1; i<=5; i++) {
                System.out.println(n * i);
                try { Thread.sleep(400); } catch(Exception e) {}
            }
        }
    }
}
// Usage:
Table obj = new Table();
MyThread1 t1 = new MyThread1(obj);
MyThread2 t2 = new MyThread2(obj);
t1.start(); t2.start();
// Output: 5, 10, 15, 20, 25, 100, 200, 300, 400, 500 (sequential)

3. Static Synchronization

When a static method is declared synchronized, the lock is on the Class object, not on any instance. This prevents interference between threads accessing the same class-level resource through different object instances.
class Display {
    public static synchronized void displayMessage(String message) {
        for(int i=0; i<5; i++) {
            System.out.println(message);
            try { Thread.sleep(500); } catch(InterruptedException e) {}
        }
    }
}
class MyThread extends Thread {
    String message;
    MyThread(String message) { this.message = message; }
    public void run() { Display.displayMessage(message); }
}
public class StaticSyncExample {
    public static void main(String[] args) {
        MyThread t1 = new MyThread("Hello");
        MyThread t2 = new MyThread("World");
        t1.start(); t2.start();
        // Only one thread executes at a time — class-level lock
    }
}

Why Static Synchronization is Needed

Without static synchronization: if two objects (obj1, obj2) of same class both have threads t1/t2 and t3/t4 — t1 and t3 can run simultaneously because they have different object-level locks. Static synchronization solves this by locking the entire class.

Concept of Lock/Monitor

  • Every Java object has an internal lock (monitor) associated with it
  • A thread must acquire the object's lock before accessing its synchronized fields
  • Only one thread at a time may hold a lock on a monitor
  • The lock is automatically released when the synchronized method/block exits
  • The synchronized keyword is used to acquire locks

15. Question & Answer Bank

Easy — 2 Marks (3–4 lines)

Q1 — Easy · 2 Marks
What is a stream in Java?
A stream in Java is an abstraction that either produces or consumes information. It is linked to a physical device by the Java I/O system. All streams behave the same way regardless of the device they are linked to. Java streams are defined in the java.io package.
Q2 — Easy · 2 Marks
What are the two types of streams in Java?
Java defines two types of streams: (1) Byte Streams — handle input/output of raw bytes, used for binary data; base classes are InputStream and OutputStream. (2) Character Streams — handle character I/O using Unicode, efficient for text; base classes are Reader and Writer.
Q3 — Easy · 2 Marks
What are the three predefined streams in Java?
System.in — standard input stream, default is keyboard. System.out — standard output stream, default is console. System.err — standard error stream, default is console. All three are defined in the System class of java.lang package.
Q4 — Easy · 2 Marks
What is a thread in Java?
A thread is a lightweight process inside a process. In Java, the Thread class (in java.lang) represents a thread of execution. Threads share the memory of the parent process. Java's multithreading enables two or more parts of the same program to run concurrently for optimal CPU utilization.
Q5 — Easy · 2 Marks
What is the purpose of the transient keyword?
The transient keyword is used in object serialization to exclude a non-static field from being serialized. When a transient field is deserialized, it gets its default value (null/0/false). Only used with variable declarations. Static variables are also excluded from serialization by default.
Q6 — Easy · 2 Marks
What keyword is used to acquire a lock on an object in Java?
The synchronized keyword is used in Java to acquire a lock on an object. When applied to a method or block, it ensures that only one thread at a time can execute that code. Volatile, locked, etc. are not valid keywords for this purpose.
Q7 — Easy · 2 Marks
List the states in the life cycle of a Java thread.
A Java thread has 5 states: (1) New — thread created, not started. (2) Runnable — after start() is called. (3) Waiting/Timed Waiting — thread paused waiting for signal or timeout. (4) Blocked — waiting to acquire a lock. (5) Terminated — thread has finished execution.
Q8 — Easy · 2 Marks
What is the difference between FileWriter and FileOutputStream?
FileWriter is a character stream (extends Writer) used to write text/characters to a file using Unicode. FileOutputStream is a byte stream (extends OutputStream) used to write raw bytes to a file. FileWriter is preferred for text files; FileOutputStream for binary files like images.
Q9 — Easy · 2 Marks
What interface must a class implement to be serializable?
A class must implement the Serializable interface (in java.io) to be serializable. This is a marker interface with no methods. Classes ObjectInputStream and ObjectOutputStream are used for the actual serialization and deserialization process.
Q10 — Easy · 2 Marks
What are Piped streams used for in Java?
Piped streams are used as a communication channel between threads in a producer-consumer scenario. They provide unidirectional data flow — one thread writes to PipedWriter/PipedOutputStream, and another thread reads from PipedReader/PipedInputStream. Useful for inter-thread communication.

Medium — 5 Marks (10–15 lines)

Q11 — Medium · 5 Marks
Explain the concept of Serialization and Deserialization in Java with a code example.

Serialization is the process of converting an object's state into a byte stream to save it to a file or transmit over a network. Deserialization is the reverse — reconstructing the object from the byte stream. The process is JVM-independent, meaning an object serialized on one platform can be deserialized on another.

To serialize a class, it must implement java.io.Serializable (a marker interface). ObjectOutputStream is used to write the object; ObjectInputStream is used to read it back. Fields marked transient are excluded from serialization.

// Class to be serialized
public class MyClass implements Serializable {
    String s; int i;
    public MyClass(String s, int i) { this.s=s; this.i=i; }
}
// Serialize
FileOutputStream fos = new FileOutputStream("data.ser");
ObjectOutputStream oos = new ObjectOutputStream(fos);
oos.writeObject(new MyClass("Hello", 42));
oos.close();
// Deserialize
FileInputStream fis = new FileInputStream("data.ser");
ObjectInputStream ois = new ObjectInputStream(fis);
MyClass obj = (MyClass) ois.readObject();
ois.close();
Q12 — Medium · 5 Marks
Explain the two ways to create a thread in Java with examples.

Method 1: Extending Thread class — Create a class that extends Thread and override the run() method. Create an object and call start().

class MyThread extends Thread {
    public void run() { System.out.println("Thread running"); }
}
MyThread t = new MyThread();
t.start();

Method 2: Implementing Runnable interface — Create a class implementing Runnable, define run(), wrap it in a Thread object, then call start(). This approach is preferred because Java allows only single inheritance — using Runnable lets the class extend another class.

class MyRunnable implements Runnable {
    public void run() { System.out.println("Thread running"); }
}
Thread t = new Thread(new MyRunnable());
t.start();

In both cases, never call run() directly — that executes in the current thread, not a new one. Always use start() which creates a new call stack.

Q13 — Medium · 5 Marks
Explain synchronized method vs synchronized block in Java with examples.

Synchronized Method: The entire method body is locked. When a thread invokes a synchronized method, it acquires the lock on the object and no other thread can invoke any synchronized method on the same object until the lock is released.

synchronized void printTable(int n) {
    for(int i=1; i<=5; i++) System.out.println(n*i);
}

Synchronized Block: Only a portion of the method is locked. This is more efficient when only part of the method accesses shared resources. The scope is smaller, so threads wait less. The object reference is explicitly specified.

void printTable(int n) {
    // non-synchronized code here (runs freely)
    synchronized(this) {
        // only this part is locked
        for(int i=1; i<=5; i++) System.out.println(n*i);
    }
}

Key difference: synchronized method locks the entire method (coarse-grained); synchronized block locks only the critical section (fine-grained), giving better performance when only part of the method uses shared resources.

Q16 — Medium · 5 Marks
Describe the complete life cycle of a thread in Java.

A Java thread goes through the following states during its lifetime:

1. New: Thread is created with new Thread() but not yet started. Memory allocated, but execution not begun.

2. Runnable: After start() is called. Thread is ready and waiting for CPU time from the thread scheduler. May or may not be currently executing.

3. Running: Thread scheduler has given CPU time to this thread; run() method is executing.

4. Waiting: Thread is waiting for another thread to notify it. Entered via wait(), join() (without timeout). Returns to Runnable when notified.

5. Timed Waiting: Thread waits for a specified time. Entered via sleep(ms), join(ms), wait(ms). Returns to Runnable after timeout or signal.

6. Terminated (Dead): Thread has completed its run() method normally, or was stopped. A terminated thread cannot be restarted.

Key transitions: New→Runnable via start(); Runnable→Waiting via wait()/join(); any→Terminated via completion or exception.

Q18 — Medium · 5 Marks
Explain static synchronization in Java and why it is needed.

Static synchronization means applying the synchronized keyword to a static method. In this case, the lock is acquired on the Class object (not an instance), meaning the entire class is locked for that thread.

Why needed: In regular (instance-level) synchronization, threads operating on different objects of the same class can run simultaneously — each object has its own lock. If two threads t1 and t3 each operate on different objects (obj1, obj2), they won't block each other even with synchronized methods.

Static synchronization solves this: all threads, regardless of which instance they use, must share the same class-level lock. This prevents interference between t1 (on obj1) and t3 (on obj2).

class Display {
    public static synchronized void displayMessage(String msg) {
        for(int i=0; i<5; i++) {
            System.out.println(msg);
            try { Thread.sleep(500); } catch(InterruptedException e) {}
        }
    }
}
// t1 and t2 both call Display.displayMessage()
// Only ONE thread executes at a time — class-level lock

  • PipedOutputStream + PipedInputStream: byte-based piped I/O
  • PipedWriter + PipedReader: character-based piped I/O

A PipedWriter must be connected to a PipedReader (or PipedOutputStream to PipedInputStream). The connection is made either in the constructor or via the connect() method. write(int) of PipedWriter throws IOException if the pipe is broken.

final PipedReader reader = new PipedReader();

// Producer thread
new Thread(() -> {
    try { writer.write("Data from producer".toCharArray()); }
    catch(Exception e) {}
}).start();

// Consumer thread
new Thread(() -> {
    try {
        int c;
        while((c = reader.read()) != -1) System.out.print((char)c);
    } catch(Exception e) {}
}).start();

Q21 — Hard · Scenario-Based
Scenario: A bank application has multiple teller threads all accessing and updating the same account balance. Without synchronization, what problems arise? Write a complete synchronized solution using Java threads that demonstrates the problem and its fix.

Problem Analysis — Race Condition:

When multiple threads read, modify, and write the same shared variable simultaneously without synchronization, they produce inconsistent results. This is called a race condition. For a bank account, Thread 1 (Teller A) and Thread 2 (Teller B) both read balance=1000, both withdraw 500, and both write balance=500 — but the correct balance should be 0. The update from one thread gets "lost."

This happens because the operation balance -= amount is not atomic — it involves: (1) read balance, (2) subtract amount, (3) write new balance. Context switch between steps causes corruption.

Step 1 — Demonstrating the Problem (No Sync):

class BankAccount {
    int balance = 1000;
    void withdraw(int amount) {     // NOT synchronized
        if(balance >= amount) {
            try { Thread.sleep(100); } catch(Exception e) {}
            balance -= amount;
            System.out.println("Withdrawn: " + amount + " | Balance: " + balance);
        } else {
            System.out.println("Insufficient funds! Balance: " + balance);
        }
    }
}
class Teller extends Thread {
    BankAccount account; int amount;
    Teller(BankAccount acc, int amt) { account = acc; amount = amt; }
    public void run() { account.withdraw(amount); }
}
public class BankTest {
    public static void main(String[] args) {
        BankAccount acc = new BankAccount();
        Teller t1 = new Teller(acc, 700);
        Teller t2 = new Teller(acc, 700);
        t1.start(); t2.start();
        // PROBLEM: Both threads may read balance=1000, both see it's enough,
        // both withdraw 700, final balance = -400 (WRONG!)
    }
}

Step 2 — Fixed Solution with Synchronized Method:

class BankAccount {
    private int balance = 1000;
    synchronized void withdraw(int amount) {  // only ONE thread at a time
        System.out.println(Thread.currentThread().getName() 
                           + " attempting to withdraw: " + amount);
        if(balance >= amount) {
            try { Thread.sleep(100); } catch(Exception e) {}
            balance -= amount;
            System.out.println(Thread.currentThread().getName() 
                + " Success! Withdrawn: " + amount 
                + " | Remaining Balance: " + balance);
        } else {
            System.out.println(Thread.currentThread().getName() 
                + " Insufficient funds! Balance: " + balance);
        }
    }
    int getBalance() { return balance; }
}
class Teller extends Thread {
    BankAccount account; int amount;
    Teller(BankAccount acc, int amt, String name) {
        super(name); account = acc; amount = amt;
    }
    public void run() { account.withdraw(amount); }
}
public class SafeBankTest {
    public static void main(String[] args) throws InterruptedException {
        BankAccount acc = new BankAccount();
        Teller t1 = new Teller(acc, 700, "Teller-A");
        Teller t2 = new Teller(acc, 700, "Teller-B");
        t1.start(); t2.start();
        t1.join(); t2.join();
        System.out.println("Final Balance: " + acc.getBalance());
        // Teller-A gets lock first → withdraws 700 → balance=300
        // Teller-B gets lock → balance=300 < 700 → Insufficient funds
        // Final Balance: 300 ✓ CORRECT
    }
}

Key Concepts Demonstrated:

  • Race condition: threads reading stale values before another thread writes its update
  • synchronized on the method acquires the object-level monitor lock
  • Only one thread executes the critical section at a time
  • join() ensures main thread waits for both tellers to finish
  • Thread.sleep() in the unsynchronized version exaggerates the race window, making the bug visible
  • The synchronized version ensures consistency even under concurrent access
Q22 — Hard · Scenario-Based
Scenario: You need to save a Student object (name, rollNo, CGPA, password) to a file and retrieve it later. The password must NOT be saved. Write the complete serialization and deserialization code and explain how transient helps.

Design Analysis:

Object serialization converts an object's state to bytes for persistent storage or network transmission. The Serializable marker interface enables this. The transient keyword protects sensitive fields (like passwords) from being serialized. When deserialized, transient fields receive their default values (null for String).

import java.io.*;

// Student class — Serializable but password is transient
class Student implements Serializable {
    private static final long serialVersionUID = 1L;
    String name;
    int rollNo;
    double cgpa;
    transient String password;  // WILL NOT be serialized (security!)

    public Student(String name, int rollNo, double cgpa, String password) {
        this.name = name;
        this.rollNo = rollNo;
        this.cgpa = cgpa;
        this.password = password;
    }
    public String toString() {
        return "Name: " + name + " | Roll: " + rollNo 
             + " | CGPA: " + cgpa + " | Password: " + password;
    }
}

public class StudentSerializationDemo {
    public static void main(String[] args) {
        Student s1 = new Student("Ravi Kumar", 101, 8.75, "secure@123");
        System.out.println("Before Serialization: " + s1);
        // Output: Name: Ravi Kumar | Roll: 101 | CGPA: 8.75 | Password: secure@123

        // SERIALIZATION — save to file
        try {
            FileOutputStream fos = new FileOutputStream("student.ser");
            ObjectOutputStream oos = new ObjectOutputStream(fos);
            oos.writeObject(s1);     // serialize
            oos.flush();
            oos.close();
            fos.close();
            System.out.println("Object serialized successfully to student.ser");
        } catch(IOException e) {
            System.out.println("Serialization error: " + e.getMessage());
        }

        // DESERIALIZATION — recover from file
        try {
            FileInputStream fis = new FileInputStream("student.ser");
            ObjectInputStream ois = new ObjectInputStream(fis);
            Student s2 = (Student) ois.readObject();  // deserialize + cast
            ois.close();
            fis.close();
            System.out.println("After Deserialization: " + s2);
            // Output: Name: Ravi Kumar | Roll: 101 | CGPA: 8.75 | Password: null
            // Password is NULL — transient field not saved!
        } catch(Exception e) {
            System.out.println("Deserialization error: " + e.getMessage());
        }
    }
}

Explanation of transient behavior: The transient keyword tells the JVM to skip the password field during serialization. When deserialized, the field gets its default value (null for String). This is critical for security-sensitive data — you never want passwords stored in plain bytes on disk.

serialVersionUID: This is a version control field for serialization. If the class changes (new fields added), the serialVersionUID ensures that incompatible versions are detected, preventing incorrect deserialization.

This pattern is widely used in enterprise applications for saving session data, caching, and network communication via Remote Method Invocation (RMI).

Q24 — Hard · Theory + Code
Explain in detail the concept of monitors/locks in Java. What is the difference between object-level locking and class-level locking? Write programs demonstrating both, and explain what happens to threads waiting for a lock.

Monitor / Lock Concept:

Every Java object has an internal entity called a monitor (also called an intrinsic lock or mutex). When a thread executes a synchronized method or block, it automatically acquires the monitor of the relevant object. Only one thread can hold a monitor at a time — all other threads attempting to acquire the same monitor are placed in a blocked state and wait in a queue. When the holding thread releases the monitor (exits the synchronized section), one waiting thread is unblocked and acquires the lock.

Object-Level Locking (Instance Lock): Lock on a specific object instance. Two threads on different objects → no blocking.

class Counter {
    int count = 0;
    synchronized void increment() {  // lock on 'this' instance
        count++;
    }
}
// Counter c1 = new Counter(); Counter c2 = new Counter();
// Thread on c1 and thread on c2 run SIMULTANEOUSLY (different locks!)
// Thread on c1 and another thread on c1 are SERIALIZED (same lock)

Class-Level Locking (Static Lock): Lock on the Class object — shared across ALL instances.

class Counter {
    static int count = 0;
    public static synchronized void increment() {  // lock on Counter.class
        count++;
    }
}
// Even threads on c1 and c2 are SERIALIZED — both share Class lock
// More restrictive but prevents class-wide race conditions

When a thread waits for a lock:

  • Thread moves from Runnable → Blocked state
  • It is placed in the monitor's entry set (wait queue)
  • CPU is not given to blocked threads
  • When the holding thread exits synchronized section, JVM picks one thread from the entry set
  • That thread moves from Blocked → Runnable → eventually Running
  • There is no guaranteed order (not FIFO) unless using fair locks from java.util.concurrent

Complete demonstration:

class SharedPrinter {
    // Object-level: different instances won't block each other
    synchronized void printInstance(String msg) {
        System.out.println(Thread.currentThread().getName() + " | Instance: " + msg);
        try { Thread.sleep(300); } catch(Exception e) {}
    }
    // Class-level: ALL threads on any instance block each other
    static synchronized void printClass(String msg) {
        System.out.println(Thread.currentThread().getName() + " | Class: " + msg);
        try { Thread.sleep(300); } catch(Exception e) {}
    }
}
public class LockDemo {
    public static void main(String[] args) {
        SharedPrinter p1 = new SharedPrinter();
        SharedPrinter p2 = new SharedPrinter();
        // These two run concurrently (different object locks)
        new Thread(() -> p1.printInstance("Hello"), "T1").start();
        new Thread(() -> p2.printInstance("World"), "T2").start();
        // These two are serialized (same class lock)
        new Thread(() -> SharedPrinter.printClass("One"), "T3").start();
        new Thread(() -> SharedPrinter.printClass("Two"), "T4").start();
    }
}
Q25 — Hard · Scenario-Based
Scenario: Design and implement a multi-threaded log writer application where multiple threads write log messages to a shared ByteArrayOutputStream. Without synchronization, logs get corrupted. Design: Multiple Logger threads concurrently append messages to a shared buffer. Without synchronization, outputs interleave and produce garbled logs. With synchronization, each log entry is written atomically.

import java.io.*;
import java.util.Date;

class ThreadSafeLogger {
    private ByteArrayOutputStream buffer = new ByteArrayOutputStream();
    
    // Synchronized to prevent interleaving from multiple threads
    synchronized void log(String message) {
        String entry = "[" + Thread.currentThread().getName() + "] "
                     + new Date() + " | " + message + "\n";
        buffer.write(entry.getBytes(), 0, entry.getBytes().length);
    }
    
    // Save accumulated log to a file
    void saveToFile(String filename) throws IOException {
        FileOutputStream fos = new FileOutputStream(filename);
        buffer.writeTo(fos);  // write entire buffer to file
        fos.close();
        System.out.println("Log saved to " + filename);
    }
    
    String getLog() { return buffer.toString(); }
}

class LoggerThread extends Thread {
    ThreadSafeLogger logger;
    String[] messages;
    
    LoggerThread(ThreadSafeLogger logger, String[] messages, String name) {
        super(name);
        this.logger = logger;
        this.messages = messages;
    }
    
    public void run() {
        for(String msg : messages) {
            logger.log(msg);
            try { Thread.sleep(50); } catch(InterruptedException e) {}
        }
    }
}

public class LogApp {
    public static void main(String[] args) throws Exception {
        ThreadSafeLogger logger = new ThreadSafeLogger();
        
        LoggerThread t1 = new LoggerThread(logger, 
            new String[]{"User logged in", "Profile loaded", "Dashboard accessed"},
            "UserService");
        LoggerThread t2 = new LoggerThread(logger,
            new String[]{"DB query executed", "Cache miss", "DB connection closed"},
            "DBService");
        LoggerThread t3 = new LoggerThread(logger,
            new String[]{"Payment initiated", "Gateway response received", "Payment successful"},
            "PaymentService");
        
        t1.start(); t2.start(); t3.start();
        t1.join(); t2.join(); t3.join(); // wait for all threads
        
        System.out.println("=== Final Log ===");
        System.out.println(logger.getLog());
        logger.saveToFile("application.log");
    }
}

What happens without synchronized: Thread 1 starts writing "[UserService]..." and gets interrupted mid-write. Thread 2 writes its message, then Thread 1 resumes. The log file contains: "[User[DB query] logged in" — corrupted.

Q28 — Medium · 5 Marks
What are advantages and disadvantages of multithreading? Give a scenario where multithreading is essential.

Advantages: Improved performance — multiple tasks run in parallel, using CPU efficiently. Better responsiveness — UI thread remains active while background threads process data. Resource sharing — threads share memory, reducing overhead. Simpler design for concurrent problems (servers, producers-consumers).

Disadvantages: Difficult to write, debug, and test — race conditions are non-deterministic. Synchronization bugs (deadlocks, livelocks, starvation) are hard to detect. Increased complexity in code design and maintenance. Porting single-threaded code to multithreaded is difficult.

Multithreading allows all requests to proceed concurrently on a single server process.

Q29 — Medium · 5 Marks
An abstract class Test implements Runnable but doesn't implement run(). Will it compile? Explain with theory.

Yes, it will compile. Here is why:

public abstract class Test implements Runnable {

Q30 — Hard · Comprehensive
Write a complete Java program that reads a text file using FileReader + BufferedReader, processes each line (converts to uppercase), writes the result to another file using FileWriter, and uses two threads — one for reading and one for writing — communicating via PipedWriter/PipedReader. Explain every step.

Design: Reader Thread reads lines from file → writes to PipedWriter → Consumer Thread reads from PipedReader → processes (uppercase) → writes to output file. This demonstrates piped I/O for inter-thread communication, character streams, and multithreading together.

import java.io.*;

public class FileProcessingApp {
    public static void main(String[] args) throws IOException {
        // Create pipe connection between threads
        final PipedWriter pw = new PipedWriter();
        final PipedReader pr = new PipedReader(pw); // connected!

        // Thread 1: PRODUCER — reads from file, writes to pipe
        Thread producer = new Thread(new Runnable() {
            public void run() {
                try {
                    FileReader fr = new FileReader("input.txt");
                    BufferedReader br = new BufferedReader(fr);
                    String line;
                    while((line = br.readLine()) != null) {
                        pw.write(line + "\n");  // write line to pipe
                        pw.flush();
                        Thread.sleep(100); // simulate processing delay
                    }
                    br.close(); fr.close();
                    pw.close(); // signal end of data
                    System.out.println("Producer: Finished reading input.txt");
                } catch(Exception e) {
                    System.out.println("Producer error: " + e.getMessage());
                }
            }
        }, "ProducerThread");

        // Thread 2: CONSUMER — reads from pipe, processes, writes to file
        Thread consumer = new Thread(new Runnable() {
            public void run() {
                try {
                    BufferedReader pipeReader = new BufferedReader(pr);
                    FileWriter fw = new FileWriter("output.txt");
                    BufferedWriter bw = new BufferedWriter(fw);
                    String line;
                    while((line = pipeReader.readLine()) != null) {
                        String processed = line.toUpperCase(); // transform
                        bw.write(processed);
                        bw.newLine();
                        System.out.println("Consumer wrote: " + processed);
                    }
                    bw.close(); fw.close(); pipeReader.close();
                    System.out.println("Consumer: Finished writing output.txt");
                } catch(Exception e) {
                    System.out.println("Consumer error: " + e.getMessage());
                }
            }
        }, "ConsumerThread");

        consumer.start(); // start consumer first (it blocks waiting for data)
        producer.start(); // producer starts generating data
        
        try { producer.join(); consumer.join(); } // wait for both
        catch(InterruptedException e) {}
        
        System.out.println("Processing complete!");
    }
}

Step-by-step explanation:

  • PipedWriter pw / PipedReader pr: Connected in constructor — form the communication channel. Data written to pw appears at pr.
  • Producer thread: Reads input.txt line by line using BufferedReader (efficient — reads whole lines). Writes each line to the pipe with pw.write(). Closes pw when done — this sends EOF signal to consumer.
  • Consumer thread: Wraps PipedReader in BufferedReader for line reading. Reads each line (readLine() returns null when pipe is closed = EOF). Converts to uppercase and writes to output.txt.
  • Thread coordination: Consumer starts first so it's ready before producer. join() ensures main thread waits for completion. PipedWriter.close() signals EOF to PipedReader.
  • Error handling: Each thread handles its own exceptions independently.
