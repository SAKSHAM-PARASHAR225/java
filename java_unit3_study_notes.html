Applets

Definition An Applet is a special type of Java program that is embedded in a webpage to generate dynamic content. It runs inside the browser (client-side) and extends the java.applet.Applet class.

  • Cross-platform: Linux, Windows, macOS
  • No installation needed on client
⚠️ Limitations
  • Requires a browser with Java plugin
  • Deprecated in modern Java (removed in Java 11)

JDBC — Definition Java Database Connectivity (JDBC) is a Java API that enables Java programs to interact with relational databases. It provides a standard set of classes and interfaces to connect, query, and update databases from Java code.

JDBC Driver Types

TypeNameDescriptionExample
Type 1 JDBC-ODBC Bridge Translates JDBC calls to ODBC. Requires ODBC setup on every client. Development only. JdbcOdbcDriver (JDK 1.2)
Type 2 Native-API Driver Converts JDBC calls to native client library (e.g., Oracle OCI). Binaries required on client. Oracle OCI Driver
Type 3 JDBC-Net Driver Three-tier approach. Uses middleware server. Most flexible; no client installation needed. IDS Driver
Type 4 100% Pure Java Driver Directly converts JDBC to native DB protocol. No installation on client (except JVM). Best for production. MySQL Connector/J
💡 Driver Selection Guide
  • Single DB (Oracle/MySQL) → Use Type 4 (best performance)
  • Multiple DBs simultaneously → Use Type 3
  • No Type 3 or 4 available → Use Type 2
  • Development/Testing only → Use Type 1

Complete JDBC Example — Oracle

import java.sql.*;

class JdbcDemo {
    public static void main(String[] args) {
        try {
            // Step 1: Load driver
            Class.forName("oracle.jdbc.driver.OracleDriver");

            // Step 2: Establish connection
            Connection con = DriverManager.getConnection(
                "jdbc:oracle:thin:@localhost:1521:xe",
                "system", "oracle"
            );

            // Step 3: Create statement
            Statement stmt = con.createStatement();

            // Step 4: Execute query
            ResultSet rs = stmt.executeQuery("SELECT * FROM student");

            // Step 5: Process results
            while (rs.next()) {
                System.out.println(
                    rs.getString(1) + " " + rs.getString(2)
                );
            }

            // Step 6: Close resources
            con.close();
        } catch (Exception e) {
            System.out.println(e);
        }
    }
}Java — JDBC Oracle Connection

Working with Statements

1. Statement Interface

Definition The Statement interface provides methods to execute SQL queries with the database. It is created from a Connection object. It is a factory of ResultSet.

Key Methods

  • executeQuery(String sql)Used for SELECT queries. Returns a ResultSet object.
  • executeUpdate(String sql)Used for INSERT, UPDATE, DELETE, CREATE, DROP. Returns int (rows affected).
  • execute(String sql)Used for queries that may return multiple results or stored procedures.
  • executeBatch()Executes a batch of commands. Returns int[].
// INSERT using Statement
Statement stmt = con.createStatement();
stmt.executeUpdate("INSERT INTO emp VALUES(33,'Irfan',50000)");

// UPDATE using Statement
stmt.executeUpdate("UPDATE emp SET name='Vimal' WHERE id=33");

// DELETE using Statement
int rows = stmt.executeUpdate("DELETE FROM emp WHERE id=33");
System.out.println(rows + " records affected");Java — Statement

2. PreparedStatement Interface

Definition PreparedStatement is a sub-interface of Statement. It is used to execute parameterized queries using ? placeholders. The query is compiled only once, improving performance.
💡 Why PreparedStatement?
  • Performance: Query is precompiled; executed multiple times efficiently
  • Security: Prevents SQL injection attacks
  • Readability: Cleaner code with parameter binding
// INSERT with PreparedStatement
PreparedStatement pstmt = con.prepareStatement(
    "INSERT INTO emp VALUES(?,?)"
);
pstmt.setInt(1, 101);           // ? at position 1 = id
pstmt.setString(2, "Raj");    // ? at position 2 = name
int i = pstmt.executeUpdate();
System.out.println(i + " records inserted");

// UPDATE with PreparedStatement
PreparedStatement pstmt2 = con.prepareStatement(
    "UPDATE emp SET name=? WHERE id=?"
);
pstmt2.setString(1, "Sonoo");
pstmt2.setInt(2, 101);
pstmt2.executeUpdate();

// SELECT with PreparedStatement
PreparedStatement pstmt3 = con.prepareStatement(
    "SELECT * FROM emp"
);
ResultSet rs = pstmt3.executeQuery();
while (rs.next()) {
    System.out.println(rs.getInt(1) + " " + rs.getString(2));
}Java — PreparedStatement

3. CallableStatement Interface

Definition CallableStatement interface is used to call stored procedures and functions in the database. It extends PreparedStatement.

Stored Procedures vs Functions

Stored ProcedureFunction
May or may not return a valueMust return a value
Called using CALL statementCalled using SELECT / expressions
Can have IN, OUT, INOUT parametersOnly IN parameters (usually)
Can perform DML operations (INSERT/UPDATE)Generally read-only
 
// Create stored procedure in Oracle:
-- CREATE OR REPLACE PROCEDURE insertR(id IN NUMBER, name IN VARCHAR2)
-- IS BEGIN INSERT INTO user12 VALUES(id,name); END;

// Call stored procedure from Java:
CallableStatement cstmt = con.prepareCall(
    "{call insertR(?,?)}"
);
cstmt.setInt(1, 1011);
cstmt.setString(2, "Amit");
cstmt.execute();
System.out.println("Success — record inserted via stored procedure");Java — CallableStatement

What is the difference between Frame and Panel in AWT?
2 marks
Answer
A Frame is a top-level container with a title bar and can optionally have menu bars. It is the main window of an AWT application. A Panel is an intermediate container with no title bar or menu bar — it is used to group other components and must be placed inside a Frame or Window.

Explain the Layout Managers in AWT with their use cases.
5 marks
Answer
Layout Managers in Java are interfaces/classes that control how components are arranged inside a container. They are used to make GUIs responsive and portable. There are 4 main layout managers:
  • BorderLayout: Divides the container into 5 regions — NORTH, SOUTH, EAST, WEST, and CENTER. Each region holds one component. It is the default layout for Frame. Example: setLayout(new BorderLayout());
  • FlowLayout: Arranges components in a row, one after another (in a flow). Wraps to the next line when the row is full. It is the default layout for Panel. Supports LEFT, RIGHT, and CENTER alignment.
  • GridLayout: Arranges components in a rectangular grid. All cells are equal in size. Useful for calculators or equal-size button grids. Example: setLayout(new GridLayout(3,3));
  • CardLayout: Shows only one component at a time, treating each component like a card. Useful for creating wizard-style multi-page interfaces.
When layout is set to null, components must be manually positioned using setBounds(x, y, width, height).
12
Describe the steps to perform Event Handling in Java AWT with an example.
5 marks
Answer
Event Handling in AWT involves three key steps:
  1. Create the Component: Create and add the UI component (e.g., Button) to the Frame.
  2. Register the Listener: Attach an event listener to the component using addActionListener(this). The class must implement the appropriate listener interface (e.g., ActionListener).
  3. Implement the Handler: Override the interface method (e.g., actionPerformed(ActionEvent e)) to define what happens when the event fires.
Example: When a Button is clicked, a TextField displays "Welcome". The class implements ActionListener, the button registers addActionListener(this), and the actionPerformed() method calls tf.setText("Welcome").

Common event-listener pairs: ActionEvent → ActionListener; MouseEvent → MouseListener; KeyEvent → KeyListener.
13
Explain the Applet Lifecycle with a diagram description and the role of each method.
5 marks
Answer
An Applet goes through 5 lifecycle stages:
  • init(): Called only once when the applet is first loaded into the browser. Used for initialization (setting up variables, loading resources). Provided by java.applet.Applet.
  • start(): Called after init(), and again whenever the browser page is revisited or the window is maximized. Used to start or resume the applet's activity.
  • paint(Graphics g): Called immediately after start() and whenever the applet needs to redraw its output. Used to draw graphics, strings, shapes. Provided by java.awt.Graphics.
  • stop(): Called when the user leaves the page or minimizes the browser. Used to suspend background tasks or threads.
  • destroy(): Called only once when the browser is closed or the applet is removed. Used to release resources and clean up.
Life cycle flow: init → start → paint → [stop ↔ start] → destroy. Note: java.applet.Applet provides init, start, stop, destroy. java.awt.Graphics provides paint.
14
Compare the four types of JDBC drivers with their advantages and disadvantages.
5 marks
Answer
  • Type 1 (JDBC-ODBC Bridge): Translates JDBC calls to ODBC. Requires ODBC setup on every client machine. Platform-dependent and slow. Used only for development/testing. Cannot be used for applets as ODBC must be installed on server.
  • Type 2 (Native-API Driver): Converts JDBC calls to native client library calls (OCI for Oracle). Faster than Type 1 but requires binary installation on each client. Not suitable for large networks.
  • Type 3 (JDBC-Net Driver): Three-tier architecture; JDBC client connects to a middleware application server. Most flexible — the middleware communicates with different databases. No client-side binaries needed. Suitable for internet applications.
  • Type 4 (100% Pure Java): Directly converts JDBC calls to the native database protocol. No client installation needed (except JVM). Fastest and most portable. Best choice for production. Example: MySQL Connector/J.
Recommendation: Use Type 4 for single-DB apps, Type 3 for multi-DB apps, Type 2 when others unavailable, Type 1 only for testing.
15
Explain the 8 steps to establish a JDBC connection with a database.
5 marks
Answer
  1. Import Packages: import java.sql.*; — imports all JDBC classes.
  2. Load JDBC Driver: Class.forName("oracle.jdbc.driver.OracleDriver"); — registers the driver with DriverManager.
  3. Open Connection: DriverManager.getConnection(url, user, password); — returns a Connection object.
  4. Create Statement: con.createStatement(); — creates a Statement for executing SQL.
  5. Execute Query: stmt.executeQuery("SELECT * FROM emp"); — returns a ResultSet.
  6. Process ResultSet: Loop using rs.next() to iterate through rows and call rs.getString(), rs.getInt() etc.
  7. Close ResultSet & Statement: Call rs.close() and stmt.close() to free resources.
  8. Close Connection: Call con.close() to end the database session. (Java GC will also close it but best practice is explicit close.)
16
What is PreparedStatement? Compare it with Statement with code examples.
5 marks
Answer
Statement executes static SQL queries. It is compiled every time it is called. Vulnerable to SQL injection. Used for simple, one-time queries.

PreparedStatement executes parameterized SQL queries using ? placeholders. The query is pre-compiled once and can be run multiple times with different values. Prevents SQL injection.

Statement example:
stmt.executeUpdate("INSERT INTO emp VALUES(101, 'Raj')");

PreparedStatement example:
PreparedStatement ps = con.prepareStatement("INSERT INTO emp VALUES(?,?)");
ps.setInt(1, 101); ps.setString(2, "Raj"); ps.executeUpdate();

The main advantages of PreparedStatement are: (1) Better performance for repeated queries, (2) Protection from SQL injection, (3) Cleaner and more readable code with dynamic values.

What is CallableStatement? How is it used to call stored procedures?
5 marks
Answer
CallableStatement is a JDBC interface used to call stored procedures and functions stored in the database. It extends PreparedStatement. It offers better performance than regular SQL because stored procedures are pre-compiled on the database server.

How to use:
1. Create the stored procedure in the database (e.g., Oracle).
2. Get a CallableStatement using con.prepareCall("{call procedureName(?,?)}")
3. Set parameter values using setInt(), setString() etc.
4. Execute with cstmt.execute()

Example: CallableStatement cs = con.prepareCall("{call insertR(?,?)}");
cs.setInt(1, 1011); cs.setString(2, "Amit"); cs.execute();

Stored procedures can have IN, OUT, and INOUT parameters unlike functions which typically only have IN parameters.

Describe the JDBC Architecture with its three main components.
5 marks
Answer
The JDBC Architecture consists of three layers:
  • Java Application: The top layer. It calls JDBC methods (from java.sql package) to send SQL statements and retrieve results. The application is DBMS-independent — same code works with different databases.
  • Driver Manager (java.sql.DriverManager): The middle layer. It manages multiple JDBC drivers installed on the system. Its getConnection() method connects the application to the appropriate JDBC driver using the JDBC URL, username, and password.
  • JDBC Driver: The bottom layer. It is a vendor-specific implementation that translates JDBC calls into database-specific protocol. Types include JDBC-ODBC Bridge (Type 1), Native-API (Type 2), JDBC-Net (Type 3), and Pure Java (Type 4).
Flow: Application → JDBC API → DriverManager → JDBC Driver → Database. The JDBC driver test suite verifies that installed drivers are JDBC-compliant.

Scenario: A developer writes a JDBC program using Statement to insert 1000 records in a loop. The application is slow. How would you optimize it? Explain using PreparedStatement and batch processing.
10 marks
Answer

Problem Identification: Using a regular Statement in a loop to insert records is inefficient because: (1) The SQL query is compiled every single iteration (1000 compilations). (2) Each executeUpdate() call is a separate round-trip to the database. (3) No batching means 1000 individual network connections.

Solution 1 — PreparedStatement: Replace Statement with PreparedStatement. The query is compiled only once, then executed 1000 times with different parameter values.

PreparedStatement ps = con.prepareStatement("INSERT INTO emp VALUES(?,?)");
for(int i=1; i<=1000; i++) {
    ps.setInt(1, i);
    ps.setString(2, "Employee"+i);
    ps.executeUpdate();  // Still 1000 round-trips
}

Solution 2 — PreparedStatement + Batch Processing (Best): Use addBatch() to accumulate statements and executeBatch() to send them all at once, drastically reducing network round-trips.

PreparedStatement ps = con.prepareStatement("INSERT INTO emp VALUES(?,?)");
con.setAutoCommit(false);  // Disable auto-commit for batch
for(int i=1; i<=1000; i++) {
    ps.setInt(1, i);
    ps.setString(2, "Employee"+i);
    ps.addBatch();  // Add to batch
    if(i % 100 == 0) {  // Execute every 100 records
        ps.executeBatch();
        con.commit();
        ps.clearBatch();
    }
}
ps.executeBatch();
con.commit();

Why this is better:

  • Query compiled only ONCE (vs 1000 times)
  • Only 10 network round-trips (vs 1000)
  • All records committed together → atomicity
  • Significantly faster — can be 10-50x improvement

Additional optimization: Use connection pooling (like HikariCP or C3P0) to avoid overhead of creating new connections repeatedly.

Explain the complete JDBC architecture with all 4 driver types, their working mechanism, advantages, disadvantages, and when to use each. Draw and describe the architecture diagram.
10 marks
Answer

JDBC Architecture Overview:

JDBC follows a layered architecture: Java Application → JDBC API → DriverManager → JDBC Driver → Database.

Three Core Components:

  1. Application Layer: Java program that uses JDBC API classes (Connection, Statement, ResultSet) from java.sql.
  2. Driver Manager: Manages all registered JDBC drivers. Selects the right driver using the JDBC URL prefix (e.g., jdbc:oracle: or jdbc:mysql:).
  3. JDBC Driver: Vendor-specific code that converts JDBC calls into database protocol calls.

Type 1 — JDBC-ODBC Bridge: Uses Windows' built-in ODBC infrastructure. ODBC must be configured on each client. Very slow (double translation). Not suitable for applets. Used only in development. Driver class: sun.jdbc.odbc.JdbcOdbcDriver.

Type 2 — Native-API Driver: Converts JDBC calls into native database client library calls (e.g., Oracle's OCI calls). Faster than Type 1. Requires database-specific binary libraries on client machine. Not suitable for internet deployments. Example: Oracle OCI Driver.

Type 3 — JDBC-Net Pure Java Driver: Uses a three-tier model. The JDBC client sends calls over a standard network socket to a middleware application server, which then communicates with the actual database. Client doesn't need database-specific code. Most flexible and scalable. Ideal for applets and internet applications. Middleware can translate for multiple database backends.

Type 4 — Pure Java Driver (Thin Driver): The most efficient type. Directly converts JDBC calls into the native database wire protocol (e.g., Oracle's Net8 or MySQL protocol). Entirely written in Java — 100% portable. No client installation needed except JVM. Can be bundled with applets for automatic download. Best performance for direct DB connections. Example: MySQL Connector/J (com.mysql.jdbc.Driver).

Selection Strategy:

  • Single DBMS (Oracle/MySQL) → Type 4 (best)
  • Multiple DBMS access → Type 3
  • Legacy systems → Type 2
  • Testing only → Type 1

Write a Java program demonstrating all three JDBC Statement types: Statement, PreparedStatement, and CallableStatement. Explain when each is appropriate.
10 marks
Answer

1. Statement — for simple, one-time queries:

Statement stmt = con.createStatement();
// Execute a SELECT
ResultSet rs = stmt.executeQuery("SELECT * FROM emp");
while(rs.next()) System.out.println(rs.getString(1));
// Execute a DDL/DML
stmt.executeUpdate("CREATE TABLE test(id NUMBER, name VARCHAR2(30))");
stmt.executeUpdate("INSERT INTO test VALUES(1, 'John')");

Use when: Simple, one-time queries with no parameters and no security concerns.

2. PreparedStatement — for parameterized repeated queries:

// Pre-compile once
PreparedStatement ps = con.prepareStatement(
    "INSERT INTO emp VALUES(?,?,?)"
);
// Execute many times with different values
ps.setInt(1, 101); ps.setString(2, "Alice"); ps.setDouble(3, 50000);
ps.executeUpdate();
ps.setInt(1, 102); ps.setString(2, "Bob"); ps.setDouble(3, 60000);
ps.executeUpdate();

Use when: Same query runs multiple times with different parameters, or when user input is involved (prevents SQL injection).

3. CallableStatement — for stored procedures:

// Stored procedure: PROCEDURE getEmpName(id IN NUMBER, name OUT VARCHAR2)
CallableStatement cs = con.prepareCall("{call getEmpName(?,?)}");
cs.setInt(1, 101);         // Set IN parameter
cs.registerOutParameter(2, java.sql.Types.VARCHAR); // Register OUT
cs.execute();
String empName = cs.getString(2);  // Retrieve OUT parameter
System.out.println("Employee: " + empName);

Use when: Business logic is stored in the database as stored procedures, for better performance and security.

Hierarchy: Statement ← PreparedStatement ← CallableStatement. CallableStatement is the most specialized; it handles IN, OUT, and INOUT parameters and can execute both stored procedures and functions.

Explain the MVC architecture in context of Swing applications. How does it differ from AWT? Write a Swing-based application demonstrating MVC principles.
10 marks
Answer

MVC (Model-View-Controller) Architecture:

  • Model: The data and business logic layer. Represents the application state. In JDBC context — the database and data retrieval code.
  • View: The presentation layer. In Swing — JFrame, JPanel, JButton, JTable. Displays data from the model.
  • Controller: Handles user input and updates Model/View accordingly. In Swing — ActionListener, event handlers.

AWT vs Swing regarding MVC: AWT does NOT support MVC pattern — its components directly mix data and display. Swing is built on MVC — for example, JTable uses a TableModel (Model) + TableCellRenderer (View) + input handlers (Controller) as separate entities.

Example — Student Grade Application:

// MODEL
class StudentModel {
    private String name;
    private int grade;
    StudentModel(String n, int g) { name=n; grade=g; }
    String getName() { return name; }
    int getGrade() { return grade; }
    String getResult() { return grade>=40 ? "PASS" : "FAIL"; }
}

// VIEW (Swing)
class StudentView extends JFrame {
    JTextField nameField = new JTextField(15);
    JTextField gradeField = new JTextField(5);
    JButton checkBtn = new JButton("Check Result");
    JLabel resultLabel = new JLabel("Result: ");
    // ... add components in constructor
}

// CONTROLLER
class StudentController implements ActionListener {
    StudentModel model;
    StudentView view;
    StudentController(StudentModel m, StudentView v) {
        model=m; view=v;
        view.checkBtn.addActionListener(this);
    }
    public void actionPerformed(ActionEvent e) {
        // Get from view, update model, push back to view
        String name = view.nameField.getText();
        int grade = Integer.parseInt(view.gradeField.getText());
        model = new StudentModel(name, grade);
        view.resultLabel.setText("Result: " + model.getResult());
    }
}

Benefits of MVC in Swing: Separation of concerns; easy to test each layer independently; UI can change without affecting business logic; multiple Views can share same Model.

Compare AWT and Swing in depth. Write a program that recreates the same form using both AWT and Swing side by side, highlighting the differences in code and functionality.

In-Depth Comparison:

1. Component Weight: AWT components are heavyweight — they delegate rendering to the OS's native windowing system, meaning each AWT component has a native OS peer object. Swing components are lightweight — they are entirely rendered by Java's own graphics system (Java2D), giving them consistent appearance across platforms.

2. Platform Dependency: AWT looks different on Windows vs Linux vs Mac because it uses native widgets. Swing looks the same everywhere (unless a custom Look-and-Feel is applied).

3. Component Richness: AWT lacks components like JPasswordField, JTabbedPane, JTree, JTable, JSlider. Swing provides all these and more.

4. MVC Architecture: Swing's JTable uses DefaultTableModel (Model) + TableCellRenderer (View), demonstrating MVC. AWT has no such separation.

Scenario: A company uses Oracle for HR data. Write a Java application that uses CallableStatement to call a stored procedure that calculates and returns the annual bonus of an employee based on their salary and performance rating. Handle IN and OUT parameters properly.
10 marks
Answer

Scenario Setup: The HR database has a stored procedure calc_bonus that takes employee ID (IN) and performance rating (IN), then returns annual bonus amount (OUT) and bonus tier (OUT — Gold/Silver/Bronze).

Step 1: Create the database procedure (Oracle PL/SQL):

CREATE OR REPLACE PROCEDURE calc_bonus(
    emp_id      IN  NUMBER,
    perf_rating IN  NUMBER,     -- 1 to 5 scale
    bonus_amt   OUT NUMBER,
    bonus_tier  OUT VARCHAR2
) IS
    emp_salary NUMBER;
BEGIN
    SELECT salary INTO emp_salary FROM employees WHERE id = emp_id;
    IF perf_rating >= 4 THEN
        bonus_amt := emp_salary * 0.20;
        bonus_tier := 'GOLD';
    ELSIF perf_rating = 3 THEN
        bonus_amt := emp_salary * 0.10;
        bonus_tier := 'SILVER';
    ELSE
        bonus_amt := emp_salary * 0.05;
        bonus_tier := 'BRONZE';
    END IF;
END;
/

Step 2: Java application to call this procedure:

import java.sql.*;
public class BonusCalculator {
    public static void main(String[] args) {
        Connection con = null;
        CallableStatement cs = null;
        try {
            // Load driver and connect
            Class.forName("oracle.jdbc.driver.OracleDriver");
            con = DriverManager.getConnection(
                "jdbc:oracle:thin:@localhost:1521:xe",
                "hr", "hr"
            );
            // Prepare callable statement with IN and OUT parameters
            cs = con.prepareCall("{call calc_bonus(?,?,?,?)}");

            // Set IN parameters
            cs.setInt(1, 1001);      // emp_id = 1001
            cs.setInt(2, 4);         // perf_rating = 4 (excellent)

            // Register OUT parameters with their SQL types
            cs.registerOutParameter(3, Types.NUMBER);   // bonus_amt
            cs.registerOutParameter(4, Types.VARCHAR);  // bonus_tier

            // Execute the stored procedure
            cs.execute();

            // Retrieve OUT parameter values
            double bonusAmt = cs.getDouble(3);
            String bonusTier = cs.getString(4);

            System.out.println("Employee ID : 1001");
            System.out.printf("Annual Bonus: Rs.%.2f%n", bonusAmt);
            System.out.println("Bonus Tier  : " + bonusTier);

        } catch (ClassNotFoundException e) {
            System.out.println("Driver not found: " + e.getMessage());
        } catch (SQLException e) {
            System.out.println("SQL Error: " + e.getMessage());
        } finally {
            // Always close resources
            try {
                if (cs != null) cs.close();
                if (con != null) con.close();
            } catch (SQLException e) {
                e.printStackTrace();
            }
        }
    }
}

Output:

Employee ID : 1001
Annual Bonus: Rs.12000.00
Bonus Tier  : GOLD

Key Concepts Demonstrated:

  • registerOutParameter(index, Types.TYPE) is required before execution to tell JDBC the type of OUT parameters.
  • OUT parameters are retrieved after execute() using appropriate getter methods (getDouble(), getString()).
  • INOUT parameters use both setXxx() and registerOutParameter() on the same index.
  • Using stored procedures improves performance (pre-compiled), security (no SQL injection), and maintainability (DB logic centralized).
  • Always use finally block to close connections — prevents resource leaks.
