What is an Abstract Class?

An abstract class is a class that cannot be instantiated (you cannot create objects of it directly). It is declared using the abstract keyword and is meant to be subclassed.

It can contain:

  • Abstract methods — declared but NOT implemented (no body) → subclass MUST implement
  • Concrete methods — fully implemented methods (with body)
  • Instance variables, constructors, static methods — all allowed

Think of an abstract class as a blueprint template. A blueprint for a "Vehicle" says every vehicle MUST have a start() method — but HOW it starts (petrol key vs electric button) is defined by each specific vehicle (Car, Bike, Truck). You can't drive a "Vehicle" — you drive a specific Car or Bike (the concrete subclass).

Abstract Method

An abstract method has NO body — just a declaration. The subclass must override and implement it.

Java – Abstract Method Syntax
abstract class Shape {
    // Abstract method — NO body, ends with semicolon
    abstract double area();      // subclass MUST implement this
    abstract double perimeter(); // subclass MUST implement this

    // Concrete method — has body, inherited by subclass
    void display() {
        System.out.println("Area = " + area());
        System.out.println("Perimeter = " + perimeter());
    }
}
Complete Abstract Class Example
Java – Shape Example (Full Program)
// Step 1: Define abstract class
abstract class Shape {
    String color;

    // Constructor of abstract class (allowed!)
    Shape(String color) {
        this.color = color;
    }

    // Abstract methods — MUST be implemented by subclass
    abstract double area();
    abstract double perimeter();

    // Concrete method — ready to use, inherited
    void display() {
        System.out.println("Color: " + color);
        System.out.println("Area: " + area());
        System.out.println("Perimeter: " + perimeter());
    }
}

// Step 2: Subclass 1 — implements abstract methods
class Circle extends Shape {
    double radius;

    Circle(double r, String color) {
        super(color); // call abstract class constructor
        this.radius = r;
    }

    double area() {
        return Math.PI * radius * radius; // must implement!
    }
    double perimeter() {
        return 2 * Math.PI * radius;
    }
}

// Step 3: Subclass 2 — implements abstract methods differently
class Rectangle extends Shape {
    double length, width;

    Rectangle(double l, double w, String color) {
        super(color);
        this.length = l; this.width = w;
    }

    double area()      { return length * width; }
    double perimeter() { return 2 * (length + width); }
}

// Step 4: Main class
public class AbstractDemo {
    public static void main(String[] args) {
        // Shape s = new Shape("Red"); // ERROR! Cannot instantiate abstract class

        Shape c = new Circle(5.0, "Red");    // OK — Circle is concrete
        Shape r = new Rectangle(4.0, 6.0, "Blue"); // OK

        System.out.println("--- Circle ---");
        c.display(); // calls Shape's display() → which calls Circle's area()

        System.out.println("--- Rectangle ---");
        r.display();
    }
}
--- Circle --- Color: Red Area: 78.53981633974483 Perimeter: 31.41592653589793 --- Rectangle --- Color: Blue Area: 24.0 Perimeter: 20.0

USE ABSTRACT CLASS WHEN

• Classes are closely related (Dog IS-A Animal)
• You want to share common code (concrete methods)
• You need constructors or non-static fields
• You need access control (private/protected)

USE INTERFACE WHEN

• Unrelated classes need same behaviour
• You need multiple inheritance
• You want to define a contract (CAN-DO relationship)
• Example: Flyable — Bird, Airplane can both fly

Interface Example for Comparison
Java – Interface
// Interface — defines a contract
interface Drawable {
    void draw(); // public abstract by default
}

interface Resizable {
    void resize(double factor);
}

// A class can implement MULTIPLE interfaces
class Circle implements Drawable, Resizable {
    double radius;
    Circle(double r) { this.radius = r; }

    public void draw() {
        System.out.println("Drawing circle with radius " + radius);
    }
    public void resize(double factor) {
        radius *= factor;
        System.out.println("Resized! New radius: " + radius);
    }
}

public class InterfaceDemo {
    public static void main(String[] args) {
        Circle c = new Circle(5.0);
        c.draw();
        c.resize(2.0);
        c.draw();
    }
}

public abstract class Test implements Runnable {
    public void doSomething() { }
    // run() is NOT implemented here
}
✅ YES — This compiles fine! Because Test is abstract, it does NOT need to implement run(). A concrete (non-abstract) subclass of Test must implement run().

class ConcreteTest extends Test {
    public void run() { // now MUST be implemented
        System.out.println("Running!");
    }
}
Exam Questions – Abstract Class
Q: Can you create an object of an abstract class?
NO — abstract class cannot be instantiated. You can only create objects of its concrete subclasses.
Q: Can abstract class have a constructor?
YES — but it is called only when a subclass object is created via super()
Q: Can abstract class have concrete (non-abstract) methods?
YES — it can have both abstract AND concrete methods. That's one key difference from interfaces.
Q: If a class has one abstract method, what must you do?
Declare the entire class as abstract. A non-abstract class cannot have abstract methods.
Q: What happens if subclass doesn't implement all abstract methods?
The subclass must also be declared abstract, or it will get a compile-time error.
Q: Difference between abstract class and interface?
Abstract class: can have concrete methods, constructors, any fields, single inheritance. Interface: only abstract methods (Java 7), no constructors, constants only, multiple implementation allowed.
Q: Can abstract and final be used together?
NO — final class cannot be extended; abstract class MUST be extended. They contradict each other.
Q: Can we have abstract static method?
NO — abstract methods are meant to be overridden, but static methods cannot be overridden.

What is a Package?

A package is a group of related classes and interfaces bundled together. Think of it like a folder on your computer — it organises your files so you can find them easily.

  • Prevents name conflicts — two classes in different packages can have the same name
  • Provides access control — you can hide implementation details
  • Makes code reusable and easy to maintain
  • Java has two types: Built-in (provided by Java) and User-defined (you create them)

A package is like a department in a hospital. Cardiology has heart doctors, Orthopaedics has bone doctors. They all work in the same building (JVM) but are organized into separate departments (packages). You can call a specialist from any department when needed.

What is a Stream?

A stream is an abstraction that either produces or consumes data. Java performs all I/O through streams. All stream classes are in java.io.

A stream is like a water pipe. Data (water) flows in one direction — either INTO your program (InputStream) or OUT of it (OutputStream). Whether the water comes from a tank (file) or river (network), the pipe works the same way.

📦 BYTE STREAMS

Handle raw bytes. Used for binary data — images, audio, any file. Classes end with Stream.

InputStream / OutputStream

Handle Unicode characters. Better for text files. Classes end with Reader/Writer.

ByteArrayOutputStream – In-memory byte buffer

Writes bytes to an in-memory byte array instead of a file. Buffer auto-grows as needed.

Java
import java.io.*;
class ByteArrayOutputStreamDemo {
    public static void main(String[] args) throws IOException {
        ByteArrayOutputStream f = new ByteArrayOutputStream();
        String s = "This should end up in the array";
        byte buf[] = s.getBytes();
        f.write(buf);

        System.out.println("As String: " + f.toString());

        byte b[] = f.toByteArray(); // get as raw byte array
        for (int i=0; i<b.length; i++) System.out.print((char)b[i]);

        OutputStream f2 = new FileOutputStream("test.txt");
        f.writeTo(f2); // write memory buffer to a real file
        f2.close();

        f.reset();    // clear the buffer
        for (int i=0; i<3; i++) f.write('X');
        System.out.println("\nAfter reset: " + f.toString());
    }
}

Both are abstract classes that wrap another Writer/Reader to process/filter characters. You must create a subclass (even anonymous) to use them.

FilterWriter extends Writer · FilterReader extends Reader · Both are abstract — must be subclassed.

        fr.write("Bhavneet");
        fr.flush();
        fr.write(c);
        fr.write('s');
        System.out.print(wr.toString());
        fr.close();

}

Piped I/O – Thread-to-Thread Communication

Pipes allow one thread (producer) to write data and another thread (consumer) to read it — they must run in different threads to avoid deadlock.

Like a walkie-talkie: Thread A speaks (writes), Thread B listens (reads). The pipe is the invisible channel between them.

Java – Piped I/O (Producer-Consumer)
import java.io.*;
public class PipedDemo {
    public static void main(String[] args) throws Exception {
        final PipedReader read = new PipedReader();
        final PipedWriter write = new PipedWriter(read); // connected

        Thread readerThread = new Thread(() -> {
            try {
                int data = read.read();
                while(data != -1) {
                    System.out.print((char)data);
                    data = read.read();
                }
            } catch(Exception e){}
        });

        Thread writerThread = new Thread(() -> {
            try {
                write.write("Hello from writer thread!\n".toCharArray());
                write.close(); // signals -1 to reader
            } catch(Exception e){}
        });

        readerThread.start();
        writerThread.start();
    }
}
Hello from writer thread!
PipedWriter is a subclass of Writer. Always use PipedWriter + PipedReader in DIFFERENT threads — same-thread use causes deadlock!

What is Serialization?

Serialization = converting an object's state into a sequence of bytes (to save to file or send over network).
Deserialization = rebuilding the object from those bytes.

  • Class must implement Serializable (marker interface — no methods!)
  • Serialization is JVM-independent — serialize on Windows, deserialize on Linux
  • static fields are NOT serialized — they belong to the class, not the object

Serialization is like packing a suitcase. You pack your stuff (object state) into a bag (byte stream). Transport the bag (file/network). At destination, unpack (deserialize) to get your stuff back.

Complete Serialization Example
Java
import java.io.*;

class MyClass implements Serializable { // must implement Serializable
    String s;  int i;  double d;
    public MyClass(String s, int i, double d) { this.s=s; this.i=i; this.d=d; }
    public String toString() { return "s="+s+"; i="+i+"; d="+d; }
}

public class SerializationDemo {
    public static void main(String[] args) {
        // ── SERIALIZE (save to file) ──
        try {
            MyClass obj1 = new MyClass("Hello", -7, 2.7e10);
            System.out.println("Saved: " + obj1);
            FileOutputStream fos = new FileOutputStream("serial.dat");
            ObjectOutputStream oos = new ObjectOutputStream(fos);
            oos.writeObject(obj1);  // serialize!
            oos.flush(); oos.close();
        } catch(Exception e) { System.out.println(e); }

        // ── DESERIALIZE (restore from file) ──
        try {
            FileInputStream fis = new FileInputStream("serial.dat");
            ObjectInputStream ois = new ObjectInputStream(fis);
            MyClass obj2 = (MyClass) ois.readObject(); // deserialize!
            ois.close();
            System.out.println("Restored: " + obj2);
        } catch(Exception e) { System.out.println(e); }
    }
}
Saved: s=Hello; i=-7; d=2.7E10 Restored: s=Hello; i=-7; d=2.7E10
The transient Keyword

Mark a field transient to exclude it from serialization. After deserialization, transient fields get default values (null, 0, false).

Java
class User implements Serializable {
    String username = "alice";
    transient String password = "secret123"; // NOT serialized!
    int age = 25;
}
// After serialize → deserialize:
// username → "alice"  (saved ✓)
// password → null     (transient — skipped ✗)
// age      → 25       (saved ✓)

What is an Exception?

An exception is an abnormal condition (unwanted event) that disrupts the normal flow of the program at runtime. Exception handling lets you deal with these errors gracefully — so your program doesn't just crash.

Imagine driving a car (your program). An exception is like hitting a pothole (unexpected error). Without exception handling, your car crashes. With exception handling, you have a spare tyre — you handle the problem and continue the journey.

Exception vs Error:

Examples: NullPointerException, IOExceptionExamples: OutOfMemoryError, StackOverflowError
Program can continue after handlingProgram usually must terminate

Creating Your Own Exception Class

Create a custom exception by extending Exception (checked) or extending RuntimeException (unchecked).

Java – Custom Exception
// Step 1: Define the custom exception class
class InsufficientFundsException extends Exception {
    double amount;  // extra field — shortage amount

    InsufficientFundsException(double amount) {
        super("Insufficient funds! Short by: ₹" + amount);
        this.amount = amount;
    }
}

// Step 2: Use the custom exception
class BankAccount {
    double balance = 1000.0;

    void withdraw(double amount) throws InsufficientFundsException {
        if (amount > balance) {
            throw new InsufficientFundsException(amount - balance);
        }
        balance -= amount;
        System.out.println("Withdrawn ₹" + amount + ". Balance: ₹" + balance);
    }
}

public class UserExceptionDemo {
    public static void main(String[] args) {
        BankAccount acc = new BankAccount();
        try {
            acc.withdraw(500);   // OK
            acc.withdraw(800);   // throws InsufficientFundsException!
        } catch (InsufficientFundsException e) {
            System.out.println("Caught: " + e.getMessage());
            System.out.println("Short by: ₹" + e.amount);
        }
    }
}

Handling Multiple Exceptions

Multiple catch Blocks

You can have multiple catch blocks for one try block — each handling a different exception type. Java matches the first compatible catch block.

Java – Multiple catch blocks
public class MultipleCatch {
    public static void main(String[] args) {
        try {
            int[] arr = new int[5];
            arr[10] = 30;             // ArrayIndexOutOfBoundsException
            int result = 10 / 0;      // ArithmeticException
            String s = null;
            s.length();              // NullPointerException
        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.println("Array error: " + e.getMessage());
        } catch (ArithmeticException e) {
            System.out.println("Math error: " + e.getMessage());
        } catch (NullPointerException e) {
            System.out.println("Null pointer: " + e.getMessage());
        } catch (Exception e) { // catch-all — MUST be last!
            System.out.println("Some error: " + e.getMessage());
        }
    }
}
Array error: Index 10 out of bounds for length 5
Order matters! Always put specific exception types FIRST and broader types (like Exception) LAST. If you put Exception first, it will catch everything and the specific catch blocks will never execute — compiler error!
Multi-catch (Java 7+ feature)

Catch multiple exception types in a single catch block using the pipe | operator.

Java – Multi-catch
try {

    // handles all three exception types the same way
    System.out.println("Error occurred: " + e.getMessage());

3.1
Introduction to Multithreading
Process vs Thread · Multitasking vs Multithreading · Advantages & Disadvantages
What is Multithreading?

Multithreading enables two or more parts of the same process to run concurrently. Each part is a thread — a lightweight sub-process that shares the same memory space as the parent process.

Your browser is one process. Inside it — one thread downloads a file, another plays YouTube, another loads the webpage. They all share browser memory but run concurrently. That's multithreading.

MULTITASKING

Multiple processes run simultaneously. Each has its OWN memory. Example: Running Word + Chrome + Music player at the same time. Heavy — expensive context switching.

MULTITHREADING ✅

Multiple threads within one process run simultaneously. They share memory. Lighter and faster. Example: Chrome downloading + streaming simultaneously.

AdvantagesDisadvantages
✅ Improved CPU utilization❌ Difficult to write and debug
✅ Better performance❌ Race conditions possible
✅ Simultaneous access to multiple apps❌ Difficult to manage concurrency
✅ Reduced number of required servers❌ Testing is non-deterministic

3.5
Synchronization
Race condition · Monitor/lock · Synchronized method · Synchronized block · Static synchronization
Why Synchronization?

Bank account problem: Two threads access the same account. Balance = ₹5000. Both read ₹5000. Both subtract ₹3000. Both write ₹2000. Final balance = ₹2000, but it should be ₹-1000! This is a Race Condition — data corruption from concurrent access.

Synchronization ensures only one thread accesses shared data at a time using a lock (monitor). Every Java object has one built-in lock.

1. Synchronized Method
Java
class Table {
    synchronized void printTable(int n) { // lock on 'this' object
        for(int i=1; i<=5; i++) {
            System.out.println(n * i);
            try{ Thread.sleep(400); } catch(Exception e){}
        }
    } // lock released when method exits
}
class T1 extends Thread { Table t; T1(Table t){this.t=t;} public void run(){t.printTable(5);} }
class T2 extends Thread { Table t; T2(Table t){this.t=t;} public void run(){t.printTable(100);} }
public class SyncDemo {
    public static void main(String[] a) {
        Table obj = new Table();
        new T1(obj).start(); new T2(obj).start();
    }
}
5 10 15 20 25 100 200 300 400 500 (clean — no mixing!)
2. Synchronized Block

More efficient — lock only the critical section, not the entire method.

Java
void printTable(int n) {
    // non-critical code here (not locked)
    synchronized(this) { // only THIS block is locked
        for(int i=1; i<=5; i++) {
            System.out.println(n * i);
            try{ Thread.sleep(400); } catch(Exception e){}
        }
    }
    // more non-critical code (not locked)
}
3. Static Synchronization

Lock is on the Class object (e.g., Display.class) — not on any instance. Ensures mutual exclusion even across different instances of the same class.

Java
class Display {
    public static synchronized void displayMessage(String msg) {
        // Lock is on Display.class — shared by ALL instances
        for(int i=0; i<5; i++) {
            System.out.println(msg);
            try{ Thread.sleep(500); }catch(InterruptedException e){}
        }
    }
}

🔒 Synchronized Method

Locks entire method. Lock on this (instance). Simpler but less efficient.

Lock: this (instance)

🎯 Synchronized Block

Locks only a block. Lock on any specified object. More efficient.

Lock: specified object

🏛️ Static Synchronized

Locks at class level. All instances share ONE lock. Protects static data.

What is Inter-Thread Communication?

Threads can communicate with each other using wait(), notify(), and notifyAll() — methods defined in the Object class. They enable a cooperative approach where threads take turns.

Chef and Waiter analogy: Chef (Producer) cooks food and puts it on the counter. Waiter (Consumer) picks it up. If the counter is empty, Waiter waits. Chef notifies the Waiter when food is ready. If counter is full, Chef waits. Waiter notifies Chef when space is free.

Producer-Consumer Complete Example
Java – Inter-Thread Communication
class SharedResource {
    int data;
    boolean produced = false;

    // Producer: produce data and notify consumer
    synchronized void produce(int val) {
        while(produced) { // if data already produced, wait
            try { wait(); } catch(InterruptedException e) {}
        }
        data = val;
        produced = true;
        System.out.println("Produced: " + val);
        notify(); // wake up consumer
    }

    // Consumer: consume data and notify producer
    synchronized void consume() {
        while(!produced) { // if no data, wait
            try { wait(); } catch(InterruptedException e) {}
        }
        System.out.println("Consumed: " + data);
        produced = false;
        notify(); // wake up producer
    }
}

public class ProducerConsumerDemo {
    public static void main(String[] args) {
        SharedResource res = new SharedResource();

        Thread producer = new Thread(() -> {
            for(int i=1; i<=3; i++) res.produce(i);
        });
        Thread consumer = new Thread(() -> {
            for(int i=1; i<=3; i++) res.consume();
        });
        producer.start(); consumer.start();
    }
}
Produced: 1 Consumed: 1 Produced: 2 Consumed: 2 Produced: 3 Consumed: 3

Suspending, Resuming, and Stopping Threads
Deprecated methods · Safe alternatives · Daemon threads
Deprecated Thread Control Methods

Java originally provided suspend(), resume(), and stop() for controlling threads. These are now deprecated because they are unsafe:

MethodProblemSafe Alternative
suspend()Can cause deadlock — thread holds lock and stays suspendedUse a volatile boolean flag
resume()Unsafe with deprecated suspend()Use notify()
stop()Abruptly kills thread, can corrupt shared dataUse a flag to request graceful stop
Safe Way to Suspend & Stop Threads (Using Flag)
Java – Safe Thread Control
class SafeThread extends Thread {
    private volatile boolean suspended = false; // volatile = visible to all threads
    private volatile boolean stopped   = false;

    public void run() {
        int i = 0;
        while(!stopped) {
            if(!suspended) {
                System.out.println("Running: " + i++);
                try { Thread.sleep(300); } catch(InterruptedException e){}
            }
        }
        System.out.println("Thread stopped gracefully.");
    }

    public void suspendThread()  { suspended = true;  System.out.println("Suspended"); }
    public void resumeThread()   { suspended = false; System.out.println("Resumed"); }
    public void stopThread()    { stopped   = true;  System.out.println("Stopping"); }
}

public class SafeThreadDemo {
    public static void main(String[] args) throws Exception {
        SafeThread t = new SafeThread();
        t.start();
        Thread.sleep(1000); t.suspendThread();
        Thread.sleep(1000); t.resumeThread();
        Thread.sleep(1000); t.stopThread();
    }
}
Running: 0 Running: 1 Running: 2 Suspended Resumed Running: 3 Running: 4 Running: 5 Stopping Thread stopped gracefully.
volatile keyword: Ensures the variable is read from main memory (not thread cache). Without volatile, one thread's change might not be visible to another thread.
Daemon Threads

A daemon thread is a background service thread that runs as long as there are non-daemon (user) threads running. When all user threads finish, the JVM terminates — killing all daemon threads too.

  • Examples of daemon threads: Garbage Collector, JIT compiler
  • Use setDaemon(true) BEFORE calling start()
  • Use isDaemon() to check if a thread is daemon
Java – Daemon Thread
class DaemonThread extends Thread {
    public void run() {
        while(true) {
            System.out.println("Daemon running...");
            try{ Thread.sleep(200); } catch(Exception e){}
        }
    }
}
public class DaemonDemo {
    public static void main(String[] args) throws Exception {
        DaemonThread dt = new DaemonThread();
        dt.setDaemon(true); // mark as daemon BEFORE start()
        dt.start();
        Thread.sleep(500);  // main thread runs for 500ms
        System.out.println("Main thread ending. JVM will terminate daemon.");
        // When main ends, JVM terminates → daemon thread dies automatically
    }
}
Exam Questions – Multithreading
Q: What are the 5 states of a thread?
NEW, RUNNABLE, RUNNING, WAITING/TIMED_WAITING, TERMINATED
Q: Two ways to create a thread in Java?
1) Extend Thread class and override run(). 2) Implement Runnable interface and override run().
Q: Difference between start() and run()?
start() creates a new thread and calls run() in it. Calling run() directly just runs it on the current thread — no new thread created.
Q: Thread priority range in Java?
1 (MIN_PRIORITY) to 10 (MAX_PRIORITY). Default is 5 (NORM_PRIORITY).
Q: What is synchronization?
A mechanism to control access to shared resources so only one thread accesses them at a time, preventing race conditions.
Q: Methods for inter-thread communication?
wait() — makes thread wait. notify() — wakes one waiting thread. notifyAll() — wakes all waiting threads. All defined in Object class.
Q: Why are suspend()/resume()/stop() deprecated?
suspend() can cause deadlock (holds lock while paused). stop() can corrupt shared data by abruptly killing thread.
Q: What is a daemon thread?
A background service thread (like GC). JVM terminates when all non-daemon threads finish, killing daemon threads too.
Q: Can synchronized variable exist in Java?
NO — only methods and blocks can be synchronized, not variables.
Q: Difference between synchronized method and static synchronized?
Instance synchronized: lock on object instance (this). Static synchronized: lock on Class object (ClassName.class) — shared across all instances.

🧵Ch3: Thread CreationCALL start(), OVERRIDE run(). Runnable preferred over extending Thread. start() creates new thread; run() directly does NOT.
🔑Ch3: Synchronizationsynchronized keyword. Method = locks whole method. Block = locks part. Static = locks on Class.class. No synchronized variable!
📡Ch3: Inter-Threadwait() releases lock and waits. notify() wakes one thread. notifyAll() wakes all. All must be in synchronized context!
👻Ch3: Daemon ThreadssetDaemon(true) before start(). JVM kills daemons when user threads finish. GC is a daemon thread. volatile for flag-based suspend/stop.
