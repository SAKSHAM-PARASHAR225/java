📐 Divide & Conquer — How It Works

📖 Divide & Conquer — Definition

A paradigm where a problem is broken into smaller subproblems of the same type, solved recursively, and their results combined. Captured by the recurrence T(n) = aT(n/b) + f(n) solved by the Master Theorem.

Master Theorem Cases

CaseConditionResult
Case 1f(n) = O(n^(log_b a − ε))T(n) = Θ(n^log_b a)
Case 2f(n) = Θ(n^log_b a)T(n) = Θ(n^log_b a · log n)
Case 3f(n) = Ω(n^(log_b a + ε))T(n) = Θ(f(n))

🔍 Binary Search

🇮🇳 Hinglish

Dictionary mein word dhundho — seedha beech page pe jaao. Agar word chhota hai toh left, bada hai toh right. Har baar aadha hissa cut! Isliye O(log n) time lagta hai 📖

📐 Binary Search — Array State Diagram
📋 Step-by-Step Algorithm (English)
  • Set low = 0 and high = n − 1
  • While low ≤ high, compute mid = (low + high) / 2
  • If arr[mid] == key → return mid (found!)
  • If arr[mid] < key → discard left half: set low = mid + 1
  • If arr[mid] > key → discard right half: set high = mid − 1
  • If loop ends and not found → return −1
💻 Pseudocode
BINARY_SEARCH(arr, n, key):
  low ← 0
  high ← n - 1
  WHILE low ≤ high DO
    mid ← (low + high) / 2
    IF arr[mid] == key
      RETURN mid
    ELSE IF arr[mid] < key
      low ← mid + 1
    ELSE
      high ← mid - 1
  RETURN -1

📊 Max & Min — Divide & Conquer

🇮🇳 Hinglish

Array ko do halves mein baanto. Left ka max/min nikalo, right ka nikalo, phir compare karo. Total comparisons: 3n/2 − 2 — straight approach se kam! 🏆

📐 Max/Min D&C — Recursion Tree
📋 Algorithm Steps
  • If only one element → max = min = that element. Return.
  • If two elements → compare once, return (larger, smaller)
  • Compute mid = (low + high) / 2
  • Recursively find (lMax, lMin) for left half
  • Recursively find (rMax, rMin) for right half
  • Return (max(lMax,rMax), min(lMin,rMin))
💻 Pseudocode
MAX_MIN(arr, low, high):
  IF low == high THEN
    RETURN (arr[low], arr[low])
  IF high == low + 1 THEN
    RETURN (MAX, MIN) of pair
  mid ← (low + high) / 2
  (lMax,lMin) ← MAX_MIN(arr,low,mid)
  (rMax,rMin) ← MAX_MIN(arr,mid+1,high)
  RETURN (max(lMax,rMax),
          min(lMin,rMin))

🔀 Merge Sort

🇮🇳 Hinglish

Books ko sort karna chahte ho? Sab books do halves mein baanto, har half sort karo, phir dono sorted halves ko merge karo. Jaise do sorted taash ki decks ko ek sorted deck mein milana! 🃏

📐 Merge Sort — Divide & Merge Diagram
📋 Algorithm Steps
  • If left ≥ right → base case, array is size 1, return
  • Find mid = (left + right) / 2
  • Recursively call MergeSort on left half [left..mid]
  • Recursively call MergeSort on right half [mid+1..right]
  • Merge the two sorted halves: always pick the smaller element first
  • Copy remaining elements of either half if any
💻 Pseudocode
MERGE_SORT(arr, left, right):
  IF left < right THEN
    mid ← (left + right) / 2
    MERGE_SORT(arr, left, mid)
    MERGE_SORT(arr, mid+1, right)
    MERGE(arr, left, mid, right)

MERGE(arr, left, mid, right):
  Copy arr[left..mid] → L[]
  Copy arr[mid+1..right] → R[]
  i←0, j←0, k←left
  WHILE i<|L| AND j<|R| DO
    IF L[i] ≤ R[j]
      arr[k++] ← L[i++]
    ELSE
      arr[k++] ← R[j++]
  Copy remaining of L, R

⚡ Quick Sort

🇮🇳 Hinglish

Ek pivot choose karo. Pivot se chhote sab left, bade sab right. Ab recursively sort karo. Pivot apni sahi jagah pe aa gaya! 🎯 Worst case: already sorted array with last element as pivot — O(n²).

📐 Partition Step — Quick Sort
📋 Algorithm Steps
  • Choose last element as pivot
  • Partition: move all elements ≤ pivot to its left, all > pivot to its right
  • Pivot is now at its correct sorted position
  • Recursively apply QuickSort to left sub-array (before pivot)
  • Recursively apply QuickSort to right sub-array (after pivot)
  • Base case: if sub-array has 0 or 1 element → already sorted
💻 Pseudocode
QUICK_SORT(arr, low, high):
  IF low < high THEN
    pi ← PARTITION(arr,low,high)
    QUICK_SORT(arr, low, pi-1)
    QUICK_SORT(arr, pi+1, high)

PARTITION(arr, low, high):
  pivot ← arr[high]
  i ← low - 1
  FOR j ← low TO high-1 DO
    IF arr[j] ≤ pivot THEN
      i ← i + 1
      SWAP(arr[i], arr[j])
  SWAP(arr[i+1], arr[high])
  RETURN i + 1

🎯 Selection Sort

🇮🇳 Hinglish

Unsorted part mein sabse chhota dhundho, use pehle position pe dalo. Phir baaki mein se chhota dhundho, second position pe. Simple but slow — O(n²). ✅ Min swaps property.

📋 Algorithm Steps
  • Start i from 0 to n−2
  • Find index of minimum element in unsorted portion [i..n-1]
  • Swap minimum with element at position i
  • Now elements at [0..i] are sorted
  • Repeat until i = n−2
💻 Pseudocode
SELECTION_SORT(arr, n):
  FOR i ← 0 TO n-2 DO
    minIdx ← i
    FOR j ← i+1 TO n-1 DO
      IF arr[j] < arr[minIdx]
        minIdx ← j
    SWAP(arr[i], arr[minIdx])

🧮 Strassen's Matrix Multiplication

🇮🇳 Hinglish

Normal 2×2 matrix mein 8 multiplications lagte hain. Strassen ne 7 se kaam chalaya! O(n³) se O(n^2.807) kar diya. GPU computing mein bahut use hota hai! 🔥

📋 Key Idea
  • Split each n×n matrix into four n/2 × n/2 sub-matrices
  • Compute 7 products M1…M7 using those sub-matrices
  • Each product uses additions/subtractions of sub-matrices
  • Compute result C's four quadrants from M1…M7
  • Saves 1 multiplication per level → better asymptotically
💻 7 Products (2×2 case)
A = [[a,b],[c,d]], B = [[e,f],[g,h]]

M1 = (a+d)(e+h)
M2 = (c+d)·e
M3 = a·(f−h)
M4 = d·(g−e)
M5 = (a+b)·h
M6 = (c−a)·(e+f)
M7 = (b−d)·(g+h)

C[0][0] = M1+M4−M5+M7
C[0][1] = M3+M5
C[1][0] = M2+M4
C[1][1] = M1−M2+M3+M6
MethodMultiplicationsTime
Standard8O(n³)
Strassen7O(n^2.807)

Recurrence: T(n) = 7T(n/2) + O(n²) → Master Theorem Case 1 → T(n) = O(n^log₂7 ≈ n^2.807)

🎒 Fractional Knapsack

🇮🇳 Hinglish

Chor ki tarah socho — bag mein sona, chandi, heera. Value/weight ratio se sort karo. Sabse zyada ratio wala pehle le. Agar item pura nahi aata — fraction le lo! Greedy works here 💎

📋 Algorithm Steps
  • Calculate value/weight ratio for each item
  • Sort items in decreasing order of ratio
  • Initialize remaining capacity = W, totalValue = 0
  • For each item: if weight ≤ remaining → take full item
  • Else: take fraction = remaining/weight of item
  • Return totalValue (guaranteed optimal)
💻 Pseudocode
FRAC_KNAPSACK(items, W):
  Sort by (value/weight) DESC
  totalValue ← 0
  remaining ← W
  FOR each item DO
    IF item.weight ≤ remaining
      totalValue += item.value
      remaining -= item.weight
    ELSE
      f ← remaining / item.weight
      totalValue += f × item.value
      BREAK
  RETURN totalValue

🌲 Prim's Algorithm (MST)

🇮🇳 Hinglish

5 ghar hain — sab ko bijli deni hai. Ek ghar se shuru, sabse sasta wire kahan jaata hai? Woh ghar jodo. Dono ghar mein se sabse sasta wire — jodo. Aise karte karte pura village connect! ⚡

📋 Algorithm Steps
  • Start from any vertex (e.g., vertex 0). Mark it as in MST.
  • Find the minimum weight edge connecting MST to a non-MST vertex
  • Add that edge and vertex to MST
  • Repeat until all V vertices are in MST
  • MST has exactly V−1 edges and minimum total weight
💻 Pseudocode
PRIM(G, start):
  key[v] ← ∞ for all v
  key[start] ← 0
  parent[start] ← NULL
  Q ← all vertices (min-PQ by key)
  WHILE Q not empty DO
    u ← EXTRACT_MIN(Q)
    FOR each neighbor v of u DO
      IF v ∈ Q AND w(u,v) < key[v]
        parent[v] ← u
        key[v] ← w(u,v)

🔗 Kruskal's Algorithm (MST)

🇮🇳 Hinglish

Sabhi edges ko price ke hisaab se sort karo. Sabse sasta edge lo — agar cycle nahi banta → include. Cycle bane → skip. Union-Find se cycle detect karo. 🔄

📋 Algorithm Steps
  • Sort all edges by weight in ascending order
  • Initialize Union-Find (each vertex is its own component)
  • For each edge (u, v, w) in sorted order:
  • If FIND(u) ≠ FIND(v) → no cycle → add to MST, UNION(u,v)
  • If FIND(u) == FIND(v) → would form cycle → skip
  • Stop when MST has V−1 edges
💻 Pseudocode
KRUSKAL(G):
  Sort all edges by weight ASC
  MST ← empty set
  Init Union-Find for all V
  FOR each edge (u,v,w) DO
    IF FIND(u) ≠ FIND(v)
      MST ← MST ∪ {(u,v,w)}
      UNION(u, v)
      IF |MST| == V-1 THEN BREAK
  RETURN MST

📡 Huffman Coding

🇮🇳 Hinglish

Jo letter zyada aata hai usse chhota code do, jo kam aata hai usse bada code. Jaise Morse code mein 'E' sirf dot! Min-heap use karo, baar baar do lowest merge karo. 📡

📋 Algorithm Steps
  • Create leaf nodes for each character with its frequency
  • Build a min-heap (priority queue) with all nodes
  • Extract two minimum frequency nodes (left, right)
  • Create new internal node: freq = left.freq + right.freq
  • Insert merged node back into heap
  • Repeat until 1 node remains — that is the Huffman tree root
💻 Pseudocode
HUFFMAN(chars, freq):
  Q ← min-heap of (freq,char)
  WHILE Q.size > 1 DO
    L ← EXTRACT_MIN(Q)
    R ← EXTRACT_MIN(Q)
    node ← new Node(
      freq = L.freq + R.freq,
      left = L, right = R)
    INSERT(Q, node)
  RETURN Q.top  // Huffman root

🇮🇳 Hinglish

Dynamic Programming — Ek bada puzzle solve karna hai. Chhote puzzle ke answers yaad rakh lo — table mein store karo (memoization). Baar baar same calculation nahi karni! "Remember and reuse" — yahi DP ka mantra hai. 🧠

Greedy vs DP: Greedy = "abhi ka best lo". DP = "sab options try karo, best choose karo." Greedy O(n log n), DP O(n²)/O(n³) — lekin DP guaranteed optimal hai jahan greedy fail kare! 💡

📐 DP — Overlapping Subproblems (Fibonacci Example)

🧠 Two Pillars of DP

✅ Optimal Substructure
  • Optimal solution of the problem contains optimal solutions of its subproblems
  • Example: shortest path A→C through B = shortest(A→B) + shortest(B→C)
🔁 Overlapping Subproblems
  • Same subproblems are solved multiple times (unlike D&C where they're distinct)
  • Memoization/Tabulation avoids redundant recomputation

🎒 0/1 Knapsack Problem (DP)

🇮🇳 Hinglish

Item ka fraction nahi le sakte! Ya pura lo (1) ya mat lo (0). Greedy fail hota hai. DP table banao: dp[i][w] = pehle i items mein se max value jab capacity w ho. Har cell mein do options compare karo!

📋 Algorithm Steps
  • Create table dp[0..n][0..W], initialize all 0
  • For each item i (1 to n), for each capacity w (0 to W):
  • Option A (skip item i): dp[i][w] = dp[i−1][w]
  • Option B (take item i, if wt[i] ≤ w): dp[i−1][w−wt[i]] + val[i]
  • dp[i][w] = max(Option A, Option B)
  • Answer is dp[n][W]
💻 Pseudocode
KNAPSACK_01(val, wt, n, W):
  dp[0..n][0..W] ← 0
  FOR i ← 1 TO n DO
    FOR w ← 0 TO W DO
      dp[i][w] ← dp[i-1][w]  // skip
      IF wt[i] ≤ w THEN
        dp[i][w] ← max(dp[i][w],
          dp[i-1][w-wt[i]] + val[i])
  RETURN dp[n][W]

📝 Longest Common Subsequence (LCS)

🇮🇳 Hinglish

"ABCBDAB" aur "BDCABA" ka LCS = "BCBA" (length 4). Subsequence means consecutive nahi chahiye! 2D DP table banao. Characters match → diagonal+1. No match → max(left, up). 🧬

📋 Algorithm Steps
  • Create dp[0..m][0..n], initialize row 0 and col 0 to 0
  • For each i (1..m) and j (1..n):
  • If X[i] == Y[j] → dp[i][j] = dp[i−1][j−1] + 1 (match!)
  • Else → dp[i][j] = max(dp[i−1][j], dp[i][j−1])
  • Answer is dp[m][n]. Trace back for actual subsequence.
💻 Pseudocode
LCS(X, Y, m, n):
  dp[0..m][0..n] ← 0
  FOR i ← 1 TO m DO
    FOR j ← 1 TO n DO
      IF X[i] == Y[j]
        dp[i][j] ← dp[i-1][j-1]+1
      ELSE
        dp[i][j] ← max(dp[i-1][j],
                        dp[i][j-1])
  RETURN dp[m][n]

🪙 Coin Change

🇮🇳 Hinglish

coins={1,5,6,9}, amount=11. Min coins chahiye. Greedy se 9+1+1=3 coins. DP se: 6+5=2 coins ✅! Isliye DP use karo. dp[j] = j amount ke liye min coins. 💰

📋 Algorithm Steps
  • Init dp[0..amount] = ∞, set dp[0] = 0
  • For each amount j (1..amount):
  • For each coin c: if c ≤ j and dp[j−c]+1 < dp[j] → update dp[j]
  • dp[j] = min coins to make amount j
  • Answer = dp[amount] (or −1 if still ∞)
💻 Pseudocode
COIN_CHANGE(coins, amount):
  dp[0..amount] ← ∞
  dp[0] ← 0
  FOR j ← 1 TO amount DO
    FOR each coin c DO
      IF c ≤ j AND dp[j-c]+1 < dp[j]
        dp[j] ← dp[j-c] + 1
  RETURN dp[amount]

🔢 Matrix Chain Multiplication

🇮🇳 Hinglish

3 matrices A(10×30), B(30×5), C(5×60). Order matter karta hai! (AB)C = 4500 operations. A(BC) = 27000. DP se optimal parenthesization nikalo. 🎲

📋 Algorithm Steps
  • Input: dims[0..n] where matrix i has dimensions dims[i−1]×dims[i]
  • dp[i][i] = 0 (single matrix, no cost)
  • For increasing chain lengths l = 2 to n:
  • For each starting index i, compute j = i + l − 1
  • Try every split point k: cost = dp[i][k] + dp[k+1][j] + dims[i−1]×dims[k]×dims[j]
  • dp[i][j] = minimum over all k. Answer = dp[1][n]
💻 Pseudocode
MATRIX_CHAIN(dims, n):
  dp[i][i] ← 0 for all i
  FOR len ← 2 TO n DO
    FOR i ← 1 TO n-len+1 DO
      j ← i + len - 1
      dp[i][j] ← ∞
      FOR k ← i TO j-1 DO
        cost ← dp[i][k]+dp[k+1][j]
          + dims[i-1]*dims[k]*dims[j]
        IF cost < dp[i][j]
          dp[i][j] ← cost
  RETURN dp[1][n]
📝 Example

Matrices: A=10×30, B=30×5, C=5×60. dims=[10,30,5,60]

(AB)C: 10×30×5 + 10×5×60 = 1500+3000 = 4500 ✅
A(BC): 30×5×60 + 10×30×60 = 9000+18000 = 27000 ❌
→ Optimal: (AB)C with cost 4500

👑 N-Queens Problem

🇮🇳 Hinglish

N×N board pe N queens rakhni hain — koi bhi doosri ko attack na kare. Same row, column, diagonal pe koi queen nahi. Backtrack: queen rakho → unsafe? → remove → try next column! ♟️

📋 Algorithm Steps
  • Start from row 0. Try placing queen in each column (0..n−1)
  • Check IS_SAFE: no queen in same column or diagonal
  • If safe → place queen at (row, col), recurse to row+1
  • If all rows filled → solution found! Print it.
  • If no column is safe in current row → backtrack to row−1
  • Remove placed queen, try next column in previous row
💻 Pseudocode
N_QUEENS(board, row, n):
  IF row == n
    PRINT solution; RETURN
  FOR col ← 0 TO n-1 DO
    IF IS_SAFE(board, row, col, n)
      board[row] ← col    // place
      N_QUEENS(board, row+1, n)
      board[row] ← -1    // backtrack

IS_SAFE(board, row, col, n):
  FOR i ← 0 TO row-1 DO
    IF board[i]==col → false
    IF |board[i]-col|==|i-row|
      → false  // diagonal
  RETURN true

➕ Sum of Subsets

🇮🇳 Hinglish

Set {1,2,5,6,8}, target=9. Backtracking se sab subsets try karo jinka sum=9 ho. Include/exclude har element. Pruning: agar sum > target ya baaki elements milake bhi target nahi → branch chhod do! 🌿

📋 Algorithm Steps
  • Start with empty subset, currentSum = 0
  • At each index, make two choices: Include or Exclude element
  • If currentSum == target → found a valid subset! Print it.
  • Prune 1: if currentSum > target → backtrack immediately
  • Prune 2: if remaining elements can't reach target → backtrack
  • Continue until all elements processed
💻 Pseudocode
SUM_SUBSETS(set,idx,curSum,target):
  IF curSum == target
    PRINT subset; RETURN
  IF idx==n OR curSum>target
    RETURN
  // Include set[idx]
  subset.add(set[idx])
  SUM_SUBSETS(set, idx+1,
    curSum+set[idx], target)
  subset.remove(set[idx])
  // Exclude set[idx]
  SUM_SUBSETS(set, idx+1,
    curSum, target)

🔄 Hamiltonian Cycle

🇮🇳 Hinglish

Graph mein ek path dhundho jo har vertex exactly ek baar visit kare aur wapas aaye. NP-complete! Backtrack: vertex add karo → connected? → last vertex start se connect? Solution! Nahi? → backtrack! 🔄

📋 Algorithm Steps
  • Start at vertex 0. path = [0]
  • At each position pos, try adding vertex v (1..n−1)
  • IS_VALID: edge exists from path[pos−1] to v, AND v not already in path
  • If valid → add v to path, recurse to pos+1
  • If pos == n AND edge exists from path[n−1] to path[0] → Hamiltonian cycle found!
  • Else → remove v from path (backtrack)
💻 Pseudocode
HAMILTONIAN(graph, path, pos, n):
  IF pos == n
    IF edge(path[n-1], path[0])
      RETURN true  // cycle!
    RETURN false
  FOR v ← 1 TO n-1 DO
    IF IS_VALID(v, graph, path, pos)
      path[pos] ← v
      IF HAMILTONIAN(graph,path,
         pos+1, n) RETURN true
      path[pos] ← -1  // backtrack
  RETURN false
📝 Key Distinction

Hamiltonian Cycle vs Euler Circuit?

Hamiltonian Cycle: Every VERTEX exactly once → NP-Complete
Euler Circuit: Every EDGE exactly once → O(E+V) polynomial. Condition: all vertices have even degree.

🌿 Branch & Bound — Core Concepts

📋 Key Terms
  • Branch: Create child nodes (make a decision — include or exclude)
  • Bound: Calculate optimistic upper/lower bound for node's subtree
  • Prune: If bound ≤ best so far (max) → discard entire subtree
  • Live Node: Generated but not yet explored (in priority queue)
  • Dead Node: Fully explored or pruned — removed from queue
  • E-Node: Currently expanding node (being branched from)
✅ Bound Function for Knapsack
  • Take all remaining items that fit completely (greedy)
  • Take fraction of next item if needed
  • This is an optimistic (upper bound) on actual achievable value
  • If upper bound ≤ current best → prune this branch

🎒 0/1 Knapsack — Branch & Bound

📋 Algorithm Steps
  • Sort items by value/weight ratio (decreasing)
  • Start at root node: value=0, weight=0
  • For each node, compute upper bound using greedy fractional fill
  • If bound ≤ bestValue → prune (dead node)
  • Branch: create two children — include item i, exclude item i
  • Use max-priority queue (best-first): explore highest-bound node first
💻 COMPUTE_BOUND
COMPUTE_BOUND(node, items, W):
  j ← node.level + 1
  totWt ← node.weight
  bound ← node.value
  WHILE j < n AND
     totWt + items[j].w ≤ W DO
    totWt += items[j].w
    bound += items[j].v
    j++
  IF j < n THEN
    bound += (W-totWt) *
      (items[j].v / items[j].w)
  RETURN bound

🗺️ TSP — Branch & Bound

🇮🇳 Hinglish

Lower bound: Reduced Cost Matrix method. Har row aur column se minimum subtract karo. Remaining minimum = lower bound. Lower bound ≥ best? → prune! 🗺️

📋 Algorithm Steps
  • Reduce cost matrix: subtract row min from each row, col min from each col
  • Sum of all reductions = initial lower bound
  • Use min-priority queue, explore node with lowest bound first
  • For each unvisited city, create child node with updated bound
  • If bound ≥ bestCost → prune that branch
  • When all cities visited → check if total < bestCost, update
💻 Pseudocode
TSP_BB(dist, n):
  Reduce matrix → lb = sum of reductions
  PQ ← min-heap by lower bound
  ENQUEUE(PQ, root(path=[0], bound=lb))
  bestCost ← ∞
  WHILE PQ not empty DO
    u ← DEQUEUE(PQ)
    IF u.bound >= bestCost CONTINUE
    IF len(u.path) == n
      cost ← u.bound +
              dist[u.path[-1]][0]
      bestCost ← min(bestCost, cost)
    ELSE
      FOR v NOT in u.path DO
        v.bound ← new bound
        IF v.bound < bestCost
          ENQUEUE(PQ, v)
  RETURN bestCost

Exam Q&A + Tips
📝 Chapter 1 — D&C & Greedy
Q1. What is the recurrence of Merge Sort? Solve using Master Theorem.
T(n) = 2T(n/2) + O(n). Here a=2, b=2, f(n)=O(n). n^(log₂2) = n^1. f(n) = Θ(n^log_b a) → Case 2: T(n) = Θ(n log n).
Q2. Why does Quick Sort have O(n²) worst case?
When pivot is always smallest/largest (sorted array, last element pivot). T(n) = T(n-1) + O(n) → O(n²). Fix: random pivot or median-of-three.
Q3. Why does Greedy fail for 0/1 Knapsack but work for Fractional?
In Fractional: taking a fraction is allowed, so highest v/w ratio first = always optimal. In 0/1: must take or leave entire item — greedy choice may skip a combination that gives higher total value.
Example: W=10, items=(6kg,₹30),(5kg,₹25),(5kg,₹25). Greedy picks (6kg,₹30)=₹30. Optimal: last two = ₹50.
Q4. Compare Kruskal's vs Prim's for MST.
Kruskal: sort edges, use Union-Find, O(E log E) — better for sparse graphs. Prim: grow from vertex using min-key, O(V²) or O(E log V) — better for dense graphs. Both give optimal MST.
Q5. Max-Min D&C: how many comparisons? Why optimal?
3n/2 − 2 comparisons. Compare elements in pairs (1 comp each), then find max of winners and min of losers. Adversary argument proves this is the minimum possible number of comparisons.
Q6. What is Strassen's significance and time complexity?
Strassen (1969) uses 7 multiplications (not 8) for 2×2 blocks. Recurrence T(n)=7T(n/2)+O(n²). Master Theorem Case 1: T(n) = O(n^log₂7) ≈ O(n^2.807). First algorithm to break O(n³) for matrix multiplication.
📝 Chapter 2 — Dynamic Programming
Q1. Two essential properties for DP?
1. Optimal Substructure: Optimal solution contains optimal solutions of subproblems. 2. Overlapping Subproblems: Same subproblems recur repeatedly (unlike D&C).
Q2. Solve 0/1 Knapsack: items={(2,3),(3,4),(4,5)}, W=5.
dp table: dp[1][2..5]=3, dp[2][3]=4, dp[2][5]=max(3, dp[1][2]+4)=max(3,7)=7, dp[3][4]=5, dp[3][5]=max(7,5)=7. Answer: 7
Q3. Find LCS of "AGGTAB" and "GXTXAYB".
Build 2D DP table. LCS = "GTAB", length = 4.
Q4. Memoization vs Tabulation?
Memoization (Top-Down): Recursive + cache. Only computes needed subproblems. O(n) stack space. More natural to code. Tabulation (Bottom-Up): Iterative, fill table. All subproblems computed. No recursion overhead. Often faster in practice.
Q5. Why is TSP NP-hard? What is DP complexity?
No known polynomial-time exact algorithm. DP (Held-Karp): O(n²·2ⁿ). For n=20: O(400M) vs brute force O(20!) ≈ 2.4×10¹⁸. Still exponential but much better.
📝 Chapter 3 — Backtracking & B&B
Q1. How is backtracking different from brute force?
Brute force tries ALL combinations exhaustively. Backtracking abandons a candidate as soon as it determines it cannot lead to a valid solution (pruning infeasible branches), saving significant computation.
Q2. How many solutions does 4-Queens have? List them.
2 solutions: [1,3,0,2] (col positions per row) and [2,0,3,1].
Q3. Difference between Backtracking and Branch & Bound?
Backtracking: Feasibility check only. DFS. Finds any/all solutions. No bound. B&B: Feasibility + optimality bound. BFS/best-first. Finds OPTIMAL solution. Bound function essential for pruning unpromising subtrees.
Q4. What is the bounding function in B&B Knapsack?
Upper bound = value already accumulated + greedy fractional fill of remaining capacity using items sorted by v/w ratio. This is always ≥ any actual achievable value. If upper bound ≤ bestValue → prune.
Q5. E-node, Live node, Dead node in B&B?
E-node: Currently expanding (generating children). Live node: Generated, in priority queue, not yet explored. Dead node: Either fully expanded or pruned (bound ≤ best).

⚠️ Common Mistakes

  • Using Greedy for 0/1 Knapsack — always use DP!
  • Confusing LCS (subsequence = not necessarily contiguous) with LCS (substring = contiguous)
  • Forgetting Merge Sort needs O(n) extra space — it's NOT in-place!
  • Quick Sort worst case is on sorted arrays with last/first element as pivot
  • MST is unique only when all edge weights are distinct
  • Hamiltonian Cycle ≠ Euler Circuit (vertices vs edges)
  • In B&B: upper bound for maximization, lower bound for minimization
  • DP does NOT always give polynomial time — TSP DP is O(n²·2ⁿ), still exponential!
