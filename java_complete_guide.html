Java Basics & Architecture

JVM, JRE, JDK, Compilation Flow, First Program
Java Execution Pseudocode
Samjho yaar: Java ka code seedha machine pe nahi chalta. Pehle .java → .class (bytecode) banta hai, phir JVM isko machine-specific code mein convert karta hai. Isi wajah se Java "Write Once, Run Anywhere" hai!
Algorithm — Java Program Execution BEGIN STEP 1: Write Java Source Code → Sample.java STEP 2: Compile using javac → Sample.class (Bytecode) STEP 3: Class Loader loads .class file into JVM STEP 4: Bytecode Verifier checks rules/validity STEP 5: JIT Compiler / Interpreter converts bytecode → Machine Code STEP 6: Execute on OS END
🎯
Exam Alert: Correct order: Java Source → Compilation → Class Loader → Byte Code Verification → Interpretation → Execution.
Syntax — First Java Program public class HelloWorld { public static void main(String[] args) { System.out.println("Hello, World!"); } }
Breakdown (Hinglish):
🔹 public class HelloWorld — Class ka naam file ke naam se same hona chahiye
🔹 public static void main(String[] args) — Yahi entry point hai Java program ka
🔹 System.out.println() — Console pe print karta hai + newline add karta hai
🔹 System.out.print() — Newline add nahi karta
💡
JVM vs JRE vs JDK:
JVM (Virtual Machine) → Bytecode run karta hai
JRE (Runtime Env) → JVM + Libraries — sirf run karne ke liye
JDK (Dev Kit) → JRE + Compiler (javac) + Tools — development ke liye

Exception Handling

try-catch-finally, throw, throws, Custom Exception, final/finally/finalize
Exception Handling — Full Pseudocode
Exception = Program runtime pe kuch galat ho gaya.
Jaise file nahi mili, divide by zero, array out of bounds. Normal flow rok deta hai — isliye handle karo!
Pseudocode — try-catch-finally TRY { risky_statement_1 risky_statement_2 ← exception yahan hua risky_statement_3 ← yeh execute nahi hoga } CATCH (ArithmeticException e) { handle divide-by-zero } CATCH (ArrayIndexOutOfBoundsException e) { handle array access } CATCH (Exception e) { // Generic handler — ALWAYS LAST handle any exception } FINALLY { // HAMESHA execute hoga — exception ho ya na ho close resources, cleanup }
Java — try-catch-finally + throw + throws
// --- Basic try-catch ---
try {
    int result = 10 / 0;        // ArithmeticException!
} catch (ArithmeticException e) {
    System.out.println("Can't divide by zero: " + e.getMessage());
} finally {
    System.out.println("This always runs!");
}

// --- throw keyword ---
void checkAge(int age) {
    if(age < 18)
        throw new ArithmeticException("Not eligible!");
}

// --- throws keyword ---
void readFile(String path) throws IOException {
    FileReader fr = new FileReader(path);  // may throw IOException
}

// --- Custom Exception ---
class AgeException extends Exception {
    AgeException(String msg) { super(msg); }
}

FileOutputStream & FileInputStream — Pseudocode
Pseudocode — Write to File (FileOutputStream) ALGORITHM WriteToFile: STEP 1: CREATE FileOutputStream(filePath) → opens file for writing STEP 2: CALL fos.write(byte or byte[]) → data likho STEP 3: CALL fos.flush() → buffer clear karo STEP 4: CALL fos.close() → resource release karo STEP 5: Handle IOException in try-catch Pseudocode — Read from File (FileInputStream) ALGORITHM ReadFromFile: STEP 1: CREATE FileInputStream(filePath) → opens file for reading STEP 2: DECLARE int i = 0 STEP 3: WHILE (i = fis.read()) != -1 { → -1 means end of file PRINT (char)i } STEP 4: CALL fis.close()

Serialization & Filter Streams

Object Serialization/Deserialization, FilterWriter, FilterReader
Object Serialization — Pseudocode
Serialization = Object ko bytes mein convert karo (disk/network pe save ke liye).
Deserialization = Bytes se wapas object banao.
Jaise freeze karna aur thaw karna!
Requirement: Class must implement Serializable interface.
Algorithm — Serialization SERIALIZE (Save Object): 1. Class IMPLEMENTS Serializable 2. CREATE FileOutputStream("filename") 3. CREATE ObjectOutputStream(fileOutputStream) 4. CALL oos.writeObject(myObject) 5. FLUSH and CLOSE Algorithm — Deserialization DESERIALIZE (Load Object): 1. CREATE FileInputStream("filename") 2. CREATE ObjectInputStream(fileInputStream) 3. CAST MyClass obj = (MyClass) ois.readObject() 4. CLOSE streams
Java — Serialization & Deserialization
import java.io.*;

// Class must implement Serializable
class MyClass implements Serializable {
    String s;
    int i;
    double d;
    MyClass(String s, int i, double d) { this.s=s; this.i=i; this.d=d; }
}

// SERIALIZE
try {
    MyClass obj1 = new MyClass("Hello", -7, 2.7e10);
    FileOutputStream fos = new FileOutputStream("serial.dat");
    ObjectOutputStream oos = new ObjectOutputStream(fos);
    oos.writeObject(obj1);
    oos.close();
} catch(Exception e) { e.printStackTrace(); }

// DESERIALIZE
try {
    FileInputStream fis = new FileInputStream("serial.dat");
    ObjectInputStream ois = new ObjectInputStream(fis);
    MyClass obj2 = (MyClass) ois.readObject();  // Casting required!
    System.out.println(obj2.s + " " + obj2.i);
    ois.close();
} catch(Exception e) { e.printStackTrace(); }
🎯
Key Points: Serialization JVM-independent hai — ek platform pe serialize, doosre pe deserialize. transient keyword wale fields serialize nahi hote.

Piped I/O

PipedWriter, PipedReader — Thread-to-Thread Communication
PipedWriter & PipedReader — Pseudocode
Pipes = Ek thread data likhta hai, doosra padhta hai. Producer-Consumer pattern.
Jaise ek banda pipe mein paani daal raha hai, doosra doosre end pe pa raha hai.
Algorithm — PipedWriter + PipedReader STEP 1: CREATE PipedReader read STEP 2: CREATE PipedWriter write = NEW PipedWriter(read) // connect karo THREAD 1 (Reader): WHILE (data = read.read()) != -1 { PRINT (char)data } THREAD 2 (Writer): write.write("Hello from Writer!".toCharArray()) STEP 3: START both threads // Data writer se nikalta hai, reader ko milta hai
Java — PipedReader & PipedWriter
import java.io.*;

public class PipeDemo {
    public static void main(String[] args) throws Exception {
        final PipedReader read  = new PipedReader();
        final PipedWriter write = new PipedWriter(read); // connected!

        Thread readerThread = new Thread(() -> {
            try {
                int data;
                while((data = read.read()) != -1)
                    System.out.print((char)data);
            } catch(Exception ex) {}
        });

        Thread writerThread = new Thread(() -> {
            try {
                write.write("My name is Saksham".toCharArray());
                write.close();
            } catch(Exception ex) {}
        });

        readerThread.start();
        writerThread.start();
    }
}

class MyThread extends Thread {

Thread Synchronization

synchronized method, synchronized block, static synchronization, monitor/lock
Why Synchronization? — The Race Condition Problem
Problem: Multiple threads ek hi resource access karein to data corrupt ho sakta hai.
Jaise do log ek hi bank account se simultaneously paise nikalein — disaster!
Solution: synchronized — ek waqt mein sirf ek thread resource use kare.
Pseudocode — Synchronization (Monitor/Lock) CONCEPT: Every Java object has an internal LOCK (monitor) WITHOUT SYNC: Thread1 reads balance = 1000 Thread2 reads balance = 1000 ← race condition! Thread1 withdraws 500 → writes 500 Thread2 withdraws 500 → writes 500 Final balance = 500 (WRONG! should be 0) WITH SYNC: Thread1 ACQUIRES lock → reads, modifies → RELEASES lock Thread2 WAITS for lock → then runs Final balance = 0 (CORRECT!)
Synchronized Method
Java — Synchronized Method (Full Example)
class Table {
    synchronized void printTable(int n) {  // lock on this object
        for(int i = 1; i <= 5; i++) {
            System.out.println(n * i);
            try { Thread.sleep(400); } catch(Exception e) {}
        }
    }
}

class Thread1 extends Thread {
    Table t;
    Thread1(Table t) { this.t = t; }
    public void run() { t.printTable(5); }
}
class Thread2 extends Thread {
    Table t;
    Thread2(Table t) { this.t = t; }
    public void run() { t.printTable(100); }
}

public class SyncDemo {
    public static void main(String[] args) {
        Table obj = new Table();   // ONE shared object
        Thread1 t1 = new Thread1(obj);
        Thread2 t2 = new Thread2(obj);
        t1.start();
        t2.start();
        // Output: 5,10,15,20,25 THEN 100,200,300,400,500 (orderly)
    }
}
Synchronized Block vs Static Synchronization
Pseudocode — Synchronized Block void doSomething() { // 45 lines of non-critical code here... synchronized(this) { // sirf ye 5 lines lock hain criticalCode_line1 criticalCode_line2 criticalCode_line3 } // more non-critical code... } // Block method se better jab sirf kuch lines critical hain
Java — Static Synchronization
class Display {
    // Lock on CLASS object (not instance) → prevents cross-object race
    public static synchronized void displayMessage(String msg) {
        for(int i = 0; i < 5; i++) {
            System.out.println(msg);
            try { Thread.sleep(500); } catch(Exception e) {}
        }
    }
}

class MyThread extends Thread {
    String message;
    MyThread(String msg) { this.message = msg; }
    public void run() { Display.displayMessage(message); }
}

Library Book System — Encapsulation & OOP
🏛️ Scenario: A library wants to manage books. Each book has a title, author, and availability status. Only valid status changes should be allowed.
💡 Hint: Use private fields + getters/setters. Validate in setter.
Java — Library System (Encapsulation)
class Book {
    private String title;
    private String author;
    private boolean isAvailable;

    public Book(String title, String author) {
        this.title  = title;
        this.author = author;
        this.isAvailable = true;
    }

    public String getTitle()  { return title; }
    public String getAuthor() { return author; }
    public boolean isAvailable() { return isAvailable; }

    public void borrowBook() {
        if(isAvailable) { isAvailable = false; System.out.println(title + " borrowed!"); }
        else            System.out.println(title + " already borrowed!");
    }
    public void returnBook() {
        isAvailable = true;
        System.out.println(title + " returned!");
    }
}

public class Library {
    public static void main(String[] args) {
        Book b = new Book("Java OOP", "Balaguruswamy");
        b.borrowBook();   // Java OOP borrowed!
        b.borrowBook();   // Java OOP already borrowed!
        b.returnBook();   // Java OOP returned!

File Copy Program — FileInputStream + FileOutputStream
📁 Scenario: You need to copy the contents of "source.txt" to "destination.txt" byte by byte using Java IO streams.
💡 Hint: Read using FileInputStream, write using FileOutputStream. Loop till read() returns -1.
Java — File Copy (IO Streams)
import java.io.*;

public class FileCopy {
    public static void main(String[] args) {
        FileInputStream  fis = null;
        FileOutputStream fos = null;

        try {
            fis = new FileInputStream("source.txt");
            fos = new FileOutputStream("destination.txt");

            int byteData;
            while((byteData = fis.read()) != -1) {  // -1 = EOF
                fos.write(byteData);
            }
            System.out.println("File copied successfully!");

        } catch(FileNotFoundException e) {
            System.out.println("File not found: " + e.getMessage());
        } catch(IOException e) {
            System.out.println("IO error: " + e.getMessage());
        } finally {
            try { if(fis != null) fis.close(); } catch(IOException e) {}
            try { if(fos != null) fos.close(); } catch(IOException e) {}
        }
    }
}

class TicketCounter {
    private int tickets = 5;  // shared resource

    synchronized void sellTicket(String agentName) {
        if(tickets > 0) {
            System.out.println(agentName + " selling ticket #" + tickets);
            try { Thread.sleep(100); } catch(Exception e) {}
            tickets--;
            System.out.println("Remaining: " + tickets);
        } else {

        }
    }
}

class Agent extends Thread {

    public void run() {
        for(int i = 0; i < 3; i++)
            counter.sellTicket(getName());
    }
}

Producer-Consumer — PipedWriter + PipedReader
🏭 Scenario: One thread (producer) generates messages, another thread (consumer) reads and prints them using Java Piped streams.
Java — Producer-Consumer (PipedWriter/Reader)
import java.io.*;

public class ProducerConsumer {
    public static void main(String[] args) throws Exception {
        final PipedReader reader = new PipedReader();
        final PipedWriter writer = new PipedWriter(reader); // connected

        // Consumer Thread — reads from pipe
        Thread consumer = new Thread(() -> {
            try {
                int ch;
                System.out.print("Consumer received: ");
                while((ch = reader.read()) != -1)
                    System.out.print((char)ch);
                System.out.println();
            } catch(IOException e) {}
        });

        // Producer Thread — writes to pipe
        Thread producer = new Thread(() -> {
            try {
                String[] messages = {"MSG1: Hello", "MSG2: World"};
                for(String msg : messages)
                    writer.write((msg + "\n").toCharArray());
                writer.close();
            } catch(IOException e) {}
        });

        consumer.start();
        producer.start();
    }
}

Shape Area Calculator — Polymorphism + Inheritance
🔷 Scenario: Design a system that calculates area for Circle, Rectangle, and Triangle using method overriding. Process them through a common reference.
Java — Polymorphism (Shape Calculator)
abstract class Shape {
    abstract double area();
    void display() {
        System.out.printf("%s area = %.2f%n", getClass().getSimpleName(), area());
    }
}

class Circle extends Shape {
    double r;
    Circle(double r) { this.r = r; }
    double area() { return Math.PI * r * r; }
}
class Rectangle extends Shape {
    double l, w;
    Rectangle(double l, double w) { this.l=l; this.w=w; }
    double area() { return l * w; }
}
class Triangle extends Shape {
    double b, h;
    Triangle(double b, double h) { this.b=b; this.h=h; }
    double area() { return 0.5 * b * h; }
}

public class ShapeMain {
    public static void main(String[] args) {
        Shape[] shapes = {
            new Circle(5),
            new Rectangle(4, 6),
            new Triangle(3, 8)
        };
        for(Shape s : shapes) s.display();  // Runtime Polymorphism!
    }
}

// Rectangle area = 24.00
// Triangle area = 12.00

Viva & Exam ke liye important points
🎯
Must Remember — Buzzwords:
🔹 Encapsulation = private + getters/setters
🔹 Abstraction = abstract class / interface — implementation hide karo
🔹 Inheritance = extends keyword, super() for parent constructor
🔹 Polymorphism = same method, different behaviour (override/overload)
🔹 Serialization = implements Serializable → ObjectOutputStream.writeObject()
🔹 Thread creation = extends Thread OR implements Runnable → start() → run()
🔹 Synchronization = synchronized keyword → lock on object/class
🔹 Checked Exception = compile time → handle mandatory (IOException)
🔹 Unchecked Exception = runtime → optional (NullPointerException)
🔹 finally block = hamesha runs (exception ho ya na ho)
🔹 Byte Stream = InputStream/OutputStream → raw bytes
🔹 Char Stream = Reader/Writer → Unicode text
💡
Common Mistakes (Galti mat karna):
❌ Abstract class ka object ban nahi sakta
❌ Static method mein this use nahi kar sakte
❌ throw = manually throw, throws = declaration in signature
❌ Multiple inheritance from classes nahi hoti (only through interfaces)
